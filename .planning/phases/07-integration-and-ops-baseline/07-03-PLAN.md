<behavior>
 - The runner continues to use `RetrievalService.retrieve()` for every unchanged gold query and all five channel envelopes.
 - A record includes per-channel latency percentile summaries, total elapsed p50/p95, quality/rank metrics, underfill, a required `explain_evidence` object, and all comparator pins.
 - `explain_evidence` is immutable, schema-versioned (`retrieval-hnsw-explain-v1`), and contains a `captures` array with one scoped `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` result for each relevant vector channel execution (`source_vector`/`search_chunks` and `wiki_vector`/`search_wiki_embeddings`) using a fixed unchanged golden query and the same benchmark workspace, query vector, requested k, order mode, and graph setting as the measured full-path arm. Each capture stores `channel`, `rpc_function`, `relation`, `query_id`, `requested_k`, `order_mode`, `graph_enabled`, and the raw JSON `plan`; the enclosing object stores `hnsw_observed`, `observed_index_names`, and `decision` (`representative_hnsw_observed` or `inconclusive_escalate_scale`).
 - The runner derives `hnsw_observed` only from the captured plans (never an assumption from corpus size). If either relevant plan lacks a confirmed HNSW index scan, it records `inconclusive_escalate_scale`, with empty/partial `observed_index_names` as applicable; it must not describe the arm as HNSW-selected.
 - Record validation rejects output overwrite, bad dimensions/cardinality, absent or malformed EXPLAIN evidence, unscoped/mismatched EXPLAIN pins, a false HNSW decision, mismatched git/policy/data pins, and invalid strict/relaxed pairs.
</behavior>
