    **섹션 1 — 경로 파서 헬퍼.** `public.storage_path_workspace(p_name text) returns uuid`,
    `language sql`, `immutable`, `set search_path = public`. `security definer`는 붙이지 않는다
    (테이블을 건드리지 않는 순수 파서다). 본문은 정규식으로 `p_name`이 정확히
    `<UUID>/<UUID>/<파일명>` 3세그먼트인지 검사한다 — 앞 두 세그먼트는 8-4-4-4-12 형태의 16진 UUID,
    세 번째 세그먼트는 비어 있지 않고 `/`를 포함하지 않는다. 일치하면 첫 세그먼트를 `uuid`로 캐스팅해
    반환하고, 불일치하면 `null`을 반환한다.
    `⚠️` 블록으로 반사실을 적는다 — 첫 세그먼트를 곧바로 `(storage.foldername(name))[1]::uuid`로
    캐스팅하면 UUID가 아닐 때 22P02를 던져 "거부"가 아니라 "에러"가 되고, 사용자는 403 대신 500을 본다.
    이유의 상세는 여기 다시 쓰지 말고 `01-CONTEXT.md > D-05`를 가리킨다.
    `comment on function`으로 계약과 호출 위치(정책 전용)를 적고,
    `grant execute on function public.storage_path_workspace(text) to authenticated;`로 마감한다.

    **섹션 2 — 버킷.** `insert into storage.buckets (id, name, public, file_size_limit)
    values ('sources', 'sources', false, 52428800) on conflict (id) do nothing;` (D-08).
    52428800바이트 = 50 MiB로 `supabase/config.toml`의 `file_size_limit = "50MiB"`와 일치시킨다.
    `allowed_mime_types`는 설정하지 않는다 — 버킷 레벨 allowlist는 타입을 하나 늘릴 때마다 새
    마이그레이션을 요구해 Phase 3 수집 확장을 막는다. MIME 검증은 Phase 3 애플리케이션 계층 몫이다.

    **섹션 3 — 정책 3종.** 재적용 안전을 위해 각 정책 생성 앞에
    `drop policy if exists <이름> on storage.objects;`를 둔다. 이름과 등급은 `0004`의 `raw_sources`
    3종과 대칭시킨다 (D-06):
    `sources_objects_select_member` — SELECT, `to authenticated`,
    `using (bucket_id = 'sources' and public.is_workspace_member(public.storage_path_workspace(name)))`.
    `sources_objects_insert_editor` — INSERT, `to authenticated`,
    `with check (bucket_id = 'sources' and public.has_workspace_role(public.storage_path_workspace(name), 'editor'))`.
    `sources_objects_delete_owner` — DELETE, `to authenticated`,
    `using (bucket_id = 'sources' and public.has_workspace_role(public.storage_path_workspace(name), 'owner'))`.
    모든 술어가 `bucket_id = 'sources'`를 반드시 함께 고정한다 — `storage.objects`는 모든 버킷이 공유하는
    한 테이블이라 이걸 빠뜨리면 다른 버킷까지 이 정책이 적용된다.
    파서가 `null`을 반환하면 `is_workspace_member(null)`도 `has_workspace_role(null, …)`도 `false`이므로
    2세그먼트 경로가 자동으로 거부된다 — 이 null 전파가 "3세그먼트 검사"의 실제 집행 경로다. 주석으로 명시한다.

    **`supabase/tests/0005_storage_policies.sql`** — 단일 트랜잭션으로 시작해 마지막에 `rollback`한다
    (테스트가 로컬 DB 상태를 남기지 않는다). 한국어 주석, 소문자 SQL 키워드.
    픽스처(postgres 역할로 실행):
    - `auth.users`에 사용자 2명 삽입 — `u_editor`, `u_outsider`. `id`와 `email`만 넣고, NOT NULL 제약이
      더 요구하면 오류가 지목하는 컬럼만 최소로 채운다.
    - `public.workspaces`에 워크스페이스 2개 삽입 — `ws_a`(owner = `u_editor`), `ws_b`(owner = `u_outsider`).
      `workspaces_add_owner_member` 트리거가 각 소유자를 `owner` 멤버로 자동 등록하므로
      `workspace_members` 직접 삽입은 필요 없다.
    - `raw_source_id` 역할을 할 UUID 하나를 상수로 잡는다. `raw_sources` 행은 만들지 않는다 —
      `storage.objects.name`은 문자열일 뿐 FK가 아니다.

    이후 `set local role authenticated;` 와
    `select set_config('request.jwt.claims', json_build_object('sub', <u_editor id>)::text, true);` 로
    `u_editor`를 가장한다. 그 상태에서 세 단언을 수행한다:
    1. **정상 3세그먼트는 성공** — `storage.objects`에 `bucket_id='sources'`,
       `name = '<ws_a>/<raw_source_id>/report.pdf'` 삽입이 성공해야 한다. 실패하면 `raise exception`.
    2. **멤버여도 2세그먼트는 거부** — `name = '<ws_a>/evil.pdf'` 삽입이 `insufficient_privilege`
       (SQLSTATE 42501)로 실패해야 한다. `do $$ begin … exception when insufficient_privilege then
       null; end $$;` 형태로 감싸고, 예외가 나지 않으면 `raise exception`으로 테스트를 실패시킨다.
    3. **비멤버 워크스페이스 경로는 거부** — `name = '<ws_b>/<raw_source_id>/report.pdf'` 삽입이 같은
       방식으로 42501이어야 한다.
    추가 단언 하나를 더 둔다:
    4. **UUID가 아닌 첫 세그먼트가 에러가 아니라 거부** — `name = 'not-a-uuid/x/y.pdf'` 삽입이
       22P02(invalid_text_representation)가 **아니라** 42501로 실패해야 한다. 22P02가 잡히면
       `raise exception`으로 실패시킨다 — D-05가 헬퍼 함수를 도입한 진짜 이유가 이 단언이다.
    마지막에 `select 'storage_policies: ok' as result;` 를 출력하고 `rollback`.

    **`scripts/verify_storage_policies.sh`** — `set -euo pipefail`.
    `docker exec -i supabase_db_NexusWiki psql -U postgres -d postgres -v ON_ERROR_STOP=1 -f -`
    로 위 SQL을 표준입력으로 흘려 넣고, 출력에 `storage_policies: ok`가 포함되지 않으면 exit 1.
    `ON_ERROR_STOP=1`이 없으면 `raise exception`이 나도 psql 종료 코드가 0이라 테스트가 조용히 통과한다 —
    스크립트 주석에 이 함정을 `⚠️`로 적는다.
