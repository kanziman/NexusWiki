<objective>
Phase 1의 tracer 슬라이스. uv 워크스페이스 3멤버(`packages/core` · `apps/api` · `apps/worker`)를 세우고,
`packages/core`의 공용 structlog 로깅 모듈 하나를 두 앱이 함께 쓰는 상태를 **로컬에서 끝까지 실행해 증명**한다.
이 계획이 통과하기 전까지 Docker · Railway · Next.js 어느 것도 시작하지 않는다 — 여기서 아키텍처가 틀리면
그 위에 쌓은 전부가 무효다.

Purpose: BOOT-04(재현 가능한 monorepo)와 BOOT-06(기동 · 헬스 · 구조화 로깅)의 실질을 확정한다.

SIGTERM에 즉시 내려가는 worker 엔트리포인트, 그리고 이 셋을 한 번에 검증하는 `scripts/smoke_tracer.sh`.
</objective>

    **`packages/core/pyproject.toml`** — `name = "nexuswiki-core"`, `requires-python = ">=3.12,<3.13"`,
    dependencies `structlog==26.1.0`, `orjson==3.11.9`. `[tool.hatch.build.targets.wheel] packages = ["src/nexuswiki_core"]`
    (D-09: `src/` 레이아웃 — 임포트 섀도잉 방지).

    **`packages/core/src/nexuswiki_core/logging.py`** — 이 페이즈에서 core가 담는 유일한 실질 내용.
    파일 헤더는 PATTERNS §Shared Pattern 2 형식: `관련 태스크: P0-INIT-02`,
    `설계 근거: 01-CONTEXT.md > D-13`. 공개 API는 정확히 다음 이름들이다:
    - `REDACTED_KEYS: frozenset[str]` — 소문자 키 denylist. 최소 원소:
      `password`, `authorization`, `token`, `api_key`, `apikey`, `secret`, `email`,
      `access_token`, `refresh_token`, `content`, `supabase_secret_key`,
      `openrouter_api_key`, `openai_api_key`, `database_url`
    - `REDACTION_PLACEHOLDER: str` — 마스킹 치환값
    - `redact_sensitive(logger, method_name, event_dict)` — structlog 프로세서. `event_dict`의 각 키를
      `casefold()`해 `REDACTED_KEYS`에 있으면 값을 `REDACTION_PLACEHOLDER`로 치환한다. 중첩 `dict` 값에도
      재귀 적용한다. `⚠️` 블록으로 "denylist에 키를 빠뜨리면 조용히 새어 나간다 — 그래서 키 목록 자체를
      단위 테스트로 고정한다"를 적는다 (D-13이 allowlist 대신 denylist를 고른 이유는 여기 다시 쓰지 말고
      `01-CONTEXT.md > D-13`을 가리킬 것).
    - `configure_logging(*, environment: str, log_level: str) -> None` — 프로세서 체인 순서는
      `structlog.contextvars.merge_contextvars` → `structlog.processors.add_log_level` →
      `structlog.processors.TimeStamper(fmt="iso", utc=True)` → `redact_sensitive` → 렌더러.
      `merge_contextvars`가 반드시 맨 앞이어야 contextvar가 이벤트 딕트에 합류한 뒤 마스킹된다.
      렌더러는 `environment == "development"`이면 `structlog.dev.ConsoleRenderer(colors=True)`,
      그 외에는 `structlog.processors.JSONRenderer(serializer=orjson.dumps)` (D-13).
      `structlog.make_filtering_bound_logger`로 `log_level`을 적용한다.
    - `bind_job_context(*, job_id: str | None = None, workspace_id: str | None = None) -> None` —
      `structlog.contextvars.bind_contextvars`를 감싼다. `None` 인자는 바인딩하지 않는다.
    - `clear_job_context() -> None` — `structlog.contextvars.clear_contextvars`를 감싼다.
    - `get_logger(name: str)` — `structlog.get_logger(name)` 얇은 재노출.

    `uvicorn==0.52.0`, `httpx==0.28.1`. `[tool.uv.sources] nexuswiki-core = { workspace = true }`.

    **`apps/api/src/api/main.py`** — `create_app() -> FastAPI`와 모듈 수준 `app = create_app()`.
    `contextlib.asynccontextmanager`로 `lifespan(app)`을 정의하고 그 안에서 (1) `configure_logging()`을
    `os.environ`의 `ENVIRONMENT`(기본 `development`)와 `LOG_LEVEL`(기본 `INFO`)로 호출, (2) 공유
    `httpx.AsyncClient(timeout=httpx.Timeout(2.0))` 하나를 만들어 `app.state.http_client`에 둔다,
    (3) `yield` 뒤에 `await app.state.http_client.aclose()`. `@app.on_event`는 쓰지 않는다(deprecated).
    필수 env 부재 시 즉시 실패시키는 규약은 여기서는 적용하지 않는다 — `/health`는 DB 없이도 200이어야
    하므로 Supabase 관련 키는 `/health/ready` 안에서만 요구한다(Task 3).

    **`apps/api/src/api/routers/health.py`** — `router = APIRouter()`에 `GET /health` 하나.
    프로세스 생존만으로 200, 본문은 `{"status": "ok", "git_sha": <RAILWAY_GIT_COMMIT_SHA 또는 GIT_SHA 또는 "unknown">}`.
    버전 · 환경 이름 · DB URL 같은 내부 정보는 넣지 않는다. `/health/ready`는 Task 3에서 같은 라우터에 추가한다.

    **`apps/api/src/api/__main__.py`** — D-03의 집행 지점. 파일 헤더에
    `설계 근거: 01-CONTEXT.md > D-03 (exec form CMD + 프로그래밍 방식 uvicorn — SIGTERM 전달)`을 적고,
    `⚠️` 블록으로 "shell을 끼우면 shell이 PID 1이 되어 SIGTERM이 자식에게 전달되지 않고, 증상은 재배포 시
    잡 유실로만 나타난다"를 적는다. 본문은 `uvicorn.run("api.main:app", host="0.0.0.0",
    port=int(os.environ.get("PORT", "8000")), log_config=None)`. `log_config=None`이어야 uvicorn이
    structlog 설정을 덮어쓰지 않는다.

    **`apps/worker/pyproject.toml`** — `name = "worker"`, dependencies `nexuswiki-core`, `httpx==0.28.1`.
    `[tool.uv.sources] nexuswiki-core = { workspace = true }`. `packages = ["src/worker"]`.

    **`apps/worker/src/worker/__main__.py`** — SPEC 경계상 잡 루프는 없다. `async def main()`이
    (1) `configure_logging()` 호출, (2) `loop.add_signal_handler(signal.SIGTERM, stop.set)`와 SIGINT 동일
    (`signal.signal`은 임의 스레드에서 발화해 루프를 건드릴 수 없으므로 금지), (3) `bind_job_context(
    job_id="bootstrap", workspace_id="bootstrap")`으로 컨텍스트를 바인딩한 뒤 `worker.started` 로그 한 줄 출력,
    (4) `await stop.wait()`, (5) `worker.stopped` 로그 후 정상 반환. `if __name__ == "__main__":
    asyncio.run(main())`. RTT 측정은 계획 01-08이 이 파일에 추가한다.

    **`scripts/smoke_tracer.sh`** — `set -euo pipefail`. 이 tracer의 end-to-end 판정기이며 계획 01-06의
    컨테이너 태스크가 그대로 재사용한다. 동작:
    1. `PORT=8011 uv run --package api python -m api`를 백그라운드로 띄우고 최대 20초 동안
       `curl -fsS -o /dev/null -w '%{http_code}' http://127.0.0.1:8011/health`가 `200`을 낼 때까지 폴링,
       실패하면 exit 1
    2. api에 SIGTERM을 보내고 10초 내 종료 확인
    3. `uv run --package worker python -m worker`를 백그라운드로 띄우고 최대 15초 동안 stdout에
       `worker.started`가 나올 때까지 대기
    4. worker에 SIGTERM을 보내고 10초 내 **종료 코드 0**으로 내려가는지 확인, 아니면 exit 1
    5. 전부 통과하면 `smoke_tracer: ok`를 출력하고 exit 0
    `--image <tag>` 인자가 주어지면 1·3단계의 `uv run …` 대신 `docker run` 경로를 타도록 분기를 두되,
    이 태스크에서는 `uv run` 경로만 실제로 검증한다.

    마지막에 `uv sync` 한 번을 돌려 `uv.lock`을 생성하고 커밋 대상에 포함한다.
