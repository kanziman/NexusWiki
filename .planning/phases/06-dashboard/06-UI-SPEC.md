## Auto-Mode Notice

This UI-SPEC was produced under an explicit user instruction: *"recommend best practice for each,
and apply this"* — no interactive questions were asked. Every open design decision below was
auto-selected using the locked Airbnb-style token file (`docs/design-systems/design-tokens.css`)
and `06-CONTEXT.md` D-01~D-11 as the ground truth, with rationale noted inline at the point of
each decision so it stays auditable. Two decisions could not simply be "recommended" — they required
a project fact-check first — and are called out explicitly:

1. **shadcn was not initialized this phase.** The `shadcn init --preset {paste}` step requires the
   developer to visit `ui.shadcn.com/create` in a browser and paste back a preset string — a
   real interactive round-trip, not an open design question I can resolve by picking a "best
   practice" answer. Since this run cannot pause for that exchange, `Tool: none` is recorded below.
   Recommendation for the executor/team: run `npx shadcn init` manually before or during
   Phase 6 execution if headless Radix primitives (chosen below) turn out to be insufficient for a
   given component; this is a reversible, additive choice and does not block Phase 6 planning.
2. **The existing 18-token color palette has no positive/neutral-warning semantic color** — only
   the brand red spectrum (`--color-primary*`), one link blue, and two luxe/plus accents. QC-01
   (disputed) and QC-02 (verified/expires_at) require a "verified = good" signal the palette
   cannot express today. Rather than reinvent the palette, two minimally-scoped semantic text
   colors are proposed as an addition (see **Color** section) — not a redesign, a gap-fill for a
   state the existing system was never asked to express.

## Spacing Scale

Project tokens (`docs/design-systems/design-tokens.css:60-69`) are reused verbatim — not the
generic template defaults, since CONTEXT.md locks this file as already-decided:

| Token | Value | Usage |
|-------|-------|-------|
| xxs | 2px | Icon-glyph-to-label micro gaps (citation superscript kerning) |
| xs | 4px | Icon gaps, inline padding, badge internal padding |
| sm | 8px | Compact element spacing (stepper dot gaps, tab underline offset) |
| md | 12px | List row internal padding (source rows, member rows) |
| base | 16px | Default element spacing (form field gaps, card padding) |
| lg | 24px | Section padding (dropzone panel, wiki page margin) |
| xl | 32px | Layout gaps (sidebar-to-content gutter) |
| xxl | 48px | Major section breaks (auth page vertical rhythm) |
| section | 64px | Page-level spacing (top-level page padding on wide viewports) |

Exceptions:
- **Icon-only touch targets: 44×44px minimum hit area** (WCAG 2.5.5), applied to the job-retry

  `--spacing-md`/`--spacing-base` padding around a 20–24px `lucide-react` glyph, not a new token.
- No other exceptions.

## Typography

Project has a much larger existing type scale (`design-tokens.css:73-100`, 16 named composite
tokens). The 4 roles below are the subset Phase 6's surfaces actually use; the rest of the scale
remains available for future phases without redeclaration.

| Role | Size | Weight | Line Height | Source token |
|------|------|--------|-------------|--------------|
| Body | 16px | 400 | 1.5 | `--font-body-md` — wiki article body, ask chat bubbles, form inputs |
| Label | 14px | 500 | 1.29 | `--font-caption` — role badges, source-row meta, stepper step labels, table headers |
| Heading | 16px | 600 | 1.25 | `--font-title-md` — card titles, section headers, member-row name |
| Display | 28px | 700 | 1.43 | `--font-display-xl` — page-level titles only (wiki page H1, "NexusWiki" wordmark) |

Weights: primary pair is **400 (regular) / 600 (semibold)**. 500 (Label) and 700 (Display) are
**inherited exceptions** from the pre-existing token file, used narrowly for exactly the two roles
above — not phase-invented additional weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-canvas` `#ffffff` | Page background, all surfaces default to white |
| Secondary (30%) | `--color-surface-soft` `#f7f7f7` + `--color-hairline` `#dddddd` | Dropzone panel background, sidebar/nav background, member-row/source-row dividers, wiki-viewer read-only banner background |
| Accent (10%) | `--color-primary` `#ff385c` | **Reserved for:** primary CTA buttons ("소스 등록", "질문하기", "초대 보내기"), the active workspace indicator in the switcher dropdown, citation superscript markers on hover/active, the current step in the job stepper (D-05), red-link "지금 생성" CTA text/icon |
| Destructive | `--color-primary-error-text` `#c13515` | **Reserved for:** job-cancel confirmation, member-removal confirmation, destructive dialog primary action. Deliberately **not** `--color-primary` — Airbnb's brand red is already the primary-CTA accent, so reusing it for destructive actions would make "add source" and "cancel job / remove member" visually indistinguishable. `--color-primary-error-text` is the existing muted-but-legible error red already reserved for inline form errors, giving destructive actions a distinct, lower-saturation red |

**Semantic addition — verification/dispute states (QC-01, QC-02, gap-fill, see Auto-Mode Notice #2):**

| Role | Value | Usage |
|------|-------|-------|
| Success text (new) | `#0a7d34` | `verification_status = 'verified'` callout icon/text (not yet expired) |
| Warning text (new) | `#8a5300` | `verification_status = 'partial'`, or `verified` **and** `expires_at` has passed ("만료됨") |
| Disputed (reuse) | `--color-primary-error-text` `#c13515` | `verification_status = 'disputed'` **or** `disputed = true` — same value as Destructive, semantically consistent ("conflicting information" is error-adjacent) |
| Unverified (reuse) | `--color-muted` `#6a6a6a` | `verification_status = 'unverified'` (default state) — neutral, not alarming |

Both new hex values are chosen at the same darkness/saturation level as the already-approved
`--color-primary-error-text` (`#c13515`) — dark, desaturated enough to clear AA text contrast on
white, consistent with the existing token file's approach to status text rather than status fills.
Executor should add these two as `--color-success-text` / `--color-warning-text` custom properties
in `design-tokens.css` during the `globals.css` `@theme` integration task already marked at
`apps/dashboard/app/globals.css:8`.

**`confidence` field (`high`/`medium`/`low`) is explicitly NOT rendered as a badge anywhere in
Phase 6** — per `REQUIREMENTS.md` Out of Scope: "수치 confidence 배지 노출" (LLM self-confidence is
uncalibrated and competes visually with the verification badge). Do not add a confidence chip.
