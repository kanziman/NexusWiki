  <files>apps/dashboard/lib/citation-anchors.ts, apps/dashboard/tests/citation-anchors.test.ts</files>
  <behavior>
    - Input `"본문 [[src:s1]] 계속 [[wiki:w2]] 끝"` with no resolution map -> splits into 5
      parts: text, anchor(kind=source,alias=s1), text, anchor(kind=wiki,alias=w2), text — this
      is the STREAMING mode (render every anchor-shaped token as a placeholder, matching
      `ISSUED_ANCHOR_PATTERN = /\[\[(wiki:w\d+|src:s\d+)\]\]/g` exactly, ported from
      `nexuswiki_core/citations.py`).
    - Input with a resolution map `{s1: {kind:"source", id:"uuid-1"}}` where `s1` is NOT in the
      map's keys (fabricated, never issued) -> the anchor part is OMITTED entirely from the
      split result (matches `resolve_citations`'s `_strip_fabricated` behavior — a fabricated
      anchor disappears, it does not render as anything, not even a placeholder, once resolution
      is known).
    - Mixed Korean/English text with 2 legitimate anchors resolves to alternating
      text/anchor/text/anchor/text parts, each anchor part carrying `{kind, alias, id}` when a
      resolution map is supplied.
    - Text with zero anchors returns a single text part unchanged.
  </behavior>
