      sends a request with a missing/empty Authorization header).

  <name>Task 2: lib/sse.ts — generic event:/data: frame parser</name>
  <files>apps/dashboard/lib/sse.ts, apps/dashboard/tests/sse.test.ts</files>
  <behavior>
    - A `Response` whose body streams `"event: meta\ndata: {\"a\":1}\n\n"` in one chunk yields
      one `{event: "meta", data: {a: 1}}` item.
    - The SAME frame split across two chunk boundaries (e.g. `"event: meta\ndata: {\"a\""` then
      `":1}\n\n"`) still yields exactly one correctly-parsed item — the parser buffers across
      `read()` calls and only emits on a complete `\n\n`-terminated frame.
    - Multiple frames in one chunk (`"event: a\ndata: {}\n\nevent: b\ndata: {}\n\n"`) yield two
      items in order.
    - A response with no body (`response.body === null`) yields zero items and returns cleanly
      (does not throw).
  </behavior>
  <read_first>
    apps/api/src/api/routers/ask.py lines 76-78 (`_format_sse` — the exact frame shape this
    parser must consume: `f"event: {name}\ndata: {json.dumps(payload)}\n\n"`).
  </read_first>
  <action>
    Create `apps/dashboard/lib/sse.ts`: export `async function* parseSseStream(response:
    Response): AsyncGenerator<{ event: string; data: unknown }>`. Guard `response.body === null`
    -> return immediately. Otherwise get a reader via `response.body.getReader()` +
    `TextDecoder`, accumulate decoded text in a string buffer, split on `"\n\n"` repeatedly
    (keep the trailing incomplete segment in the buffer across reads), and for each complete
    frame parse the `event: <name>` line and the `data: <json>` line (a frame may have multiple
    `data:` lines per the SSE spec in general, but this project's `_format_sse` always emits
    exactly one — parse only the first `data:` line, do not attempt multi-line data
    concatenation, since over-generalizing here would silently accept malformed frames the
    backend never produces). `yield { event, data: JSON.parse(dataLine) }`. This module is
    generic and framework-agnostic — it must not import anything Ask-specific; `06-06-PLAN.md`'s
    `AskConversation.tsx` is its only consumer this phase, but it belongs here because it is
    infrastructure, not a UI concern.
  </action>
