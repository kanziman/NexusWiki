<objective>
Implement QC-01's conflict detection exactly where D-05 locked it: a job-chain step appended after the wiki-embedding job completes (not the compile step — wiki_embeddings do not exist until embedding finishes, so an earlier trigger point would have nothing to compare against), using 05-02's `find_similar_wiki_pages` RPC for cheap semantic-similarity candidate surfacing and the project's existing `complete_structured()` structured-output pattern for the expensive contradiction-vs-legitimate-variation judgment call, writing `disputed=true`/`verification_status='disputed'` only when the LLM judge confirms an actual contradiction.

Purpose: this is the last requirement of the phase and the one most exposed to LLM cost — bounding it to write-time (once per newly-compiled page, not per Ask request) and to a cosine-thresholded candidate set (not every page pair in the workspace) keeps the added spend proportional to ingestion, not to query volume.
Output: a new `conflict_check` job type, chained automatically after every wiki-embed job, that surfaces and (on confirmed contradiction) marks disputed pages.
</objective>
