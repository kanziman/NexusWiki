<objective>
Close the cost-safety gap 05-RESEARCH.md's Pitfall 2 found: `enqueue_source_job` is the only budget-cap enforcement point in the schema and it only gates *queued* compile-pipeline jobs — the Ask endpoint's synchronous LLM call has no budget gate at all, so a workspace that has already exceeded its monthly cap could still make unlimited-cost Ask calls. Since `LlmStreamService` already needs a `service_client`/`ServiceDb` to record `usage_events` after each completed stream (05-RESEARCH.md Pattern 3's deliberate asymmetry from the query-embedding listener, which has no DB client at all), add the pre-flight budget check to the same code path.

Purpose: this is a real, documented architectural gap discovered mid-research (05-CONTEXT.md > D-09), not a numbered CITE/API/QC requirement on its own — it protects the OPS-01 cost guardrail this project's budget system exists for, using 05-01's already-built generic non-2xx error handling in `AskService.stream_answer()` (a 402 from the worker surfaces as the same graceful `citations`/`done` error event the tracer already built for 401/429/502/504) so no API-side code changes are needed at all.
Output: `LlmStreamService` rejects with 402 before opening an OpenRouter stream when a workspace is already at/over its monthly cap, and records every completed stream's usage exactly once.
</objective>
