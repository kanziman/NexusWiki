<objective>
Close the Phase 4 goal's worker-boundary observable-truth gap: replace the worker listener's process-lifetime request counter with a bounded, time-refilling control so the API's dense channels remain available under sustained normal retrieval traffic without weakening the private embedding boundary. This is not an RTV-09 task: RTV-09 (safe channel-failure isolation) is already verified; the gap is durable capacity at the private worker boundary.
</objective>

  <action>Replace `_remaining_requests` with a lock-protected token bucket that uses injected `time.monotonic`, has a positive configurable capacity and refill rate/interval, never exceeds capacity, and calculates available tokens before provider work. Authenticate and validate text before consuming a token. Consume one token for every authenticated, syntactically valid provider attempt, including provider failure or timeout, so an unavailable provider cannot be retried without a cost bound; preserve `CancelledError` propagation and do not refund a cancelled attempt once it has begun.     - A capacity of 2 admits two valid authenticated attempts, rejects the next immediately, and admits another after exactly the configured refill interval without a process restart.
    - Refill is based on monotonic elapsed time (not wall clock), is concurrency-safe, and cannot create more than capacity tokens.
    - Unauthenticated and invalid-text requests consume no quota; provider failure, timeout, and begun cancellation consume exactly one token according to the documented policy.
  </acceptance_criteria>

<threat_model>
- T-04-16 permanent availability loss: a process-lifetime counter turns routine traffic into an indefinite lexical-only degradation; monotonic bounded refill and deterministic recovery tests prevent it.
- T-04-17 cost exhaustion: refill must be rate-limited and capped, while failures/timeouts consume a token; capacity/refill validation and accounting tests prevent unlimited provider retries.
- T-04-18 quota bypass/race: authenticate and validate before reservation, protect token updates with a lock, and test simultaneous callers so invalid calls or races cannot drain/overspend quota.
- T-04-19 boundary regression: preserve private bearer authentication, vector validation, redaction, and no database/provider-key expansion; run the existing CI boundary gate and focused tests.
</threat_model>
