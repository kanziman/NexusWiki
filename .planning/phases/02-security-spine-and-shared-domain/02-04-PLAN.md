`two_workspaces_two_users` 픽스처는 **테스트마다 고유한** 사용자 2명과 워크스페이스 2개를 만들고 테스트 종료 시 전부 지운다. 사용자 이메일과 워크스페이스 이름에 `uuid4` 조각을 섞어 이름 충돌이 원리적으로 불가능하게 만든다. ⚠️ 픽스처를 세션 스코프로 공유하면 실행 순서와 병렬성에 따라 결과가 달라져 위양성/위음성이 생긴다 — 함수 스코프로 두고 teardown을 보장한다 (02-CONTEXT.md > D-14, SPEC Edge Coverage R5 concurrency). 이 `⚠️`를 픽스처 위에 남긴다.

사용자 생성은 로컬 GoTrue의 admin 경로로 하고, 각 사용자의 JWT를 password grant로 받는다. 워크스페이스는 `owner_id`를 그 사용자로 하여 만든다 — `workspaces_add_owner_member` 트리거가 소유자를 멤버로 자동 등록하므로 멤버십을 따로 넣지 않는다 (`0001_core_schema.sql:32-84`). teardown은 사용자 삭제로 시작해 cascade가 워크스페이스까지 지우는지 확인하고, 남는 것이 있으면 명시적으로 지운다.

`authed_client` 픽스처는 `test_health.py:13-18`의 `app_client()` 형태 위에 `Authorization: Bearer <jwt>` 헤더를 얹는다. 사용자를 인자로 받아 그 사용자의 클라이언트를 돌려주는 팩토리 픽스처로 만든다 — 한 테스트 안에서 A와 B의 클라이언트가 동시에 필요하다.

`apps/api/tests/test_workspaces_isolation.py`를 만든다. 모듈 최상단에 `CROSS_TENANT_CASES` 테이블을 두고 `(method, path_template, description)` 행으로 채운다. 새 라우터가 늘 때 이 테이블에 **행만 추가**하면 되도록 설계한다 (02-CONTEXT.md > D-14). `@pytest.mark.parametrize`로 그 테이블을 돌린다.

⚠️ 이 테스트가 공허해지는 두 가지 경로를 구조적으로 막는다: (1) 같은 워크스페이스를 두 번 쓰는 것 — 각 케이스가 A의 클라이언트로 **B의** id를 때린다는 것을 단언으로 고정한다(두 id가 서로 다름을 먼저 assert). (2) 인증 없는 요청 — 헤더에 JWT가 실렸음을 단언한다. 인증 없는 요청은 Unauthorized를 받으므로 Forbidden 단언이 통과해버리는 위양성이 생기지 않도록, 인증 없는 경우를 **별도 케이스**로 분리해 다른 상태 코드를 단언한다.
