파일 전체를 `begin;` / `commit;`으로 감싼다. ⚠️ 기존 마이그레이션 중 어느 것도 자기 자신을 트랜잭션으로 감싸지 않았으므로 `0007`이 최초 사례다. 이 이탈을 파일 상단 주석에 적고, SPEC R7이 "부분 적용 불가"를 수용기준으로 요구했다는 사실을 인용한다. Task 4가 이것을 `checklists.json`의 `deviations_from_plan`에도 올린다.

번호 섹션을 `-- ---` 규칙선으로 분리한다 (`0003:24-26` 형태). 섹션 1-6은 D-21이 정한 순서 그대로이고, 섹션 7은 D-21을 넘어선 의도적 추가(사유는 해당 섹션에), 섹션 8은 권한이다:

**1. 검색 함수** — 02-01-PLAN이 잠근 트랜스포트를 따른다. RPC가 채택됐다면 `supabase/spike/0002_search_fn_rpc.sql`의 `spike_search_chunks`를 프로덕션 이름으로 승격하고 `security invoker` + `stable` + `set search_path = public` + GUC 3종 modifier 블록을 그대로 유지하며 `grant execute ... to authenticated`를 건다. asyncpg가 채택됐다면 함수 대신 애플리케이션이 조립할 쿼리의 지원 객체만 두고, 왜 함수를 만들지 않는지 주석으로 남긴다. 어느 쪽이든 pgvector 참조는 schema-qualified다 (`0002_search_schema.sql:30`).

**2. `jobs_dedup_idx`** — 같은 워크스페이스에 같은 종류·같은 대상의 잡이 중복 인큐되는 것을 막는 부분 유니크 인덱스. 대기 중인 잡(`status in ('queued','running','failed')`)에만 걸어 완료된 잡이 재인큐를 막지 않게 한다. `payload` 안의 식별 키를 인덱스 표현식으로 쓰고, 어떤 키를 쓰는지와 왜 부분 인덱스인지를 주석으로 남긴다.

**3. `complete_job_and_chain(p_job_id uuid, p_next_type text, p_next_payload jsonb)`** — 완료와 다음 잡 인큐를 한 트랜잭션에 묶는다. `complete_job`(`0003:135-148`)의 형태를 따르되 `where id = p_job_id and status = 'running'` 절을 반드시 유지한다 — 이 절이 이미 `succeeded`인 잡에 대한 재호출을 예외가 아니라 0행 no-op으로 만든다 (SPEC R10 수용기준이 이미 이것에 의존한다). 0행이면 다음 잡을 인큐하지 않는다. `locked_at`과 `locked_by`를 함께 비운다 — `jobs_lock_consistency` CHECK(`0003:65-68`)가 그러지 않으면 행을 거부한다.

**4. `release_job(p_job_id uuid, p_worker_id text)`** — `status='queued'`, `attempts = attempts - 1`, `locked_at=null`, `locked_by=null`로 바꾸고 `where id = p_job_id and status = 'running' and locked_by = p_worker_id`. ⚠️ `locked_by` 술어가 R10의 "다른 워커의 진행을 덮어쓰지 않는다"를 참으로 만드는 유일한 장치다. `attempts >= 0` CHECK(`0003:47`)가 감소를 지킨다. ⚠️ `fail_job`을 재사용하면 재배포 세 번에 정상 잡이 `dead`로 떨어진다는 사실을 주석으로 남기고 근거는 `02-CONTEXT.md > D-18`.

**5. 검증 메타** — `wiki_pages`에 `verified_by uuid references auth.users(id)`, `verified_at timestamptz`, `expires_at timestamptz`를 추가한다. 주인과 날짜 없는 검증 배지는 쓰이지 않는다는 DOM-03의 요지를 주석으로 남긴다. `verification_status`가 `verified`일 때 `verified_by`/`verified_at`이 있어야 한다는 CHECK를 걸지, 애플리케이션에 맡길지 결정하고 그 판단 근거를 주석에 남긴다.

**6. 버전 컬럼** — `source_chunks`와 `wiki_embeddings`에 `embedding_version`을, `source_chunks`에 `chunker_version`을 추가한다. 어휘 검색에만 버전이 있던 비대칭을 해소하는 것이 DOM-04다. 타입은 **`text`** 다 — 임베딩 모델 이름(`text-embedding-3-small`)과 청커 버전은 애초에 문자열이다. 바로 다음 섹션 7이 `tsv_tokenizer_version`도 `text`로 맞추므로 세 버전 컬럼의 타입이 일치한다.

**7. 토크나이저 버전 컬럼 타입 정정 (D-21 이탈)** — `source_chunks.tsv_tokenizer_version`(`0002_search_schema.sql:94`)과 `wiki_pages.tsv_tokenizer_version`(`:220`)을 `smallint`에서 `text`로 바꾼다. 두 컬럼 모두 `alter table ... alter column ... type text` 한 줄이며 `using` 절이 필요 없다 — 지금 두 테이블의 행이 0개이기 때문이다.

`supabase/tests/0007_queue_functions.sql`을 만들고 `release_job()`의 계약을 SQL 수준에서 고정한다. `supabase/tests/0005_storage_policies.sql`의 형식과 관례를 따른다 — `supabase/migrations/`가 아니라 `supabase/tests/`에 두어 `db reset`이 이것을 적용하지 않게 한다.

고정할 계약 네 가지:

1. **`attempts` 되돌림** — 워크스페이스와 `noop` 잡을 하나 만들고 `claim_job('w1', array['noop'])`으로 점유한다. `attempts`가 1이 된 것을 확인한 뒤 `release_job(id, 'w1')`을 부르고, `attempts`가 다시 0이고 `status`가 `queued`이며 `locked_at`/`locked_by`가 모두 null인 것을 단언한다.
2. **락 소유자 술어** — 같은 잡을 `'w1'`이 점유한 상태에서 `release_job(id, 'w2')`를 부르면 **아무 행도 반환되지 않고** 잡 상태가 그대로 `running`이며 `locked_by`가 여전히 `'w1'`인 것을 단언한다. 이것이 R10의 "다른 워커의 진행을 덮어쓰지 않는다"의 SQL 수준 증명이다.
3. **상태 술어** — 이미 `succeeded`인 잡에 `release_job`을 부르면 0행 no-op이고 예외가 나지 않는 것을 단언한다.
4. **`complete_job_and_chain` 원자성** — 점유된 잡에 대해 호출하면 그 잡이 `succeeded`가 되고 다음 잡이 `queued`로 새로 생기는 것을 하나의 단언으로 확인한다. 이미 `succeeded`인 잡에 재호출하면 0행이고 다음 잡이 **추가로 생기지 않는** 것을 단언한다 — 여기서 실패하면 at-least-once 재처리가 잡을 무한 증식시킨다.

단언은 `do $$ begin ... if not (...) then raise exception '...'; end if; end $$;` 형태로 쓰고 실패 시 무엇이 어긋났는지 값과 함께 밝힌다. 테스트가 만든 행은 마지막에 전부 지운다 — 남기면 `jobs_dedup_idx`가 다음 실행을 방해한다.

파일 헤더에 이 스크립트가 검증 전용이며 마이그레이션 순서에 들어가지 않는다는 사실과 실행 방법(`docker exec -i` 경유)을 한국어로 적는다.
