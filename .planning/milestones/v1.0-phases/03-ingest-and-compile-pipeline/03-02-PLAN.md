## 이 플랜이 닫는 위임 결정 (03-CONTEXT.md `<deferred>` — planner 재량, 근거를 남긴다)

**D-P1 — 인큐 권한 모델: `security definer` RPC를 택하고 `jobs`에 INSERT 정책을 만들지 않는다.**
조건부 INSERT 정책 + grant를 주면 `authenticated`가 PostgREST로 `/jobs`에 직접 INSERT할 수 있게
되고, 그 경로는 **비용 상한을 건너뛴다**. OPS-01은 상한이 *인큐 시점에* 걸릴 것을 요구하므로
"상한을 통과하지 않고는 잡이 만들어질 수 없다"가 구조적으로 참이어야 한다. definer 함수는
그 조건을 만족하는 유일한 형태다 — 다른 INSERT 경로가 존재하지 않기 때문이다.
대가: definer는 RLS를 우회하므로 함수 본문이 `has_workspace_role` 로 멤버십을 **직접** 확인해야
하고 `set search_path = public` 이 필수다. `0004`의 헬퍼 3종과 `0005`의 Storage 헬퍼가 이미
같은 규율을 쓴다.

**D-P2 — 비용 단위는 micro-dollar 정수(`cost_micros bigint`), 기본 상한은 워크스페이스당 월 $5.00.**
단위를 토큰이 아니라 돈으로 두는 이유: 상한이 지키려는 것은 토큰 수가 아니라 청구서이고,
LLM과 임베딩의 토큰 단가가 다르므로 토큰 합은 청구서와 단조 관계가 아니다. 부동소수가 아니라
정수 micro인 이유: `sum()`이 순서와 무관하게 정확해야 상한 판정이 재현 가능하다 (edge: precision,
ordering). 기본값 $5.00 = `5000000` micros는 `checklists.json > open_questions` 의
"워크스페이스별 월 LLM 비용 상한값"을 Phase 3에서 닫은 값이며, 근거는 PROJECT 예산 제약
(Railway Hobby $5/mo 수준의 개인 프로젝트)이다. 값은 `workspaces.monthly_budget_micros` 컬럼이라
워크스페이스마다 다르게 둘 수 있다.

**D-P3 — 취소는 `jobs.status`에 `canceled`를 더하고 협조적으로 한다.**
`jobs.status` CHECK 변경은 "기존 객체 변경"이지만 D-01의 판별 기준에 걸리지 않는다 — 되돌릴 수
없는 것은 **파일 번호**이지 객체가 아니고, CHECK는 어느 번호의 마이그레이션에서도
`drop constraint` + `add constraint`로 되돌릴 수 있다. 되돌릴 수 없었던 임베딩 차원과 다른
점은 데이터가 걸려 있지 않다는 것이다. `running` 잡을 즉시 죽이지 않고
`cancel_requested_at` 만 찍는 이유는 워커가 `jobs`를 직접 UPDATE하지 않는다는 계약과
COMP-04의 잡 분할이다 — 체인이 4개로 쪼개져 있어 취소가 다음 단계 경계에서 반영된다
(02-CONTEXT.md > D-16이 하트비트 대신 분할을 택한 것의 배당금).

    **섹션 1 — `jobs` 상태 확장.** 먼저 `pg_constraint`로 `public.jobs`의 `status` 인라인 CHECK 이름을 확인한다(기대값 `jobs_status_check`; 다르면 실제 이름을 쓴다). `alter table public.jobs drop constraint jobs_status_check;` 후 `add constraint jobs_status_check check (status in ('queued','running','succeeded','failed','dead','canceled'));`. 이어 `alter table public.jobs add column cancel_requested_at timestamptz;` 와 그 컬럼에 대한 `comment on column`. 주석에 `⚠️`로 남길 것: `canceled`는 `running`이 아니므로 `jobs_lock_consistency`(0003:65-68)가 `locked_at`/`locked_by`를 null로 요구한다는 사실, 그리고 `claim_job`의 `status in ('queued','failed')` 술어 덕분에 `canceled` 잡은 다시 집히지 않는다는 사실.

    **섹션 2 — `workspaces` 월 상한.** `alter table public.workspaces add column monthly_budget_micros bigint not null default 5000000 constraint workspaces_budget_non_negative check (monthly_budget_micros >= 0);` 와 `comment on column` — 단위가 micro-dollar 정수이고 이유는 `03-02-PLAN.md > D-P2`라고만 가리킨다(근거 재서술 금지).

    **섹션 3 — `usage_events`.** 컬럼: `id uuid primary key default gen_random_uuid()`; `workspace_id uuid not null references public.workspaces (id) on delete cascade`; `job_id uuid references public.jobs (id) on delete set null`; `kind text not null check (kind in ('llm','embedding'))`; `provider text not null check (char_length(btrim(provider)) > 0)`; `model text not null check (char_length(btrim(model)) > 0)`; `prompt_tokens int not null default 0 check (prompt_tokens >= 0)`; `completion_tokens int not null default 0 check (completion_tokens >= 0)`; `total_tokens int not null default 0 check (total_tokens >= 0)`; `cost_micros bigint not null default 0 check (cost_micros >= 0)`; `occurred_at timestamptz not null default now()`; `metadata jsonb not null default '{}'`. 인덱스 `usage_events_workspace_occurred_idx on public.usage_events (workspace_id, occurred_at desc)`. `alter table public.usage_events enable row level security;` 를 **같은 마이그레이션에서** 켜고(0001의 관례) 정책 하나만 만든다: `create policy usage_events_select_member ... for select to authenticated using (public.is_workspace_member(workspace_id));`. 사용자 쓰기 경로는 설계상 없다. `metadata` 컬럼 주석에 `⚠️`로 남길 것 — 여기에 프롬프트나 LLM 응답 본문을 싣지 않는다, 이 테이블은 멤버가 SELECT할 수 있다.

    **섹션 4 — `dead_letter_job`.** `create or replace function public.dead_letter_job(p_job_id uuid, p_worker_id text, p_error text) returns setof public.jobs language sql volatile set search_path = public` 로 만들고 본문은 `release_job`(0007:212-233)과 **동형**으로 쓴다 — `update public.jobs j set status = 'dead', last_error = p_error, locked_at = null, locked_by = null where j.id = p_job_id and j.status = 'running' and j.locked_by = p_worker_id returning j.*;`. `comment on function` 에 계약을 적는다: 락 소유자 본인만 데드레터로 보낼 수 있고, `locked_by`가 다르거나 `running`이 아니면 0행 no-op이며 `service_role` 전용이다. 주석에 `⚠️`로 남길 것 — `locked_by = p_worker_id` 술어가 없으면 reap이 락을 뺏은 뒤 늦게 깨어난 워커가 남의 잡을 `dead`로 만든다.

    **섹션 5 — `cancel_job`.** `public.cancel_job(p_job_id uuid, p_worker_id text) returns setof public.jobs`, `language sql volatile set search_path = public`, 본문은 `status = 'canceled', locked_at = null, locked_by = null` 로 두고 술어는 `dead_letter_job`과 같은 3개(`id` · `status = 'running'` · `locked_by = p_worker_id`). `service_role` 전용. 워커가 claim 직후 `cancel_requested_at`을 보고 핸들러를 돌리지 않은 채 이 함수로 마감하는 경로다.

    **섹션 6 — 사용자 RPC 3종 (전부 `security definer stable=아님/volatile` · `set search_path = public`).**
    (a) `public.enqueue_source_job(p_workspace_id uuid, p_raw_source_id uuid) returns setof public.jobs`, `language plpgsql volatile security definer set search_path = public`. 잡 종류를 인자로 받지 **않는다** — 본문이 `'parse'`를 고정한다. 그러지 않으면 로그인 사용자가 임의의 `jobs.type`과 임의의 payload를 definer 권한으로 삽입할 수 있다. 본문 순서: (1) `if not public.has_workspace_role(p_workspace_id, 'editor') then raise exception '...' using errcode = '42501'; end if;` (definer는 RLS를 우회하므로 이 확인이 유일한 격리 수단이다). (2) `if not exists (select 1 from public.raw_sources r where r.id = p_raw_source_id and r.workspace_id = p_workspace_id) then raise exception ... using errcode = '42501'; end if;`. (3) 이번 달 지출 계산 — `select coalesce(sum(u.cost_micros), 0) into v_spent from public.usage_events u where u.workspace_id = p_workspace_id and u.occurred_at >= date_trunc('month', now() at time zone 'utc');` 그리고 `select w.monthly_budget_micros into v_cap from public.workspaces w where w.id = p_workspace_id;`.
