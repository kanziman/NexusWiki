넥서스위키 AI 답변 방금 전
넥서스위키의 테넌트 격리는 애플리케이션 코드가 아닌 Postgres 데이터베이스 엔진이 직접 강제합니다.

1. 모든 9개 테이블은 문서에 명시된 복합 외래키 (id, workspace_id)로 테넌트 경계를 전파합니다.

2. 원본 아키텍처 설계 문서 에 따르면 백그라운드 워커 계층조차 테넌트 경계를 우회할 수 없으며, 38개 RLS 정책 테스트를 통과했습니다.

개요 (Summary)

넥서스위키의 모든 데이터는 멀티테넌트 환경에서 완벽히 격리되며, Postgres 17의 RLS 정책과 (id, workspace_id) 복합 외래키를 통해 물리적 데이터 유출을 원천 방지합니다.

1. 복합 외래키 전파 규칙

단일 ID 컬럼 대신 상위 테넌트의 workspace_id가 모든 하위 테이블에 복합 키로 전파되어 조인 쿼리 단계의 테넌트 경계 이탈이 불가능합니다.

2. 38개 RLS 정책 보안 검증

비동기 백그라운드 워커 풀조차 request.jwt.claim.workspace_id 컨텍스트를 강제받으며, 자동화된 테스트 스위트 38건이 통과되었습니다.

-- Enable Row Level Security
ALTER TABLE "workspace_members" ENABLE ROW LEVEL SECURITY;

CREATE POLICY "members_isolation_policy" ON "workspace_members"
FOR ALL USING (workspace_id = (current_setting('request.jwt.claim.workspace_id', true))::uuid);

-- Composite FK enforcement
ALTER TABLE "documents" ADD CONSTRAINT "fk_doc_ws"
FOREIGN KEY ("id", "workspace_id") REFERENCES "workspaces"("id", "workspace_id") ON DELETE CASCADE;
