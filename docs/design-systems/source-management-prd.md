# 넥서스위키(NexusWiki) 원문 소스 관리 & 임베딩 파이프라인 PRD

> **문서 상태**: 확정 (Validated)  
> **기능 영역**: 원본 소스 수집, 청킹 관리 및 5채널 임베딩 파이프라인 뷰어 (`/sources`)

## 1. 개요 및 목적 (Overview & Goals)

### 1.1. 배경
* 넥서스위키는 엔지니어링 원천 자료(SQL DDL, 시스템 아키텍처 PDF, 슬랙 기술 논의 내역, 마크다운 등)를 수집하여 청킹한 뒤, 순수 PostgreSQL 기반의 **5채널 하이브리드 인덱싱**을 통해 살아있는 위키(Living Wiki)로 자동 컴파일합니다.
* 사용자는 **어떤 원본 파일이 등록되어 있고, 불변(Immutable) 청킹 및 5채널 임베딩이 정상적으로 완료되었으며, 각 소스가 어떤 위키 문서에 인용되고 있는지**를 한눈에 관리할 수 있어야 합니다.

### 1.2. 핵심 원칙 및 데이터 계약
1. **불변(Immutable) 소스 파이프라인 원칙**:
   * `raw_sources` 및 `source_chunks`는 Insert-only 데이터 계약을 따르며 `UPDATE` 정책이 존재하지 않습니다.
   * `verification_status`, `confidence`, `disputed`, `verified_by`는 원본 소스가 아닌 **오직 `wiki_pages`에만 존재**하며, 소스 화면에서는 순수 파이프라인 인덱싱 상태(`● 인덱싱 완료`, `⏳ 처리 중`, `❌ 인덱싱 실패`)만 추적합니다.
2. **실제 5채널 하이브리드 검색 인덱스 체계**:
   * ① `wiki_embeddings` HNSW (pgvector)
   * ② `source_chunks` HNSW (pgvector)
   * ③ `wiki_pages.search_tsv` GIN (Full-Text Search)
   * ④ `source_chunks.search_tsv` GIN (Full-Text Search)
   * ⑤ `wiki_links` 재귀 CTE 그래프 확장 (Recursive CTE Graph Extension)
   *(별도 BM25 엔진이나 외부 그래프 DB 없이 순수 pgvector + tsvector + CTE로 구동)*
3. **양방향 N:M 인용 매핑 추적**: 각 소스 파일이 인용되고 있는 모든 위키 문서 목록을 알약 칩(`📘 테넌트 격리...`)으로 제공.
4. **청크 단위 데이터 검사 (Chunk Inspector)**: 개별 청크의 텍스트 발췌문, 캐릭터 좌표(`char range`), 토큰 수 정밀 검사.

## 2. 사용자 페르소나 및 유저 스토리 (User Stories)

* **백엔드 개발자 (User A)**: "새로운 DB 마이그레이션 SQL 파일을 업로드하고, 파이프라인이 12개 청크로 분할하여 HNSW 및 GIN 인덱싱을 완료하는 과정을 확인하고 싶다."
* **인프라/DevOps 엔지니어 (User B)**: "5채널 하이브리드 인덱싱 작업이 100% 완료되었는지, 실패한 청크가 없는지 파이프라인 헬스 상태를 점검하고 싶다."
* **테크 리드 (User C)**: "더 이상 유효하지 않은 오래된 소스를 삭제하거나 재인덱싱하여 위키의 정합성을 최신으로 유지하고 싶다."

## 3. 핵심 기능 요구사항 (Functional Requirements)

### 3.1. 상단 파이프라인 통계 및 툴바 (Header & Pipeline Stats)
* **브레드크럼 경로**: `엔지니어링 코어 / 원문 소스 관리`
* **타이틀 & 설명**: `원문 소스 관리 & 임베딩 파이프라인` + 1줄 요약.
* **3대 핵심 파이프라인 메타 통계**:
  * 📦 총 등록 소스: **18개 파일**
  * 📑 생성된 청크: **42개 청크**
  * ⚡ 5채널 인덱싱 상태: **100% 완료 (정상 가동 중)**
* **우측 액션 버튼**: `[+ 소스 업로드]` 프라이머리 알약 버튼.

### 3.2. 소스 필터 및 목록 테이블 (Source Management Table)
* **단일 축(파일 포맷) 탭 필터**: `전체 (18)`, `SQL 스크립트 (8)`, `PDF 문서 (5)`, `마크다운 (3)`, `CSV/JSON (2)`.
* **데이터 테이블 컬럼 구성**:
  1. **소스 파일명 & 포맷**: 확장자 배지(`SQL`, `PDF`, `MD`, `CSV`), 파일명, 용량.
  2. **연결된 위키 문서**: 해당 소스를 인용 중인 컴파일된 위키 칩(`📘 테넌트 격리 및 RLS...`).
  3. **청크 수 및 좌표**: 분할된 청크 수 및 토큰 메타.
  4. **파이프라인 인덱싱 상태**: 
     * `● 인덱싱 완료` (초록색 닷 `#10B981`)
     * `⏳ 처리 중` (블루 닷 `#2563EB`)
     * `❌ 인덱싱 실패` (로즈 닷 `#E11D48`)
  5. **업로드 일시**: 상대 시간 표기 (예: `1시간 전`).
  6. **액션 메뉴**: `[더보기(···)]` 드롭다운 버튼:
     * ⬇️ **원본 파일 다운로드**: 저장된 원본 소스 파일 다운로드.
     * 🗑️ **소스 영구 삭제**: 소스 및 종속 청크 삭제 트리거 (영향도 확인 모달 필수 호출).

### 3.3. 우측 청크 인스펙터 패널 (Chunk Inspector Slide-out)
* 테이블에서 특정 소스 행을 클릭 시 우측에서 슬라이드아웃되는 상세 인스펙터:
  * 소스 기본 메타데이터 및 연결된 위키 문서 매핑 확인.
  * 분할된 개별 청크 리스트 (청크 #1 ~ #12) 및 캐릭터 범위(`1,420–1,890 char`).
  * 선택된 청크의 원본 코드 뷰어 (`JetBrains Mono`, 토큰 수, 캐릭터 좌표).

### 3.4. 소스 업로드 모달 (Source Ingestion Modal)
* 드래그앤드롭 영역 + 지원 파일 안내 (`.sql`, `.pdf`, `.md`, `.csv`, `.json`, `.zip` - 최대 50MB).
* 소스가 귀속될 팀 프로젝트 및 1-depth 위키 그룹 선택 셀렉터.
* 업로드 즉시 백그라운드 청킹 및 5채널 인덱싱 큐 자동 진입 (수동 조작 불필요).

### 3.5. 소스 영구 삭제 영향도 확인 모달 (Permanent Delete Warning Modal)
* **목적**: 소스 삭제는 되돌릴 수 없으므로, 위키 인용 관계 파괴를 사전 경고하여 데이터 무결성 보장.
* **필수 노출 정보**:
  * ⚠️ 경고 타이틀: `원문 소스 영구 삭제`
  * **인용 영향도 분석**: `"현재 N개 위키 문서(예: 📘 테넌트 격리 및 RLS 보안 스파인 등)가 이 소스를 인용하고 있습니다."`
  * **사후 조치 안내**: `"삭제 시 해당 위키 문서의 인라인 인용 칩은 즉시 '작성 대기 백로그(Red-link)'로 자동 전환됩니다."`
  * **액션**: `[취소]` 및 위험 스타일의 `[영구 삭제]` 버튼.

### 3.6. 소스 삭제 시 자동 재컴파일 파이프라인 (Side-effect Auto-Compilation)
* **트리거**: 소스 삭제 성공 시 시스템 부수 효과(Side-effect)로 자동 발동 (사용자 수동 버튼 클릭 불필요).
* **파이프라인 실행 단계**:
  1. `raw_sources` 및 종속 `source_chunks` 즉시 물리 삭제.
  2. 삭제된 소스를 인용 중이던 모든 `wiki_pages`의 `wiki_id`를 조회.
  3. **배치/중복 큐잉 방지 (Deduplication)**: 여러 소스를 동시 삭제하거나 동일 위키가 다수 인용되더라도 `wiki_id` 기준으로 중복 제거하여 1건의 `compile_job`만 인큐.
  4. 서비스 계정(System Worker)이 비동기 백그라운드 재컴파일 큐에 등록.
  5. **과도기 상태 처리**: 비동기 재컴파일 완료 전까지 해당 위키 문서 상단에 `JobStepper` 스타일로 **"자동 재컴파일 대기/진행 중"** 상태 배너를 노출.

## 4. 비기능 요구사항 및 디자인 원칙 (Non-Functional Requirements)

1. **100% Pure White Theme**: 웜베이지/아이보리 배제, `#FFFFFF` 순백색 캔버스 + `#E2E8F0` 헤어라인 보더.
2. **Zero Emojis**: 일체의 이모지 배제, 2.0~2.2px 두께의 단색 SVG 벡터 라인 아이콘 적용.
3. **고밀도 테이블 UX**: 불필요한 여백을 줄이고 엔지니어링 관점의 정보 스캔성을 극대화한 컴팩트 테이블 레이아웃.
4. **Zero Internal Scrollbars**: 페이지 전체 스크롤 외에 테이블 내부 이중 스크롤바 방지.
