> **문서 상태**: 확정 (Validated)  
> **기능 영역**: 위키 문서 상세 읽기 및 원문 출처 역추적 뷰어 (`/wiki/[slug]`)

## 1. 개요 및 목적 (Overview & Goals)

### 1.1. 배경
* 넥서스위키는 다양한 원본 소스(SQL DDL, 아키텍처 PDF, 슬랙 논의 내역 등)를 AI가 5채널 하이브리드 검색을 통해 합성·컴파일하여 살아있는 위키(Living Wiki)로 유지합니다.
* 사용자는 생성된 위키 문서를 읽을 때 **"이 내용이 환각(Hallucination) 없이 원본 소스 어디에 근거하고 있는가?"**를 실시간으로 역추적하고 신뢰도를 검증할 수 있어야 합니다.

### 1.2. 핵심 목적
1. **신뢰성 높은 지식 열람**: 환각 없는 고밀도 엔지니어링 위키 본문과 초록색 `[✔ 검증 완료]` 상태 제공.
2. **원클릭 출처 역추적 (Source Provenance)**: 본문 내 인라인 원문 칩(`📗 0004_rls_security_spine.sql`)을 통해 즉시 원본 코드 청크 및 라인 좌표를 대조.
3. **양방향 지식 연결망 시각화**: 이 문서가 참조하는 지식(Outbound)과 이 문서를 인용 중인 백링크(Inbound)를 SVG 노드 다이어그램으로 제공.
4. **지속적 지식 수명주기 자동 동기화**: 원본 소스 변경 또는 추가 시 백그라운드 AI 파이프라인이 위키 문서를 최신 내용으로 자동 갱신.

## 2. 사용자 페르소나 및 유저 스토리 (User Stories)

* **온보딩 엔지니어 (User A)**: "팀의 데이터베이스 RLS 보안 격리 규칙을 읽으면서, 실제 적용된 SQL 마이그레이션 파일의 라인과 RLS 정책 코드를 그 자리에서 확인하고 싶다."
* **테크 리드 / 아키텍트 (User B)**: "이 위키 문서가 다른 어떤 서비스 모듈(인증, 테넌트 마이그레이션 등)에서 인용되고 있는지 백링크 관계를 한눈에 파악하고 싶다."
* **지식 관리자 (User C)**: "원본 SQL 스키마가 업데이트되었을 때, 수동 개입 없이도 위키 문서가 자동으로 최신 상태로 유지되길 원한다."

## 3. 핵심 기능 요구사항 (Functional Requirements)

### 3.1. 문서 헤더 및 메타데이터 영역
* **브레드크럼 경로**: `엔지니어링 코어 / 데이터베이스 & RLS / 테넌트 격리 및 RLS 보안 스파인`
* **타이틀 & 즐겨찾기**: 문서 대제목 + 클릭 토글 가능한 `☆` 즐겨찾기 버튼.
* **신뢰도 및 거버넌스 뱃지**: 초록색 `[✔ 검증 완료]` 뱃지 (`#ECFDF5`, `#059669`).
* **3대 핵심 메타 통계**:
  * 📄 인용된 원문 소스: `2개 파일 (SQL, PDF)`
  * 🕒 최종 컴파일 시점: `1시간 전 (자동 동기화)`
  * 🔗 인용 중인 백링크: `2개 위키 문서`
* **우측 액션 툴바**:
  * `[+ 소스 추가]`: 새로운 원본 문서나 청크를 이 위키 문서에 연결 (프라이머리 알약 버튼).
  * `[더보기(···)]` 드롭다운 메뉴:
    1. 🔗 **문서 링크 복사 (Copy Link)**: 현재 위키 문서의 공유 URL을 클립보드에 복사.
    2. 📄 **마크다운으로 내보내기 (Export .md)**: 위키 본문 내용을 `.md` 파일로 다운로드.
    3. 📦 **위키 문서 아카이브 (Archive Wiki)**: 사용자에게는 간결하게 '위키 문서 아카이브'로 노출되며, 내부적으로는 소프트 삭제(`archived_at` 타임스탬프 설정)로 처리되어 검색 및 AI 질의(Ask) 색인에서 제외하되 DB에 보존.

### 3.2. 구조화 본문 캔버스 (Reading Canvas)
* **Pretendard & JetBrains Mono 타이포그래피**: H2/H3 섹션 구분선, 블록 인용구, 코드 블록.
* **이중 인용 인라인 칩 (Dual Citation Chips)**:
  * `📘 [위키 참조 칩]`: 클릭 시 해당 연결 위키 문서로 즉시 이동.
  * `📗 [원문 소스 칩]`: 마우스 호버 시 툴팁 미리보기, 클릭 시 하단/우측 원문 청크 대조 서랍(Drawer) 오픈.
* **Zero Bracket Syntax**: 본문에 `[[문서명]]` 브래킷 문법 노출 금지, 1px 보더의 슬릭한 알약형 칩 적용.

### 3.3. 우측 접이식 내비게이션 & 관계도 사이드바 (Collapsible Right Sidebar)
* **패널 열기/닫기 토글**:
  * 상단 액션 바의 `[목차 패널]` 버튼 및 사이드바 헤더의 `✕` 닫기 버튼을 통해 접기/펼치기 가능.
  * 패널을 닫으면 중앙 본문 독서 캔버스가 풀 위드로 확장되어 높은 몰입감의 독서 환경 제공.
* **목차 내비게이션 (Floating TOC)**: 스크롤 위치에 따라 활성 섹션 하이라이트.
* **연결된 지식 SVG 노드 다이어그램**:
  * `[인용 위키 (2)]` ➔ `[현재 위키 (Hub)]` ➔ `[참조 위키 (2)]`의 3-Column 베지어 곡선 흐름 시각화.
  * 각 노드 클릭 시 해당 문서로 내비게이션.

### 3.4. 하단 출처 대조 서랍 (Source Provenance Drawer)
* 본문 인용 칩 클릭 시 활성화되는 다크 콘솔 코드 뷰어 (`JetBrains Mono`, 원본 라인 42~58행 하이라이트, 유사도 점수 0.91 표기).

### 3.5. 비동기 자동 재컴파일 과도기 상태 처리 (JobStepper Transient State)
* 원본 소스 삭제 또는 수정으로 인해 시스템 서비스 계정이 비동기 `compile_job`을 실행 중일 때:
  * 문서 헤더 하단에 `JobStepper` 스타일의 알림 배너 노출:
    * `"⚡ 원문 소스 변경에 따라 AI가 위키 문서를 백그라운드에서 자동 재컴파일 중입니다 (3/4 단계: 인라인 인용 및 링크 재구성 중)..."`
  * 컴파일 완료 시 자동으로 최신 본문으로 리프레시되며, 삭제된 원본 소스의 인용 칩은 자연스럽게 '작성 대기 백로그'로 정리됨.

### 3.6. 웹에 공개 (Public Web Sharing) & 1:1 사이드카 발행 수명주기
* **상단 액션 버튼 (`[🔗 웹에 공개]`)**:
  * **사전 게이트 (Prerequisite)**: 오직 `verification_status == 'verified'`인 기술 검증 완료 문서만 공개 신청 가능 (`unverified`/`stale` 차단).
  * **스니펫 육안 검토 모달 (Public Review Modal)**:
    * 컴파일러가 자동 추출한 인용 스니펫(5~10줄) 목록을 모달에서 사람이 직접 육안 검토 (`[✅ 승인 / ❌ 제외]`)하여 내부 호스트명, 주석, 민감정보 유출 원천 차단.
    * 최종 승인 시 `wiki_page_publications` 사이드카 테이블에 본문 전문 + 승인 스니펫 JSONB가 불변 스냅샷으로 저장되고 `/p/[workspace_slug]/[page_slug]` 공개 URL 발급.
* **재발행 트리거 (`updated_at > published_at`)**:
  * 원문 변경 및 재컴파일로 `wiki_pages.updated_at`이 갱신되어도 외부 게스트는 기존 승인 발행본(`wiki_page_publications`)을 안전하게 열람.
  * 내부 위키 상단에 `⚠️ 공개 이후 최신 내용이 갱신되었습니다. (마지막 발행: YYYY.MM.DD) ➔ [변경사항 검토 및 재발행]` 배너 노출.
  * `[변경사항 검토 및 재발행]` 클릭 시 최초 발행과 완벽히 동일한 스니펫 육안 검토 모달을 100% 거쳐야만 갱신 완료.

## 4. 비기능 요구사항 및 디자인 원칙 (Non-Functional Requirements)

1. **100% Pure White Theme**: 웜베이지/아이보리 배제, `#FFFFFF` 순백색 캔버스 + `#E2E8F0` 헤어라인 보더.
2. **Zero Emojis**: 일체의 이모지 배제, 2.0~2.2px 두께의 단색 SVG 벡터 라인 아이콘 적용. (본 PRD의 §3에 등장하는 이모지 표기(📄🕒🔗☆📘📗 등)는 실제 UI에 쓰일 SVG 라인 아이콘의 자리표시자이며, 최종 구현에서는 이 원칙에 따라 전부 아이콘으로 대체된다.)
3. **반응형 가독성**: 본문 폭 780px~840px로 제한하여 장문 텍스트의 최적 독서 경험 제공.
4. **Zero Internal Scrollbars**: 페이지 자체 스크롤 외에 내부 중첩 스크롤바 방지.
