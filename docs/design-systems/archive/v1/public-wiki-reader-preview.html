테넌트 격리 및 Row Level Security (RLS) 아키텍처

발행일: 2026. 08. 15 • ● 검증 승인본 (Published Snapshot)

NexusDB의 멀티테넌시(Multi-Tenancy) 데이터 격리는 PostgreSQL 17의 Row Level Security (RLS)를 기반으로 작동합니다. 모든 비즈니스 데이터는 워크스페이스 단위로 완벽하게 물리적 격리되며, 권한이 없는 사용자의 접근은 데이터베이스 엔진 레벨에서 원천 차단됩니다.

1. 워크스페이스 격리 원리

모든 테이블(wiki_pages, source_chunks)은 최상위 테넌트 식별자인 workspace_id를 필수로 보유합니다 .

RLS 정책은 사용자의 세션 토큰에서 파싱된 auth.uid()가 workspace_members 테이블에 등록된 멤버인지 검사하는 is_workspace_member(workspace_id) 함수를 통해 수행됩니다 .

2. 복합 외래키(Composite FK) 전파 규칙

자식 테이블은 단순 wiki_page_id만 참조하지 않고, 항상 FOREIGN KEY (wiki_page_id, workspace_id) REFERENCES wiki_pages(id, workspace_id) 복합 외래키를 통해 테넌트 식별자를 일체형으로 실어 나릅니다. 이를 통해 서비스 계정이 RLS를 우회하더라도 다른 테넌트로 데이터가 잘못 연결되는 버그를 DB 제약 조건 차원에서 100% 방지합니다.

CREATE TABLE wiki_pages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    slug TEXT NOT NULL,
    title TEXT NOT NULL,
    UNIQUE (id, workspace_id)
);
