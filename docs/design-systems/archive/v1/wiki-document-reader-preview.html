테넌트 격리 및 RLS 보안 스파인

검증 완료 지식 그룹: 백엔드 데이터 보안 운영
📄 인용된 원문 소스 2개 파일 (SQL, PDF)
🕒 최종 컴파일 1시간 전 (자동 동기화)
🔗 인용 중인 백링크 2개 위키 문서

개요 (Summary)

넥서스위키의 모든 데이터는 멀티테넌트 환경에서 완벽히 격리되며, 의 행 단위 보안(RLS) 정책과 (id, workspace_id) 복합 외래키를 통해 물리적 데이터 유출을 원천 방지합니다.

핵심 보안 원칙: 모든 데이터 접근 및 쿼리는 애플리케이션 레벨의 WHERE 절에 의존하지 않고, 데이터베이스 커널이 직접 테넌트 경계를 강제합니다.

1. 복합 외래키(Composite FK) 전파 규칙

단일 ID 컬럼 대신 상위 테넌트의 workspace_id가 모든 하위 테이블(documents, chunks, wiki_pages)에 복합 키로 전파됩니다. 원본 DDL 정의 스크립트 에 명시된 바와 같이, 테넌트 경계를 벗어난 조인은 데이터베이스 레벨에서 즉시 차단됩니다.

-- 모든 하위 엔티티의 복합 외래키 제약조건 예시 ALTER TABLE "chunks" ADD CONSTRAINT "fk_chunks_workspace_doc" FOREIGN KEY ("document_id", "workspace_id") REFERENCES "documents"("id", "workspace_id") ON DELETE CASCADE;

2. 38개 RLS 정책 보안 검증

비동기 백그라운드 워커 풀조차 request.jwt.claim.workspace_id 컨텍스트를 강제받으며, 자동화된 테스트 스위트 38건이 통과되었습니다. 하이브리드 라우팅 및 인덱스 스캔 튜닝에 대해서는 문서를 참조하십시오.
