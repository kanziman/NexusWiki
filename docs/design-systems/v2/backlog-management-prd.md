# 넥서스위키(NexusWiki) 미완성 백로그 & 레드링크 관리 PRD

> **문서 상태**: 확정 (Validated)  
> **기능 영역**: 결손 지식(레드링크) 자동 수집, 우선순위 분석 및 원본 소스 연결 대시보드 (`/backlog`)  
> **연계 프로토타입 시안**: [`docs/design-systems/backlog-management-preview.html`](file:///Users/zorba/projects/NexusWiki/docs/design-systems/backlog-management-preview.html)

## 1. 개요 및 목적 (Overview & Goals)

### 1.1. 배경
* 넥서스위키는 엔지니어링 위키를 자동 컴파일하는 과정에서 원본 소스가 부족하여 작성을 완료하지 못한 결손 지식을 **'레드링크(Red-link, `⭕ 작성 대기 백로그`)'** 형태로 본문에 남겨둡니다.
* 또한, 특정 원본 소스가 삭제되었을 때 해당 소스를 인용하던 위키 부분 역시 자동으로 백로그 상태로 전이됩니다.
* 사용자는 **어떤 핵심 지식이 누락되어 있고, 몇 개의 위키 문서가 해당 백로그를 참조하고 있으며, 어떤 소스 자료를 추가해야 백로그를 해소할 수 있는지**를 체계적으로 관리할 수 있어야 합니다.

### 1.2. 핵심 목적
1. **결손 지식(레드링크) 자동 집계**: 위키 컴파일 중 감지된 미작성 링크 및 소스 삭제로 인한 결손 항목을 실시간 집계.
2. **영향도 기반 우선순위 산정**: 많은 위키 문서에서 인용하고 있는 백로그 항목(예: `캐시 계층 전략`, `인증 세션 관리`)을 상단에 정렬하여 팀의 지식 작성 우선순위 가이드.
3. **원클릭 소스 매핑 & 자동 컴파일 해소 (Source Attachment & Auto-Resolution)**:
   * 백로그 상세 인스펙터에서 엔지니어가 관련 소스 파일(SQL, PDF, Markdown, CSV 등)을 업로드하면,
   * 시스템이 즉시 백그라운드에서 5채널 인덱싱 및 위키 자동 컴파일 작업을 실행하여 해당 백로그를 `[✔ 해결 완료]` 상태로 전환.
4. **전체 지식 커버리지 지표 제공**: 현재 워크스페이스 내 전체 지식 대비 컴파일 완료된 위키 비율(%)을 가시화하여 지식 완성도 추적.

## 2. 사용자 페르소나 및 유저 스토리 (User Stories)

* **테크 리드 / 아키텍트 (User A)**: "팀 위키 중 가장 많은 문서에서 참조하고 있지만 아직 원본 자료가 없는 '캐시 계층 전략' 백로그를 확인하고, 인프라 팀에 필요한 설계서 작성을 요청하고 싶다."
* **도메인 엔지니어 (User B)**: "내가 담당하는 모듈의 결손 백로그에 방금 작성한 DB 마이그레이션 SQL 파일을 업로드하여, 위키 문서가 자동으로 완성되고 백로그가 해소되는 것을 확인하고 싶다."
* **온보딩 신규 입사자 (User C)**: "문서를 읽다가 `⭕ 작성 대기` 칩을 마주쳤을 때, 백로그 대시보드로 이동하여 해당 지식이 언제 어떤 소스로 보강될 예정인지 상태를 파악하고 싶다."

## 3. 핵심 기능 요구사항 (Functional Requirements)

### 3.1. 상단 헤더 및 백로그 메타 통계 (Header & Stats)
* **브레드크럼 경로**: `엔지니어링 코어 / 작성 대기 백로그`
* **타이틀 & 설명**: `미완성 지식 백로그 & 레드링크 관리` + 1줄 요약.
* **3대 핵심 메타 통계** (과거 스냅샷/시계열 테이블 없이 현재 DB 상태 집계만 표시):
  * ⭕ **미해결 백로그**: `6건` (해결 대기 중인 결손 지식)
  * 🔗 **영향받는 위키**: `14개 문서` (백로그를 인용 중인 컴파일 위키)
  * 📊 **지식 완성 커버리지**: `88.4%` (전체 위키 대비 결손 없는 완성 위키 비율)
* **우측 액션 버튼**: `[+ 수동 백로그 등록]` (필요 시 팀이 사전에 작성할 지식 토픽 예약).

### 3.2. 백로그 필터 탭 & 고밀도 목록 테이블 (Backlog Table)
* **우선순위/상태 필터 탭**:
  * `전체 (6)`, `높은 인용 빈도 (3)`, `신규 감지 (2)`, `소스 삭제 결손 (1)`.
* **고밀도 데이터 테이블 컬럼 구성**:
  1. **백로그 명칭 (Topic)**: 결손 지식 타이틀(예: `캐시 계층 전략`, `글로벌 결제 정산 게이트웨이`).
  2. **인용 중인 위키 문서 (Referenced Wikis)**: 해당 백로그를 참조하고 있는 위키 알약 칩(`📘 테넌트 격리 및 RLS...` 외 N개).
  3. **인용 빈도 (Impact Score)**: 백로그를 필요로 하는 위키 문서 수(예: `5개 문서에서 참조 중`).
  4. **감지 경로 (Origin)**: 최초 발생 원인 (`AI 컴파일 결손`, `소스 삭제 결손`).
  5. **감지 일시**: 상대 시간 표기 (예: `2시간 전`).
  6. **액션**: `[+ 소스 연결]` 프라이머리 알약 버튼.

### 3.3. 우측 백로그 해결 인스펙터 패널 (Resolution Inspector Slide-out)
* 테이블 행 또는 `[+ 소스 연결]` 클릭 시 우측에서 슬라이드아웃되는 해결 전용 패널:
  1. **백로그 상세 정보**: 토픽명, 최초 발생 원인(컴파일 중 미완성 / 소스 삭제 부수효과).
  2. **인용 문맥 발췌문 (Citation Context)**: 해당 백로그가 인용된 실제 위키 본문 속의 문장 발췌문 노출 (컴파일러 LLM이 본문에 남긴 실제 원문 컨텍스트).
  3. **인용 중인 위키 목록**: 영향받는 위키 문서 리스트.
  4. **원문 소스 드래그앤드롭 인제스천 영역**:
     * 소스 파일(.sql, .pdf, .md, .csv 등) 업로드 시 즉시 백그라운드 5채널 인덱싱 및 위키 자동 컴파일 작업 큐잉.
     * 업로드 완료 시 백로그가 즉시 목록에서 해결 처리되고 상단 통계가 실시간 갱신됨.

## 4. 비기능 요구사항 및 디자인 원칙 (Non-Functional Requirements)

1. **100% Pure Crisp White Mode**: 웜베이지/아이보리 배제, 순백색(`#FFFFFF`) 캔버스 + `#F8FAFC` 슬레이트 + `#E2E8F0` 헤어라인 보더.
2. **Zero Emojis**: 일체의 이모티콘 배제, 2.0~2.2px 두께의 단색 SVG 벡터 라인 아이콘만 적용.
3. **Zero Bracket Syntax**: 본문 및 칩에 `[[문서명]]` 브래킷 노출 금지, 슬릭한 로즈/레드 틴트 알약 칩(`⭕ [캐시 계층 전략]`) 적용.
4. **실시간 인터랙티브 피드백**: 소스 업로드 시 토스트 알림 및 자동 상태 전이 제공.
