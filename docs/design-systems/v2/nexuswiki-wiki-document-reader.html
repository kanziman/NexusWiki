개요

넥서스위키의 테넌트 격리는 애플리케이션의 관례가 아니라 PostgreSQL 엔진이 직접 강제하는 정책입니다. 모든 요청은 세션에 설정된 tenant_id를 기준으로 분리되며, 정책을 빠뜨린 쿼리도 다른 테넌트의 데이터를 반환할 수 없습니다.

이 문서는 운영 중인 RLS 정책과 스키마 제약을 하나의 보안 경계로 설명합니다.

1. 복합 외래키 전파 규칙

9개 핵심 테이블은 테넌트 키를 포함한 복합 외래키를 사용합니다. 테넌트 범위를 넘는 연결은 데이터 모델 단계에서 거부되며, 관련 개념은 에서 확인할 수 있습니다.

정책 정의는 의 42–58행을 기준으로 검증됩니다. 이 원문은 현재 문서의 핵심 주장과 직접 연결되어 있습니다.

2. RLS 정책 검증

일반 서비스 연결은 app.tenant_id가 비어 있을 때 어떠한 행도 조회하지 못합니다. 서비스 역할에는 별도 연결 경로와 감사 로그가 요구됩니다.

운영 원칙

원문 소스가 변경되면 재컴파일 작업이 문서의 인용 관계와 신뢰도를 다시 계산합니다. 변경 이력은 결과 문서와 함께 보존됩니다.
