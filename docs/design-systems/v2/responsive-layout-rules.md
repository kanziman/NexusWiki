# NexusWiki 반응형 레이아웃 규칙

## 목적

데이터가 많은 NexusWiki 화면에서 작은 화면을 단순 축소하지 않고, 읽기 순서와 조작성을 유지한다.

## 화면 구간

| 구간 | 폭 | 기본 원칙 |
| --- | --- | --- |
| 데스크톱 | 1600px 이상 | 내비게이션, 콘텐츠, 인스펙터를 동시에 표시한다. |
| 컴팩트 데스크톱 | 901–1599px | 사이드바와 상시 인스펙터를 접고, 콘텐츠 폭을 우선한다. |
| 태블릿 | 641–900px | 데이터 표를 카드 목록으로 바꾸고, 통계는 가로 3열로 유지한다. |
| 모바일 | 640px 이하 | 한 손으로 읽을 핵심 정보만 남기고, 통계와 카드 메타데이터를 세로 흐름으로 둔다. |

## 데이터 표 전환 규칙

### 데스크톱

- 관계가 있는 여러 항목을 한눈에 비교해야 할 때만 HTML 테이블을 사용한다.
- 열을 숨기는 방식으로 좁은 화면을 해결하지 않는다.
- 오른쪽 인스펙터가 열려 있을 때에도 표 본문을 가리지 않게 별도 열 또는 오버레이 상태를 명확히 선택한다.

### 태블릿과 모바일

- `table-layout: fixed`와 `<colgroup>`에 의존한 채 열을 감추지 않는다.
- 900px 이하에서는 각 레코드를 카드로 전환한다. 카드 순서는 소스 파일 → 연결 문서 → 청크 정보 → 파이프라인 상태 → 추가 작업이다.
- 640px 이하에서는 연결 문서처럼 보조적인 정보는 기본 목록에서 감추고, 행 선택 후 상세 패널에서 확인할 수 있게 한다.
- 삭제·더보기 버튼은 카드의 오른쪽 상단에 고정하고, 최소 44px 터치 영역을 확보한다.
- 행 선택으로 열리는 인스펙터는 독립 레이어로 표시한다. 열려 있을 때 배경 스크롤과 클릭을 차단하며, 닫기 버튼과 Esc 키를 제공한다.

## 정보 우선순위

1. 파일 형식, 파일명, 파일 요약
2. 처리 상태와 청크 수
3. 연결된 위키 문서
4. 업로드 시점과 삭제 같은 보조 작업

작은 화면에서 1–2번 정보는 절대 생략하거나 한 글자 단위로 줄바꿈하지 않는다. 3–4번은 상세 패널 또는 메뉴로 이동할 수 있다.

## 구현 금지 사항

- 숨긴 `td`만 남기고 `<colgroup>`의 폭을 0으로 덮어쓰지 않는다.
- 고정 폭 테이블에서 텍스트가 글자 단위로 꺾이도록 방치하지 않는다.
- 데스크톱, 태블릿, 모바일에 같은 열 비율을 재사용하지 않는다.
- 모바일에서 가로 스크롤을 숨겨 문제를 감추지 않는다.

## 완료 전 확인 목록

- [ ] 1600px, 1280px, 768px, 375px에서 핵심 정보가 겹치거나 잘리지 않는다.
- [ ] 768px 이하에서 데이터 행은 카드 흐름이며 표 헤더에 의존하지 않는다.
- [ ] 375px에서 파일명, 청크 수, 상태가 자연스럽게 읽힌다.
- [ ] 필터는 가로 스크롤될 수 있으나 페이지 전체는 가로로 넘치지 않는다.
- [ ] 상세 패널을 열고 닫은 뒤에도 배경 스크롤과 키보드 상태가 정상이다.
- [ ] 선택, 호버, 포커스 상태의 텍스트 대비가 기본 상태보다 낮아지지 않는다.
