1. Background (배경 지식)

초심자를 위한 시스템 개요: Living Wiki SaaS란?

NexusWiki는 단순한 문서 저장소가 아닙니다. 사용자가 업로드한 수많은 PDF, 텍스트, 아티클 등의 원문 소스(Raw Sources)를 수집하여, AI(LLM)가 이를 지속적으로 요약·정리·연결하는 '살아있는 지식 위키(Living Wiki)' SaaS입니다.

이러한 지식 위키 시스템을 구축할 때 가장 중요한 엔지니어링 과제는 두 가지입니다:

  1. 이중 인용(Dual Citation): AI가 답변을 생성할 때, 자신이 만든 "위키 문서"뿐만 아니라 사용자가 처음 올렸던 "원문 청크"의 위치(문단, 문자 좌표)까지 정확히 가리켜야 합니다.
  2. 멀티테넌시(Multi-tenancy) 격리: 여러 팀이 하나의 데이터베이스를 공유하므로, 팀 A의 직원이 절대로 팀 B의 지식이나 원문 청크를 조회하지 못하도록 DB 수준에서 강력히 차단해야 합니다.

NexusWiki가 직면한 3가지 핵심 기술 한계와 해결책

① Neo4j 그래프 DB의 배제와 Postgres `wiki_links` 선택

위키 문서 간의 백링크(Backlink) 구조를 표현하기 위해 당초 Graph DB(Neo4j) 도입이 검토되었습니다. 하지만 분석 결과 Neo4j 기본 티어에는 GDS 그래프 알고리즘이 포함되어 있지 않고, 위키 문서 수가 $10^3 \sim 10^4$ 규모일 때는 그래프 순회 이점이 크지 않았습니다. 무엇보다 팀 모드에서 Neo4j는 **행 단위 보안(RLS)을 지원하지 않아** 애플리케이션 코드가 테넌트 격리를 전담해야 하는 보안 위험이 있었습니다. 따라서 Postgres 테이블(`wiki_links`)과 **재귀적 공통 테이블 식(Recursive CTE)**을 활용하여 Graph DB 없이 완벽한 N-hop 문서 순회를 구현했습니다.

② 한국어 전문 검색(FTS)과 Bigram 앱 레이어 토크나이저

PostgreSQL의 기본 FTS 함수(`to_tsvector`)는 공백 및 띄어쓰기를 기준으로 텍스트를 나눕니다. 영어에서는 잘 동작하지만, 조사와 접미사가 결합하는 교착어인 한국어에서는 `"검색기능을"`이라는 단어를 통째로 인덱싱하여 사용자가 `"검색"`으로 찾았을 때 검색에 실패합니다. Supabase 클라우드는 커스텀 형태소 분석기(pg_bigm, pgroonga)를 제공하지 않으므로, 백엔드 앱에서 문자열을 **2글자씩 슬라이딩 윈도우로 쪼개는 Bigram 토크나이저**를 거쳐 `tsvector`에 저장하는 방식을 채택했습니다.

📌 설계 근거: 왜 Bigram을 DB 생성 컬럼이 아닌 앱에서 채우는가?
Postgres의 생성 컬럼(`GENERATED ALWAYS AS ... STORED`)은 DB 내부 SQL 함수만 호출할 수 있습니다. DB 내부 파서는 한국어를 공백 단위로만 쪼개므로, 백엔드(FastAPI)에서 미리 2글자 음절 단위로 잘라낸 Bigram 문자열을 생성한 후 `search_tsv` 일반 컬럼에 저장해야만 한글 키워드 부분 일치 검색이 보장됩니다.

2. Intuition (직관적 이해와 핵심 설계)

5-Way 하이브리드 검색 채널

NexusWiki는 사용자의 질문에 대해 단 한 가지 검색 방식만 사용하지 않습니다. 오탐을 줄이고 환각(Hallucination) 없는 인용을 제공하기 위해 **5가지 서로 다른 채널**의 결과를 결합합니다.

NexusWiki 5-Way Hybrid Search Architecture
1
위키 벡터 유사도
wiki_embeddings (HNSW)
의미 기반 검색. 질문과 가장 유사한 맥락의 위키 요약 청크를 탐색합니다.
2
원문 청크 벡터 유사도
source_chunks (HNSW)
원문 세부 인용용. 사용자가 업로드한 원본 문서 문단 검색.
3
위키 Bigram 어휘 검색
wiki_pages (GIN tsvector)
고유명사, 프로젝트명, 고유 신조어 정확 매칭.
4
원문 Bigram 어휘 검색
source_chunks (GIN tsvector)
원문에 포함된 전문 용어 키워드 직치 검색.
5
N-Hop 그래프 연관 문서 탐색
wiki_links (Recursive CTE)
매칭된 위키 문서에서 출발하여 [[wiki:target_slug]] 링크로 연결된 주변 지식 노드를 순회 확장합니다.

Bigram 2글자 음절 분할 작동 방식

"한국어 검색기능"이라는 원문이 입력되었을 때 백엔드 앱과 DB가 이를 가공하는 흐름입니다:

원문 입력: "한국어 검색기능"
↓ 백엔드 파이썬 토크나이저 (2글자 슬라이딩)
Bigram 토큰 추출: "한국 국어 어검 검색 색기 기능"
↓ DB INSERT (`to_tsvector('simple', ...)` 적용)
search_tsv 컬럼에 GIN 인덱스 색인 완료
↓ 검색 실행 (`phraseto_tsquery('simple', '검색')`)
키워드 '검색' 토큰이 정확하게 매칭되어 결과 반환!

RLS 무한 재귀(Infinite Recursion) 차단 매커니즘

Supabase에서 멀티테넌트 권한을 검증할 때, `workspace_members` 테이블에 대한 RLS 정책 안에서 "이 사용자가 멤버인가?" 확인하기 위해 `workspace_members`를 다시 `SELECT`하면 Postgres는 **무한 재귀 에러(`42P17`)**로 쿼리를 중단시킵니다.

⚠️ SECURITY DEFINER 헬퍼 함수의 역할
NexusWiki는 is_workspace_member(ws_id) 함수를 SECURITY DEFINER로 생성하여, 쿼리가 실행될 때 소유자(postgres) 권한으로 전환되도록 합니다. 이를 통해 RLS 평가 고리를 끊어내고 $O(1)$ 속도로 테넌트 권한을 검증합니다.

3. Code Walkthrough (마이그레이션 스키마 분석)

0001: 코어 스키마 & RLS 선행 차단 (0001_core_schema.sql)

테이블을 만들자마자 정책(Policy)이 없는 상태로 RLS를 먼저 활성화합니다. 정책이 0개인 RLS는 '전면 거부(Deny-by-default)'이므로, 스키마가 마이그레이션되는 중간 과정에 데이터가 외부로 노출되는 보완 창을 완전히 제거합니다. 

-- 1. 워크스페이스 테이블 (owner_id 포함)
create table public.workspaces (
  id         uuid primary key default gen_random_uuid(),
  name       text not null check (char_length(btrim(name)) between 1 and 100),
  kind       text not null default 'team' check (kind in ('personal', 'team')),
  owner_id   uuid not null references auth.users (id) on delete restrict,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- 2. 워크스페이스 생성 시 소유자를 자동으로 owner 멤버에 등록하는 트리거
create or replace function public.add_owner_as_member()
returns trigger language plpgsql security definer set search_path = public as $$
begin
  insert into public.workspace_members (workspace_id, user_id, role)
  values (new.id, new.owner_id, 'owner')
  on conflict (workspace_id, user_id) do update set role = 'owner';
  return new;
end;
$$;

0002: 검색 스키마 & pgvector HNSW 인덱스 (0002_search_schema.sql)

원문 청크(`source_chunks`), 위키 임베딩(`wiki_embeddings`), 백링크 그래프(`wiki_links`) 스키마를 정의합니다. 

-- pgvector 확장 켜기
create extension if not exists vector with schema extensions;

-- 원문 청크 테이블 (원문 + 위키 이중 인용의 근거)
create table public.source_chunks (
  id            uuid primary key default gen_random_uuid(),
  raw_source_id uuid not null,
  workspace_id  uuid not null,
  chunk_index   int not null check (chunk_index >= 0),
  content       text not null,
  char_start    int not null check (char_start >= 0),
  char_end      int not null,
  embedding     extensions.vector(1536), -- OpenAI text-embedding-3-small
  search_tsv    tsvector,                -- 앱이 입력하는 Bigram tsvector
  tsv_tokenizer_version smallint,
  created_at    timestamptz not null default now(),
  
  constraint source_chunks_char_range_check check (char_end > char_start),
  constraint source_chunks_raw_source_fkey
    foreign key (raw_source_id, workspace_id)
    references public.raw_sources (id, workspace_id) on delete cascade
);

-- pgvector HNSW 코사인 유사도 인덱스 생성
create index source_chunks_embedding_idx
  on public.source_chunks using hnsw (embedding extensions.vector_cosine_ops);

-- Bigram 어휘 검색 GIN 인덱스 생성
create index source_chunks_search_tsv_idx
  on public.source_chunks using gin (search_tsv);

0003: 비동기 작업 큐 (0003_jobs.sql)

외부 인프라(Redis/RabbitMQ) 없이 Postgres 단일 DB 안에서 안전한 워커 폴링 큐를 구축합니다. 

-- FOR UPDATE SKIP LOCKED 기반 분산 작업 획득 함수
create or replace function public.dequeue_job(worker_id text)
returns setof public.jobs language plpgsql as $$
begin
  return query
  update public.jobs
  set status = 'running',
      locked_at = now(),
      locked_by = worker_id,
      attempts = attempts + 1,
      updated_at = now()
  where id = (
    select id from public.jobs
    where status = 'queued'
    order by created_at asc
    for update skip locked
    limit 1
  )
  returning *;
end;
$$;

0004: 테넌트 격리 RLS 정책 (0004_rls_policies.sql)

`SECURITY DEFINER` 헬퍼 함수를 사용하여 재귀 없이 사용자의 워크스페이스 역할(`owner` > `editor` > `viewer`)에 맞게 조회를 제한합니다. 

-- SECURITY DEFINER로 무한 재귀를 막는 헬퍼 함수
create or replace function public.is_workspace_member(ws_id uuid)
returns boolean language sql security definer stable set search_path = public as $$
  select exists (
    select 1 from public.workspace_members m
    where m.workspace_id = ws_id
      and m.user_id = (select auth.uid())
  );
$$;

-- source_chunks 테이블 RLS 정책: 워크스페이스 멤버만 SELECT 가능
create policy source_chunks_select_policy on public.source_chunks
  for select to authenticated
  using (public.is_workspace_member(workspace_id));
