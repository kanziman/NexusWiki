# 로컬 평가 실행과 누적 비교

공개 회귀 분석 화면의 실행 기능은 로컬 개발 환경에서만 활성화한다. 운영 빌드의
`/api/local-evaluation`은 항상 403을 반환한다. 개발 서버도 반드시 루프백에 바인딩한다.

## 시작

저장소 루트에서 실행기를 시작한다.

```bash
.venv/bin/python scripts/local_evaluation_server.py
```

별도 터미널의 `apps/dashboard`에서 개발 서버를 시작한다.

```bash
LOCAL_EVALUATION_ENABLED=1 pnpm dev --hostname 127.0.0.1 --port 54410
```

`http://127.0.0.1:54410/showcase/regression`의 로컬 평가 실행에서 이름을 입력하고 실행한다.
초기 기준은 보존된 합성 HTTP 1이다. 완료 결과는 로컬 누적 실행에 추가되고 지정된 기준과
자동 비교된다. 기준 지정도 새로고침과 실행기 재시작 이후 유지된다.

## 실행 종류

- 저장 답변 재채점: 현재 기대 표현과 채점 코드로 보존된 답변을 다시 검사한다. 모델을 호출하지
  않는다. 표시되는 모델 비용·토큰·지연은 원본 기록이며 재채점의 새 비용이나 속도가 아니다.
- 새 답변 생성: 로컬 재생 API·워커를 먼저 준비하고 실행기에 아래 설정을 추가한다.

```bash
.venv/bin/python scripts/local_evaluation_server.py \
  --state .worktrees/reliability-evidence-20261108/state.json \
  --api-url http://127.0.0.1:8031
```

API·워커 준비 방법은 `scripts/ask_replay_serve.sh`와 `docs/ops/ask-sample-replay.md`를 따른다.
API 건강 확인이 성공해야 화면에서 유료 실행을 선택할 수 있다. 유료 실행 준비 상태가
공급자 크레딧이나 워크스페이스 예산의 충분함까지 보장하지는 않는다.

실행별 목표 상한은 $0.20~$2.00, 문항 수는 1~30이다. 다음 질문 전에 최소 $0.20 또는
관측한 최대 문항 비용으로 남은 금액을 확인한다. 공급자 비용 보고 지연·추정 오차가 있어
절대 지출 보장은 아니다. 비용 미기록 문항은 즉시 중단하며 기존 워크스페이스 예산도 적용된다.
운영 예산·모델 설정을 자동 변경하지 않는다.

## 보존과 실패 처리

`.worktrees/evaluation-dashboard/`에 실행·부분 원본·진행 상태·기준 지정을 저장한다.
채점 코드를 수정했다면 실행기를 재시작한 뒤 새 평가를 요청한다. 실행 중인 Python 프로세스는
기동할 때 로드한 채점 함수를 사용한다.
토큰 파일과 원본은 외부로 공개하거나 커밋하지 않는다. 프록시는 토큰을 서버에서만 읽는다.
유료 실행은 문항마다 답변을 체크포인트한다. 중단·부분 실행·비용 미기록은 정상 완료 후보로
추가하지 않는다. 실행기를 재시작하면 진행 중이던 작업은 중단됨으로 표시하고 부분 답변을 남긴다.

동시 실행은 한 건으로 제한한다. 실행기 종료는 해당 터미널에서 Ctrl-C로 한다.
이 기능은 정기 평가·운영 로그 자동 수집이나 CI/CD 배포 차단을 추가하지 않는다.

## 골든셋과 AI 심사

사람이 직접 검토할 때는 `http://127.0.0.1:54410/showcase/review`를 연다. 문항·정답 기준 검토와
AI 답변 채점을 별도 모드로 제공하며 원문과 저장 폼을 바로 보여 준다. 작성 중에는 다른 문항으로
이동하지 못하도록 하고 저장 실패 시 입력을 유지한다. 기존 작업대의 ‘검토 전용 페이지 열기’로도
이동할 수 있으며 두 화면은 같은 로컬 판정 저장소를 사용한다. 유료 심사 실행은 기존 작업대에서만 한다.

계약: `openspec/specs/golden-answer-evaluation/spec.md` · GitHub #266.

대시보드 아래의 **골든셋과 AI 심사**를 펼친다. 처음에는 30문항 모두 사람 미검토인 후보다.
질문·기대 사실·허용 표현·정답 원문 구간을 확인하고 **골든셋 후보 검토 저장**을 직접 제출해야
사람 검토 완료로 집계한다. 개발 중 에이전트가 구성하거나 자동 검사한 사실은 사람 확인이 아니다.

답변 출처는 **검증용 합성 예시**와 **저장된 실제 모델 답변**으로 구분한다. 예시에는 올바른 답변뿐 아니라
위조 표식, 엉뚱한 출처, 인용 누락도 포함하며 모델의 실제 성적으로 사용하지 않는다. 기존 저장 답변은 질문이
후보와 정확히 일치할 때만 연결한다. 모호함을 수정한 일반 입고 질문에 과거 반품 답변을 자동 연결하지 않는다.
기존 기록에 생성 당시 인용 근거 맵이 없으면 원문을 대신 끼워 넣지 않고 인용 의미 지표를 심사 불가로 표시한다.

### 유료 심사 준비

로컬 실행기를 시작하는 환경에 `OPENROUTER_API_KEY`와 `EVALUATION_JUDGE_MODELS`를 지정한다.
가격은 실제 실행할 모델의 공급자 가격을 확인해 설정한다. 아래는 설정 모양이며 가격·모델을 채우기 전에는
실행 가능한 설정이 아니다. 키는 브라우저 입력이나 공개 JSON에 넣지 않는다.

```text
EVALUATION_JUDGE_MODELS={"provider/model":{"input_usd_per_million":"확인한 입력 단가","output_usd_per_million":"확인한 출력 단가","max_output_tokens":2000}}
```

프로젝트 환경 파일로 로드할 때는 저장소 루트에서 다음과 같이 시작할 수 있다.

```bash
uv run --env-file .env.local python scripts/local_evaluation_server.py
```

서버에 허용 모델·양의 단가·키가 준비돼야 심사 모델을 선택할 수 있다. 화면에서 모델·심사 예산·답변 범위를
지정하고 **선택한 저장 답변 심사 · 유료**를 눌렀을 때만 모델을 호출한다. 새 답변 생성과 별개로 저장 답변을
채점하는 비용이다. 조회·원문 펼치기·사람 검토 저장에는 모델 호출이 없다. 이 기능을 구현하거나 테스트하는
과정에서 실제 유료 심사를 자동 실행하지 않는다.

다음 호출 전에 입력 크기·출력 상한과 설정 단가로 비용을 보수 추정한다. 한 번에 한 작업만 실행하고,
비용 미관측·공급자 오류·형식 오류에는 자동 재시도하지 않는다. 잘못된 심사 응답에도 이미 발생한 비용은
보존한다. 공급자 보고 지연·단가 설정 오차가 있으므로 절대 지출 상한을 보장하지 않는다.

### 사람과 심사기 대조

코드의 인용 표식 유효성과 LLM의 사실 일치·인용 정확도·주요 주장 인용 충실도·거절 적절성을 분리한다.
표식이 유효해도 주장을 뒷받침하지 않으면 인용 정확도는 실패할 수 있다. 근거가 필요 없는 거절 등은
적용 안 됨으로 분리하며, 의미가 애매하면 검토 필요로 남긴다.

**이 답변의 사람 판정 남기기**에서 네 지표와 이유를 직접 제출한다. 후보 자체의 검토와는 별개다.
사람 판정과 AI 심사에 동일 입력·동일 지표의 명시적 통과/실패가 모두 있을 때만 일치도에 반영한다.
분모 0은 미측정이다. 동일 입력의 반복 기록은 중복 집계하지 않으며, 예시와 실측 출처도 합치지 않는다.
오통과는 사람 실패/AI 통과, 오실패는 사람 통과/AI 실패다. 이전 입력의 판정은 새 질문·답변·근거에 재사용하지 않는다.

입력과 심사 버전·지문, 체크포인트와 검토 개정 이력은 `.worktrees/evaluation-dashboard/judge/`에 보존된다.
검토 중 다른 제출이 저장되면 충돌을 표시하므로 새로 확인한 뒤 제출한다. 사람 이름을 인증하는 기능은 아니며
이 컴퓨터의 사용자 제출 기록이다. 실제 사람 라벨과 실제 유료 심사 없이 심사기의 정확도가 검증됐다고 주장하지 않는다.
