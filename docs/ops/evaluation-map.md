# 평가 지도와 적용 원장

NexusWiki의 AI 품질을 어디까지 재고 있는지(지도), 그리고 어떤 평가 기법을 실제로 적용해 무엇이 바뀌었는지(원장)를 한 곳에서 본다. 세부 수치와 방법은 출처 문서에 있고, 이 문서는 지도와 원장만 둔다.

> 초안 (2026-11-08). ⚠️ 아래 Ask 수치는 전부 **합성 샘플**(가상 물류 회사 문서 8건, 고정 질문 30개)에서 나왔다. 운영 트래픽 성과로 인용하면 안 된다.

## 1. 무엇이 틀리면 가장 위험한가

이 제품의 약속은 "답을 원문 청크와 위키 페이지 양쪽으로 되짚을 수 있다"이다. 그래서 위험 순서는 다음과 같다.

1. **근거 없는 답**: 인용이 없거나, 인용이 위조됐거나, 원문과 위키 중 한쪽만 가리키는 답
2. **다른 테넌트의 데이터가 섞인 답**: 격리 실패
3. **모를 때 지어낸 답**: 거절해야 할 질문에 답함
4. 틀린 사실: 근거는 달렸지만 내용이 틀림

정답성보다 근거성과 격리가 앞에 온다. 이중 Citation이 무너지면 제품이 "또 하나의 RAG 챗봇"이 되기 때문이다.

"잰 것"도 합성 샘플 한 번의 값이다. 같은 코드로 다시 돌리면 실패 문항이 바뀔 수 있다.

**검색 칸에 대해**: 현재 코드로 재생 29문항(답할 수 있는 질문)을 검색만 따로 채점했다. 모든 질문에서 상위 6개가 위키, 7~8위가 원문이고 채널 장애는 없었다. 재수집마다 위키가 다르게 컴파일되어(11쪽 → 13쪽) hit@1이 19/29와 16/29로 달랐으므로, 비교는 같은 수집 결과 위에서 한다. 위키가 13쪽뿐이라 위키 적중은 우연으로도 높게 나오므로 순위 지표(hit@1)를 본다. 이전에 기록된 recall 0.222는 2026-08 대규모(5만 벡터) 스트레스 측정으로, HNSW 규모 동작을 잰 다른 질문이다. 대규모 워크스페이스의 검색 품질은 여전히 현재 코드로 재지 않았다.

## 3. 숫자를 읽을 때

이 절의 규칙은 문항 수와 통과/실패 구조에만 달려 있어 도메인과 무관하다.

- **30문항에서 한 문항은 3.3%p다.** 27/30과 28/30의 차이는 판정 규칙 수정(#224)에서 나왔고, 성능이 좋아진 것이 아니다.
- **95% 구간이 넓다.** 28/30의 구간은 78.7~98.2%다. "93%"라고만 쓰면 안 된다.
- **판정 규칙에 버전이 있다.** 이중 인용은 답변 단위로 센다(위키 1개 이상, 원문 1개 이상). 첫 재생은 이 필드를 기록하기 전이라 q26이 더 엄격한 문장 기준으로 판정됐다.
- **정답원이 없다.** 사용자가 올린 임의 문서가 대상이라 공식 정답 API로 숫자를 대조할 수 없다. 정답성은 질문마다 사람이 적은 기대 사실의 포함 여부로만 잰다.

## 4. 이미 있는 관문

| 관문 | 무엇을 막나 | 무엇을 못 막나 |
| --- | --- | --- |
| CI: SEC-03 · SEC-05 | `service_role` 키의 사용자 경로 사용 · 번들 비밀 유출 | 답변 품질 |
| CI: COMP-06 | 검색 함수 계약 위반 | 검색 품질 하락 |
| CI: 루트 pytest | 판정 함수(`verdict`)와 집계의 회귀 | 실제 LLM 답변의 회귀 |
| 런타임: 인용 계약 (`enforce`) | 위반 답을 수리하거나 결정론적 Fallback으로 끝냄 | 근거는 맞지만 내용이 틀린 답 |
| Control Room 품질 탭 | 운영 인용 위반 · 수리 · Fallback 집계를 보여 줌 | 정답 여부 (본문을 보지 않는다) |

**답변 품질의 회귀 관문은 없다.** 프롬프트나 정책을 바꾼 PR이 30문항 중 어떤 문항을 떨어뜨려도 CI는 통과한다.

## 5. 적용 원장

평가 기법을 실제로 적용한 기록이다. 한 줄은 하나의 적용이며, 증거는 열어 볼 수 있는 PR이나 기록이어야 한다. "측정이 바꾼 것"이 없는 적용은 쓰지 않는다. 기법 이름 옆 번호는 참고한 강의 편이다.

## 6. 다음 순서

각 작업은 원장 한 줄과 측정 기록을 남기도록 설계한다.

1. ~~검색 평가 (32편)~~: 완료(적용 원장 3행). 남은 것: 위키가 상위를 차지하는 원인(#195 가설) 확인, 대규모 워크스페이스 재측정.
2. **통계 (31편)**: 성적표 화면과 기록에 통과율의 95% 구간을 표시한다.
3. **오류 분석 (26편)**: 실패 문항을 처음 틀어진 단계(검색 · 근거 · 작성 · 채점기)별로 묶어 센다.
4. **모델 비교 (22 · 24편)**: 같은 날, 같은 시험지로 모델 2~3개를 비교한다. 통과율보다 흔들리지 않는 비용 · 지연 · 위조 앵커를 먼저 읽는다.
5. **회귀 관문 (33편)**: 저장된 재생 출력을 PR마다 지금 코드로 다시 채점하고 문항 단위로 막는다. 모델 호출이 없다.
   - 결정 필요: 지금은 "합성 수치라 결과 파일을 커밋하지 않는다". 관문에는 저장된 출력이 저장소에 있어야 한다.
   - 회귀 세트는 여러 번 돌려 모두 통과한 문항만 넣는다.
6. **개선 한 바퀴 (34편)**: 오류 분석의 가장 큰 칸 하나를 고치고, 영향받은 문항과 회귀 세트로 확인한 뒤 관문을 통과시킨다.

그 뒤에 남는 칸: 거절 표본 늘리기, 사람 라벨과 판사(29 · 30편), 위키 컴파일 품질.

## 7. 출시 기준

아직 정하지 않았다. 기준은 숫자를 보기 전에 정한다. 정할 항목:

- 위조 앵커 허용 건수
- 답변 단위 이중 인용 통과율 하한
- 거절 통과율 하한(거절 표본을 늘린 뒤)
- 문항당 비용 · p95 지연 상한
- 회귀 세트 문항 하락 허용 개수
