## 방법

측정 주체는 개발자 머신이 아닌, `asia-southeast1` 리전에서 실행 중인 배포된 Railway

달라지므로 사용하지 않았다.

SPEC R9는 배포된 `api`에서 측정하도록 요구하지만, 같은 SPEC 경계는 `/health`와
`/health/ready` 외의 라우터를 금지한다. 따라서 같은 이미지의 `worker` 엔트리포인트가 기동할 때
한 번 측정했다. 이 편차의 근거는 `01-CONTEXT.md > D-14`다.

대상은 Supabase `ap-southeast-1` 프로젝트다. `/health/ready`와 같은 PostgREST 단일 행 조회 및
publishable 키의 `apikey` 헤더를 사용했다. 콜드 첫 요청 1회를 먼저 측정하고, 워밍업 5회를 버린
뒤 본 표본 50회를 측정했다. p50과 p95는 정렬한 성공 표본에서 `ceil(p × N)`번째 값을 택하는
최근접 순위법으로 산출했다.
