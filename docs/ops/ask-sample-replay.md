# Ask 합성 샘플 재생 기록

`scripts/ask_replay.py`는 가상의 물류 회사 문서 8건과 고정 질문 30개를 실제 LLM으로 재생해 코드 전후를 비교한다. 2주 기준선 대신 쓰기로 2026-11-03에 결정했다. 근거: `openspec/changes/ai-control-output-contract/design.md`.

⚠️ 합성 샘플 수치다. 운영 트래픽의 효과로 인용하면 안 된다. 질문 수가 적고 LLM 답변이 매번 달라 작은 차이는 의미가 없다.

## 실행

```bash
# 544xx와 분리된 546xx 스택을 띄운다. 공유 스택의 큐에 붙으면 다른 테스트의 잡을 가져간다.
scripts/ask_replay_stack.sh start /tmp/ask-replay
# 비교할 코드로 API와 워커를 띄운다. 워커 내부 포트 8081은 고정이라 한 번에 한 벌만 띄운다.
scripts/ask_replay_serve.sh <코드 루트> /tmp/ask-replay/logs &
uv run python scripts/ask_replay.py seed --state state.json
uv run python scripts/ask_replay.py ask --state state.json --label after --out after.json
uv run python scripts/ask_replay.py compare before.json after.json
```

## 기본 모드 결정

`AI_CONTROL_QUALITY_MODE`의 기본값은 `enforce`다. 합성 샘플 30턴에서 인용 계약 위반이 0건이어서 정상 답변에 수리 호출이 붙지 않았다. 표본이 작고 합성 문서이므로 운영 오탐률을 뜻하지는 않는다. 위반이 늘거나 비용 문제가 생기면 코드를 되돌리지 않고 `shadow`나 `off`로 내린다.

## 2026-11-03 결과

모델은 `anthropic/claude-sonnet-4.6`이다. 문서 수집 약 $0.21, 질문 30개 1회 약 $0.75~$0.94가 들었다.

| 지표 | `06eae17` | `1e92dbe` (Step 2) | `314a855` (Step 3) |
| --- | --- | --- | --- |
| 평균 입력 토큰 | 7,974 | 6,188 | 6,300 |
| 질문 30개 비용 (USD) | 0.94 | 0.75 | 0.78 |
| 평균 이중 인용률 | 0.000 | 0.606 | 0.452 |
| 위키·원문을 모두 인용한 턴 | 0/30 | 29/30 | 24/30 |
| 기대 사실 포함률 | 1.000 | 0.966 | 1.000 |
| 인용 계약 위반 턴 | 측정 안 함 | 측정 안 함 | 0/30 |

`1e92dbe`는 squash 머지 전 작업 커밋이라 머지 뒤 `main` 이력에는 없다. `314a855`는 작업 중 고쳐 쓴 커밋이라 어느 브랜치에도 없고, 그 뒤 리뷰 지적을 반영한 코드와 다르다. 각각 #194와 `ai-control-output-contract` 구현 도중의 값이다.

"인용 계약 위반 턴"은 재생 당시의 판정이 아니라 최종 판정 함수를 재생 결과 파일(저장소 밖)의 답변에 다시 적용한 값이다. 재생을 다시 돌리지 않았으므로 최종 코드의 수리 경로가 실제 LLM에서 돈 적은 없다.

해석:

- 입력 토큰 감소는 예산 절단이 아니라 근거 구성 변화(위키 8건 → 위키 4건 + 원문 4건)에서 나왔다. 이 샘플에서 예산 절단은 0턴이다.
- `06eae17`의 이중 인용률 0은 위키가 검색 상위를 독차지한 결함 때문이다(#184, #195).
- Step 2와 Step 3의 차이는 재수집으로 위키가 달라진 것과 답변 변동을 포함하며 Step 3의 효과가 아니다.
- 위반이 0건이라 수리와 Fallback은 이 재생에서 돌지 않았다. 해당 경로는 합성 시나리오와 단위 테스트로 검증했다.
- Step 3 재생에서 만든 위키 13쪽은 모두 근거 청크가 연결됐다.
- 질문 1건(`q30`)은 Step 2 재생에서 질의 임베딩 실패로 `no-evidence`가 됐다.

## Step 4 재생 (2026-11-03)

공통 정책과 `data_collection: deny`, 템플릿 정리를 넣은 코드로 같은 위키에 질문 30개를 다시 돌렸다. `06eae17` 대비가 아니라 Step 3 재생 대비다.

| 지표 | Step 3 | Step 4 |
| --- | --- | --- |
| 평균 입력 토큰 | 6,300 | 6,619 |
| 질문 30개 비용 (USD) | 0.78 | 0.81 |
| 평균 이중 인용률 | 0.452 | 0.474 |
| 위키·원문을 모두 인용한 턴 | 24/30 | 24/30 |

- 데이터 수집 거부를 실어도 공급자 호출과 컴파일이 실패하지 않았다.
- 정책 문구로 호출당 입력이 약 320토큰 늘었다.
- 질문 1건(`q16`)은 질의 임베딩 일시 실패로 `no-evidence`가 됐다(#195). 재생 전체의 비용 합계는 약 $4.70이다.

위키 쓰기 기본 모드는 `shadow`다. 합성 샘플로는 운영의 보류 빈도를 잴 수 없어, 설계서 결정대로 빈도를 본 뒤 `enforce`로 전환한다.
