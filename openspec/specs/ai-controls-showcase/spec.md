# ai-controls-showcase Specification

## Purpose

로그인 없이 Controlled AI의 통제 전후 동작을 보여주되, 실제 테넌트 데이터가 공개 화면으로 나갈 경로를 원천적으로 두지 않는다.

## Requirements

### Requirement: 합성 증거만 쓰는 공개 쇼케이스
시스템은 로그인 없이 볼 수 있는 `/showcase/controlled-ai` 라우트를 운영 환경에서 SHALL 제공한다. 이 라우트는 저장소에 커밋된 합성 증거 파일만 읽어야 하며, 렌더링 중 Supabase나 API를 MUST NOT 호출한다.

#### Scenario: 익명 방문자의 접속
- **WHEN** 비로그인 방문자가 쇼케이스를 연다
- **THEN** 화면이 표시되고 로그인으로 이동하지 않으며 데이터베이스나 API 요청이 발생하지 않는다

#### Scenario: 로그인 세션이 있는 방문자
- **WHEN** 세션 쿠키를 가진 사용자가 쇼케이스를 연다
- **THEN** 익명 방문자와 같은 합성 내용을 보며 워크스페이스 데이터는 표시되지 않는다

### Requirement: 재현 가능한 통제 전후 증거
합성 증거는 자동화된 테스트 시나리오가 SHALL 생성하고, 시나리오 이름, 생성 커밋, 수정 전후의 관측값을 MUST 담는다. 쇼케이스는 Step 1(추적과 비용 회계), Step 2(프롬프트·토큰 예산과 단락), Step 3(출력 계약 검증), Step 4(정책과 위험한 쓰기 통제)의 통제 전후 비교 증거를 모두 SHALL 표시한다. 화면은 합성 데이터임을 SHALL 명시하고, 실측 운영 성과처럼 MUST NOT 표현한다.

#### Scenario: 충돌 판정 비용 누락의 전후 비교
- **WHEN** 방문자가 비용 누락 항목을 본다
- **THEN** 수정 전후의 기록 비용과 그 값을 만든 시나리오 이름, 커밋이 표시된다

#### Scenario: Step 2 예산 및 단락 시나리오의 전후 비교
- **WHEN** 방문자가 Step 2 항목(동일 원문 재컴파일 단락, Ask 컨텍스트 예산과 이중 근거 보존, 구조화 출력 `max_tokens` 강제)을 본다
- **THEN** 각 항목의 수정 전후 관측값과 시나리오 이름, 커밋이 표시된다

#### Scenario: Step 3 출력 계약 시나리오의 전후 비교
- **WHEN** 방문자가 Step 3 항목(코드 펜스 재시도, placeholder 페이지 거부, 인용 없는 Ask의 종결 상태)을 본다
- **THEN** 각 항목의 수정 전후 관측값과 시나리오 이름, 커밋이 표시된다

#### Scenario: Step 4 정책 시나리오의 전후 비교
- **WHEN** 방문자가 Step 4 항목(검증된 페이지 덮어쓰기, 데이터 수집 거부, 템플릿 우회)을 본다
- **THEN** 각 항목의 수정 전후 관측값과 시나리오 이름, 커밋이 표시된다

#### Scenario: 증거 파일의 내용 검사
- **WHEN** 증거 파일을 검사한다
- **THEN** 합성 입력만 포함하고 UUID 형식의 실제 워크스페이스 식별자, 자격 증명, 사용자 이메일이 없다

#### Scenario: 아직 구현되지 않은 단계
- **WHEN** 증거가 없는 Step이 있다
- **THEN** 준비 중임을 표시하고 예시 수치를 실제 결과처럼 보여주지 않으며, 그런 Step이 없으면 다음 단계 영역을 표시하지 않는다
