# golden-answer-evaluation Specification

## Purpose

합성 질문의 기대 사실과 원문 근거를 버전으로 보존하고, 코드 검사·LLM 심사·사람 판정을 구분하여 평가기의 오류와 답변의 오류를 대조할 수 있도록 한다. 미검토 자료와 측정 실패를 검증된 결과로 오인하지 않게 한다.

## Requirements

### Requirement: 골든셋 후보와 사람 검토 구분
시스템은 초기 30문항에 질문, 유형, 기대 사실, 허용 표현, 근거 문서와 원문 구간, 거절 기준, 데이터셋 버전을 MUST 보존한다. 각 문항은 사람 검토 전 후보 상태이며 실제 사람이 확인한 기록 없이 검토 완료로 표시해서는 MUST NOT 된다.

#### Scenario: 검토하지 않은 문항 조회
- **WHEN** 사람이 확인한 이력이 없는 문항을 조회한다
- **THEN** 골든셋 후보 또는 미검토로 표시하고 사람 기준 일치도 집계에서 제외한다

#### Scenario: 모호한 질문 수정
- **WHEN** 질문 또는 기대 사실과 근거가 변경된다
- **THEN** 새 버전과 지문을 만들고 과거 실행 결과와 사람 판정을 덮어쓰거나 자동 재사용하지 않는다

### Requirement: 사실과 인용의 분리 판정
시스템은 인용 유효성을 코드로 검사하고 사실 일치, 인용 정확도, 주요 주장 인용 충실도, 거절 적절성을 LLM 심사로 MUST 구분한다. 정확도는 해당 주장과 인용된 근거의 뒷받침 관계이며, 충실도는 근거가 필요한 주요 주장에 인용이 있는지를 의미한다. 판정은 통과·실패·검토 필요를 지원하고 적용할 수 없는 지표는 별도로 MUST 표시한다.

#### Scenario: 올바른 답에서 옛 규정 부정
- **WHEN** 답변이 현재 규정을 정확히 설명하며 옛 규정은 적용되지 않는다고 대조한다
- **THEN** 옛 값의 단순 등장만으로 의미 기반 심사를 실패시키지 않고 적용 규정과 근거에 따라 평가한다

#### Scenario: 존재하지만 주장을 뒷받침하지 않는 인용
- **WHEN** 제공된 실제 출처를 인용했으나 그 출처가 답변의 주장을 뒷받침하지 않는다
- **THEN** 인용 유효성과 인용 정확도를 서로 다른 판정으로 보존한다

#### Scenario: 심사 불가
- **WHEN** 필요한 근거가 누락되거나 심사 호출 실패 또는 응답 형식 오류가 발생한다
- **THEN** 심사 불가 사유를 보존하고 통과나 일반 오답으로 집계하지 않는다

### Requirement: 판정 근거와 실행 식별
심사 결과는 짧은 판정 이유, 대조한 답변·근거 구간, 데이터셋·답변·심사 모델·프롬프트·판정 기준 버전과 입력 지문을 MUST 보존한다. 모델이 제시한 인용 구간이 입력과 일치하지 않으면 유효한 근거로 표시해서는 MUST NOT 된다.

#### Scenario: 심사 모델의 잘못된 근거 구간
- **WHEN** 심사 응답의 근거 구간이 전달된 입력에서 확인되지 않는다
- **THEN** 검토 필요 또는 심사 불가로 표시하며 근거가 검증된 판정으로 집계하지 않는다

### Requirement: 사람 판정과 불일치 검토
작업대는 코드 판정 / LLM 판정 / 사람 확인을 MUST 나란히 표시하고 불일치와 미검토를 구분한다. 사람 검토는 확인한 입력 지문과 검토 시점 및 근거를 MUST 보존한다. 일치율과 오통과·오실패 건수는 동일 지표에 대해 사람의 명시적 통과·실패가 있는 동일 입력 표본만 분모로 사용하며 표본 수와 제외 수를 MUST 표시한다.

#### Scenario: 사람이 확인하지 않은 표본
- **WHEN** LLM 판정만 있고 사람 판정이 없다
- **THEN** 미검토로 표시하고 사람과 일치했다는 결과를 만들지 않는다

#### Scenario: 사람과 LLM 판정 불일치
- **WHEN** 동일 입력·동일 지표에 사람과 LLM의 통과·실패가 다르다
- **THEN** 해당 표본을 불일치 목록에서 확인할 수 있고 오통과 또는 오실패로 구분한다

### Requirement: 로컬 실행 및 명시적 비용 경계
초기 실행과 사람 판정 저장은 로컬 개발 환경에 한정하고 운영 환경 요청은 MUST 거부한다. 화면 조회나 미리보기는 유료 심사를 MUST 실행하지 않는다. 실제 심사는 모델·문항 범위·예산이 지정된 명시적 요청으로만 시작하고 지출·중단·미실행·비용 미측정을 MUST 구분한다. 합성 데이터만 외부 심사에 전달하고 문서와 답변을 실행 지시로 취급해서는 MUST NOT 된다.

#### Scenario: 운영 환경 또는 페이지 조회
- **WHEN** 운영 환경에서 심사를 요청하거나 사용자가 결과 화면을 조회한다
- **THEN** 운영 요청은 거부하고 조회만으로는 모델을 호출하지 않는다

#### Scenario: 예산 또는 비용 관측 부족
- **WHEN** 다음 호출을 위한 예산이 부족하거나 비용을 확인하지 못한다
- **THEN** 추가 호출을 중단하고 완료·미실행 표본 및 중단 이유를 보존한다
