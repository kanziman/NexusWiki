## Context

홈 Ask 히어로는 검색 범위를 세 가지로 고르게 되어 있다. 제출 시 `scope` 쿼리를 붙이지만, 질문하기 화면은 `q`와 `thread`만 읽고 Ask API `AskRequest`에도 범위 필드가 없다. 기본 검색 정책은 `graph_enabled = false`라 hop 확장도 타지 않는다. 카테고리 선택 UI도, 홈의 현재 문서도 없다.

## Goals / Non-Goals

**Goals:**

- 동작하지 않는 검색 범위 선택을 홈 Ask 히어로에서 제거한다
- 질문 제출은 질의만 넘기고, 검색은 기존 워크스페이스 전체 경로를 쓴다
- 스펙·프로토타입·스켈레톤이 같은 화면을 가리키게 한다

**Non-Goals:**

- 카테고리·문서 주변 검색을 구현하지 않는다
- `graph_enabled`를 켜거나 hop 검색을 질문 경로에 넣지 않는다
- 지식 그래프 화면의 `wiki_graph_neighborhood` 이웃 표시는 바꾸지 않는다
- Ask 대화 화면의 입력 composer는 바꾸지 않는다

## Decisions

검색 범위 컨트롤을 통째로 제거한다. 남는 값이 워크스페이스 전체 하나면 드롭다운은 조작처럼 보이기만 하고 실제 선택은 없다.

거부한 대안: 옵션 두 개를 숨기고 `워크스페이스 전체`만 남긴다. 항목이 하나인 선택기는 범위를 고르는 것처럼 읽힌다.

구현은 `AskHero`의 범위 상태와 `scope` 쿼리, 대응 CSS·프로토타입·스켈레톤·테스트를 지우는 것으로 끝낸다. 검색 서비스와 Ask API는 손대지 않는다.

## Risks / Trade-offs

- 나중에 카테고리·문서 주변 검색을 넣으려면 범위 UI를 다시 설계해야 한다. 지금은 가짜 선택이 더 비싸다.
- 프로토타입 HTML과 불변식 문서가 스펙과 어긋나면 같은 컨트롤이 다시 그려진다. 이번 변경에서 함께 맞춘다.
