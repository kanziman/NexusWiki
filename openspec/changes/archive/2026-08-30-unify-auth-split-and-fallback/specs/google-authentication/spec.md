## MODIFIED Requirements

### Requirement: Google 단일 인증

시스템은 로그인과 가입에서 Google OAuth만 제공해야 한다(MUST). 로그인과 가입
화면은 데스크톱에서 지식 비주얼과 인증 영역을 나란히, 모바일에서는 인증 영역을 먼저
제공해야 한다(MUST). 로그인 인증 영역은 제품명, 로그인 안내, Google CTA, 가입 화면
연결을 제공하고, 가입 인증 영역은 제품명, 가입 안내, Google 가입 CTA, 로그인 화면
연결을 제공해야 하며(MUST), 시각적 보조 영역이 없어도 인증을 완료할 수 있어야 한다.
지식 미리보기는 질문 입력, 답변 생성, 원문·위키 근거 표시 순서로 현재 시나리오를
보여 줘야 하며(MUST), 제품 메시지 “답으로 연결하다.”는 accent 밑줄로 강조해야
한다(MUST). 감소 모션 설정 또는 탭이 비가시 상태인 경우에는 미리보기와 밑줄을
정적으로 완성된 상태로 제공해야 한다(MUST). OAuth 진행 중에는 중복 시작을 막고
진행 상태를 알려야 한다(MUST). OAuth 실패는 계정 존재 여부를 드러내지 않는
단일 오류로 처리해야 한다.

#### Scenario: 로그인 시작

- **WHEN** 사용자가 로그인 화면의 Google CTA를 선택하면
- **THEN** 시스템은 내부 콜백 URL을 redirect 대상으로 OAuth를 시작한다

#### Scenario: 가입 시작

- **WHEN** 사용자가 가입 화면의 Google 시작 CTA를 선택하면
- **THEN** 시스템은 내부 콜백 URL을 redirect 대상으로 OAuth를 시작한다

#### Scenario: 인증 실패

- **WHEN** 콜백의 코드 교환이 실패하면
- **THEN** 시스템은 `/login?error=auth`로 이동하고 단일 오류 문구만 표시한다

#### Scenario: 데스크톱 로그인 화면

- **WHEN** 사용자가 데스크톱 너비에서 로그인 화면을 연다
- **THEN** 시스템은 지식 탐색 맥락을 보여 주는 시각적 보조 영역과 Google 인증
  영역을 나란히 제공한다

#### Scenario: 모바일 로그인 화면

- **WHEN** 사용자가 모바일 너비에서 로그인 화면을 연다
- **THEN** 시스템은 인증 영역을 먼저 한 열로 제공하고, 화면의 가로 넘침 없이
  Google 로그인과 가입 화면 연결을 사용할 수 있게 한다

#### Scenario: 데스크톱 가입 화면

- **WHEN** 사용자가 데스크톱 너비에서 가입 화면을 연다
- **THEN** 시스템은 지식 탐색 맥락을 보여 주는 시각적 보조 영역과 Google 가입
  영역을 나란히 제공한다

#### Scenario: 모바일 가입 화면

- **WHEN** 사용자가 모바일 너비에서 가입 화면을 연다
- **THEN** 시스템은 가입 영역을 먼저 한 열로 제공하고, 화면의 가로 넘침 없이
  Google 가입과 로그인 화면 연결을 사용할 수 있게 한다

#### Scenario: 지식 미리보기의 생성 순서

- **WHEN** 사용자가 모션을 허용하는 환경에서 로그인 또는 가입 화면을 연다
- **THEN** 시스템은 질문을 입력한 뒤 답변을 생성하고 원문 청크와 위키 문서
  근거를 표시한 후 다음 시나리오로 전환한다

#### Scenario: 헤드라인 강조

- **WHEN** 사용자가 모션을 허용하는 환경에서 로그인 또는 가입 화면을 연다
- **THEN** 시스템은 “답으로 연결하다.” 아래의 accent 밑줄을 그려 제품 메시지를
  강조한다

#### Scenario: 감소 모션 또는 비가시 탭

- **WHEN** 사용자가 감소 모션을 설정했거나 인증 탭이 비가시 상태다
- **THEN** 시스템은 지식 미리보기와 헤드라인 밑줄을 즉시 완성된 정적 상태로
  제공하고 새 타이핑 순환을 시작하지 않는다

#### Scenario: OAuth 요청 진행 중

- **WHEN** 사용자가 Google CTA를 선택해 OAuth 시작 요청이 진행 중이다
- **THEN** 시스템은 CTA를 비활성화하고 진행 상태를 표시하여 중복 요청을 막는다

#### Scenario: 가입 화면 연결

- **WHEN** 사용자가 로그인 화면의 가입 안내를 선택한다
- **THEN** 시스템은 `/signup`으로 이동한다

#### Scenario: 로그인 화면 연결

- **WHEN** 사용자가 가입 화면의 로그인 안내를 선택한다
- **THEN** 시스템은 `/login`으로 이동한다

### Requirement: OAuth 콜백은 안전한 내부 경로만 따른다

시스템은 authorization code를 한 번 교환하고, `/`로 시작하되 `//`로 시작하지 않는
경로만 다음 목적지로 허용해야 한다(MUST). 만약 authorization code가 콜백 경로가 아닌
루트 경로(`/`)로 직접 전달된 경우, 시스템은 code를 손실하지 않고 콜백 핸들러(`/auth/callback`)로
안전하게 포워딩하여 세션 교환을 수행해야 한다(MUST).

#### Scenario: 외부 리다이렉트 거부
- **WHEN** next 값이 절대 URL 또는 `//`로 시작하면
- **THEN** 시스템은 코드 교환 뒤 루트 경로로 이동한다

#### Scenario: 루트 경로의 authorization code 포워딩
- **WHEN** 사용자가 `/?code=...` 형태로 루트 경로에 접근하면
- **THEN** 시스템은 `/auth/callback?code=...` 로 안전하게 리다이렉트하여 세션을 발급한다
