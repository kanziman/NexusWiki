# 스펙 부합 리뷰 1차

판정: **needs_fix**

검토 범위: `golden-answer-evaluation` delta spec, proposal/design/tasks, 로컬 Python 실행기·심사 모듈, Next 프록시, 골든셋 비교 UI와 관련 테스트. 테넌트 격리 리뷰는 사용자 요청에 따라 수행하지 않았다. 실제 유료 심사와 사람 라벨이 아직 없다는 사실 자체는 구현 결함으로 보지 않는다.

## 수정 필요

### P1 — 호출 중 중단된 심사의 비용과 미실행 상태를 잃는다

`scripts/golden_answer_judge.py`의 `execute`는 공급자 호출 후에만 문항 상태를 파일에 쓴다. 호출 직전 `asked` 증가도 메모리에만 있고, 선택한 표본 id 목록은 job에 없다. 공급자 호출 도중 프로세스가 중단되면 복구는 status만 interrupted로 바꾸어 실제 호출한 문항을 미실행과 구분하지 못하며 `unknown_cost=False`, 지출 0으로 남긴다.

가짜 공급자에서 KeyboardInterrupt를 일으키는 방식으로 재현했다. 복구된 기록은 `asked=0`, `rows=[]`, `unknown_cost=False`, `not_run` 없음이었다. 비용 미관측·중단·미실행을 구분한다는 spec 및 설계에 맞지 않는다.

권고: 선택한 입력 id를 사전 보존하고 호출 전 in-flight 체크포인트를 남긴다. 재시작 시 응답이 확인되지 않은 호출은 비용 미관측·중단 표본으로 보존하고 아직 시작하지 않은 표본만 미실행으로 남긴다.

### P1 — 실제 입력 패키지가 보존되지 않는다

job과 row는 dataset/sample/judge 지문, model/config, 판정 구간만 저장한다. 실제 질문·기대 사실·답변·참조 원문·생성 당시 제공된 근거 맵은 저장하지 않는다. 후보 파일이나 저장된 답변이 변경되면 과거 판정 이유와 구간을 원래 입력과 대조하거나 재현할 수 없다. `results()`도 현재 표본 지문으로 조회하므로 변경된 입력의 예전 결과는 UI에서 사라진다.

권고: 실행 시작 시 지문으로 식별되는 불변 입력 패키지와 dataset/rubric/prompt 버전 또는 내용을 권한 제한된 파일에 저장하고 job이 참조하게 한다. 과거 실행을 현재 데이터셋으로 재구성하지 않도록 검증한다.

### P2 — 백그라운드 갱신이 검토 수정 충돌을 우회한다

`GoldenJudgePanel.tsx`의 HumanForm은 제출 순간 `review?.revision`을 사용한다. 작성 도중 다른 창에서 검토가 저장되면 3초 polling으로 review prop이 바뀌고 기존 작성 폼이 그 새 revision을 자동 채택한다. 따라서 사용자가 읽지 않은 새 검토를 stale conflict 없이 덮어쓴다. 서버의 revision 검사는 있지만 UI가 이를 무력화한다.

권고: 편집 시작 시 revision을 고정하거나 최신 revision 변경 시 작성 중임을 알리고 명시적 재조회·재편집을 요구한다. polling 후 제출하는 테스트로 409 또는 UI 충돌 차단을 검증한다.

### P2 — 공급자가 알려준 비용도 응답 구조 오류에서 버린다

`OpenRouterJudge.__call__`은 usage.cost를 읽은 후 `data.get("choices", [{}])[0]`를 사용한다. 공급자 응답이 `choices=[]`이거나 message 구조가 잘못되면 비용을 확보했어도 어댑터가 예외를 던져 실행기는 해당 금액을 기록하지 못하고 비용 미관측으로 처리한다. 형식 오류도 발생한 지출을 보존한다는 설계가 일부 형식 오류에서 성립하지 않는다.

권고: 비용 추출과 콘텐츠 검증을 분리하고 알려진 cost와 콘텐츠 오류를 함께 반환한다. 실제 어댑터 HTTP mock에 `usage.cost`가 있는 빈 choices/잘못된 message를 넣어 알려진 지출이 보존되는지 검사한다.

## 확인된 구현

- 후보 30문항과 원문 범위·해시 검증, 기본 미검토 상태.
- 실제 저장 답변과 합성 예시의 출처 구분, 지표별 사람/LLM 통과·실패 쌍만 일치도 분모로 사용, 분모 0 미측정.
- 코드 인용 유효성과 의미 심사 분리, 생성 당시 근거 맵이 없는 인용 지표를 심사 불가로 처리.
- 명시적 모델·예산·문항 요청, 조회에서 유료 호출 없음, 고정 로컬 경로와 운영 요청 차단.
- 검토 근거·시점·이력 저장, 서버의 예상 지문·개정 검사.

위 항목 수정과 관련 회귀 테스트 후 2차 리뷰가 필요하다.
