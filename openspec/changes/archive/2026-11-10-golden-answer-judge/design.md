## Context

동기는 proposal.md의 Why를 따른다. 추적: #266.
기존 Python 로컬 실행기는 루프백·토큰 인증과 파일 보존을 사용하고 Next.js 개발 전용 프록시가 연결한다. 공개 대시보드는 저장 결과를 읽으며 사람 검토는 브라우저 메모와 구분해야 한다. 기존 실행 원본에는 심사에 필요한 전체 인용 근거가 없을 수 있으므로 이를 복원했다고 가정하지 않는다.

## Goals / Non-Goals

목표와 제품 범위는 proposal.md와 delta spec을 따른다. 설계 경계는 운영 DB 변경 없이 합성 근거 패키지를 다루는 것이다. 30문항은 후보로 제공하고 실제 사람 확인은 구현 작업이나 에이전트의 내용 점검과 구분한다. 실제 유료 심사는 모델·예산 확정 후 별도 실행한다.

## Decisions

### 구조 게이트: 저장과 실행 구조 비교

| 기준 | A. 기존 로컬 실행기 확장(추천) | B. 별도 CLI와 수동 결과 가져오기 | C. 운영 DB·워커 통합 |
| --- | --- | --- | --- |
| 데이터 구조 | 버전 JSON 후보 + 로컬 실행·사람 판정 파일 | 같은 JSON을 CLI 입출력으로 사용 | DB 테이블·RLS·이력 스키마 필요 |
| API 영향 | 기존 로컬 프록시에 심사·검토 전용 고정 작업 추가 | 실행 API 없음, 가져오기 검증 필요 | 인증 API와 작업 큐 추가 |
| 상태 관리 | 원자 저장·지문·한 번에 한 작업, 재시작 중단 복구 | CLI 체크포인트와 수동 파일 선택 | DB 상태·큐·멱등성·테넌트 격리 |
| 핵심 동작 | 대시보드에서 명시적 실행과 불일치 검토 연결 | 실행은 터미널, 대조는 가져온 결과 | 팀이 여러 기기에서 실행·검토 |
| 컴포넌트 | 기존 작업대 안에 판정 비교 영역 추가 | 파일 선택·가져오기 UI 추가 | 사용자·권한·공유 UI까지 확대 |
| 기존 패턴 | 루프백·토큰·로컬 파일 패턴 재사용 | 기존 평가 CLI와 유사하나 사용자 흐름 분리 | 운영 AI 큐 패턴과 유사하나 초기 범위 초과 |
| 테스트 | 가짜 심사 공급자·임시 저장소·프록시 차단 검증 | 파일 호환·CLI·UI 검증 | 위 검증에 DB·RLS·큐 통합 검증 추가 |

A를 사용자 승인으로 확정했다. 이미 사용 중인 결과 확인·로컬 실행 흐름을 유지하며 공개 유료 호출이나 DB 마이그레이션을 추가하지 않는다. B는 개발자 수동 실행용 대안으로 남기고, C는 팀 운영 요구가 생길 때 재검토한다.

### 골든셋과 입력 패키지

- `scripts/fixtures/golden_answers.v1.json`에 30문항 후보를 둔다. 원문에서 바로 답할 수 있는 문항 12개, 복수 사실·계산 6개, 적용 시점·대상 구분 4개, 근거 부족 거절 4개, 인용·근거 대조 4개를 초기 구성으로 삼는다. 질문은 기존 합성 자료를 재사용하되 모호한 q06은 허브 일반 입고와 반품 입고를 명시적으로 구분한다.
- 정답 문장 하나와 문자열 일치시키지 않고 기대 사실 목록, 허용 표현, 적용 조건, 거절 여부와 근거 문서의 원문 구간을 보존한다. 모든 후보의 초기 검토 상태는 미검토다.
- 별도 답변 표본은 실제 저장 실행과 검증용 합성 답변을 `origin`으로 구분한다. 합성 오답·위조 인용 예시는 자동화 검증에 쓰되 모델의 실측 성적으로 집계하지 않는다.
- 심사 입력은 질문·답변·참조 정답 근거와 답변 생성 시 제공된 인용 근거 맵을 구분한다. 원문만 있는 기존 실행에 위키 근거나 생성 시점 인용 맵을 추측해 넣지 않는다. 누락된 지표만 심사 불가로 남긴다.
- 데이터셋 검토는 문항 지문에, 답변의 사람 판정은 답변·근거·문항·평가 기준을 합친 표본 지문에 연결한다. 심사 모델 변경만으로 사람 정답을 무효화하지 않으며 LLM 결과는 별도 심사 지문으로 보존한다.

### 로컬 저장과 작업 상태

- 기존 `.worktrees/evaluation-dashboard/` 하위의 별도 `judge/` 영역에 입력 패키지·심사 실행·비용·검토 이력을 보존한다. 원본을 수정하지 않고 기존 `run-*.json` 비교 형식과 분리한다.
- 파일은 원자 교체와 프로세스 잠금으로 저장한다. 같은 표본에 대한 검토는 예상 지문·이전 개정값을 확인해 저장하고 충돌 시 재조회하도록 한다. 권한은 디렉터리 700·파일 600을 적용한다.
- 작업은 `queued → running → completed / partial / failed / interrupted`이며 각 문항 뒤 체크포인트한다. 문항별 상태는 `evaluated / review_needed / not_evaluable / error / not_run`으로 구분하고 재시작 시 진행 작업은 interrupted로 복구한다.
- 기존 재채점·새 답변 생성과 심사를 합쳐 한 번에 한 작업만 실행한다. 심사는 저장 답변을 읽으며 새 답변 생성을 연쇄 실행하지 않는다.

### 심사 호출과 판정 검증

- Python 쪽 공급자 어댑터에 심사 요청과 사용량·비용 결과를 한정한다. 기존 OpenRouter 호출·비용 정규화 패턴을 재사용하되 운영 DB의 사용량으로 위장하지 않고 로컬 심사 비용으로 별도 기록한다. 키는 로컬 서버 환경변수로만 읽고 API 응답·파일 내보내기·로그에 남기지 않는다.
- 서버 설정에 심사 허용 모델·가격 정보가 없으면 준비 필요로 표시한다. 클라이언트가 URL·키·임의 경로를 전달하지 못하며, 모델은 서버 허용 목록에서 선택한다. 모델별 가격은 실제 실행 전 확인된 설정을 사용하며 코드에 특정 모델을 기본 유료 실행으로 고정하지 않는다.
- 호출 전 입력 한도와 출력 상한을 포함한 예상 비용을 점검한다. 예산·문항 범위·모델을 명시한 실행만 허용하고 비용 미관측·공급자 장애 시 자동 재시도 없이 중단한다. 비용이 발생한 형식 오류도 지출에 포함한다. 공급자 미보고 비용은 0으로 바꾸지 않는다.
- 답변과 자료는 비신뢰 데이터로 구분해 전달하고 도구·문서 쓰기를 허용하지 않는다. 각 지표에 `pass / fail / review_needed / not_applicable`과 짧은 이유·구간 참조를 받는다. 근거가 없는 응답, 범위를 벗어난 구간, 입력에 존재하지 않는 인용은 검증된 판정으로 표시하지 않는다. 내부 추론 원문은 요구하거나 저장하지 않는다.
- 코드 인용 유효성, 의미 판정, 호출 실패를 분리한다. 유효성 실패가 의미 지표 전체를 자동 실패시키지 않으며, 모든 지표를 합친 단일 품질 점수는 첫 범위에서 만들지 않는다.

### 로컬 API와 대시보드

- 기존 개발 전용 프록시와 루프백 인증 경계 아래 고정 작업 `judge-status`, `judge-run`, `judge-review`를 추가한다. 요청은 서버가 가진 실행·문항 id만 참조하며 클라이언트가 사람 이름을 인증된 신원처럼 생성할 수 없게 한다. 사람 검토는 로컬 사용자의 제출 기록이며 조직 인증 증명이 아니다.
- 읽기 응답은 허용 필드만 반환한다. 동시 실행 충돌·지문 충돌·유효하지 않은 입력·연결 실패는 화면에서 구분한다. 공개 결과에는 로컬 검토자의 식별 정보와 임의 원본을 포함하지 않는다.
- 기존 작업대 안에서 골든셋 검토 상태와 실행 요약을 표시하고 질문 상세에 코드 / LLM / 사람 비교를 배치한다. `불일치`, `사람 미검토`, `심사 불가`를 구분해 필터링한다. 각 지표의 적용 불가·검토 필요도 표시한다.
- 사람은 답변과 근거를 확인한 뒤 지표별 판정과 이유를 직접 제출한다. 미검토 상태의 기본값을 통과로 두지 않는다. 골든셋 후보 검토 완료와 특정 답변의 사람 판정은 별도 동작이다.
- 사람 기준 일치도는 동일 표본·동일 지표의 명시적 통과·실패 쌍만 집계한다. 분모 0은 미측정이며 100%로 표시하지 않는다. 오통과는 사람 실패/LLM 통과, 오실패는 사람 통과/LLM 실패다. 예시용 합성 답변은 실측 답변 집계와 별도 묶음으로 표시한다.

### 테스트와 검증

가짜 공급자와 임시 저장소로 정상 판정, 옛 값 부정, 거절, 인용 근거 불일치, 형식 오류, 비용 미기록, 예산 중단, 재시작 복구, 검토 충돌, 지문 변경 후 제외를 검증한다. HTTP 경계는 운영 403·다른 출처 거부·고정 경로·입력 크기를 확인한다. UI는 사람 판정 미생성, 분모 0, 불일치 필터, 제출·저장 실패를 확인한다. 실제 심사 정확도는 사람 라벨과 유료 실행이 준비된 이후에만 보고한다.

## Risks / Trade-offs

- 사람 검토를 자동 생성할 위험 → 미검토 기본값, 사람 제출 기록과 입력 지문 없이는 분모에서 제외.
- 원본 인용 근거 부재 → 근거를 합성·추측해 채우지 않고 심사 불가로 표시. 별도 합성 입력 패키지로 회귀 표본 제공.
- 심사기의 잘못된 판정·프롬프트 주입 → 평가 지침과 비신뢰 문서·답변 분리, 형식·구간 검증, 사람 대조.
- 비용 보고 지연 → 사전 추정과 다음 호출 전 잔여 예산 확인, 미측정 시 중단. 절대 지출 상한으로 주장하지 않음.
- 로컬 파일은 기기 간 공유 불가 → 첫 범위의 의도된 제약. 공개 결과는 허용 필드 내보내기만 사용.

## Migration Plan

기존 결과와 사람 메모 형식은 덮어쓰지 않는다. 새 평가 경로를 추가하고 기능 비활성화로 되돌린다. 로컬 main이 원격보다 뒤처진 상태는 구현 착수 전에 확인하고, 기존 랜딩 문구 수정은 별도 변경으로 보존한다.

- 요구사항·용어: 승인 완료.
- 구조 선택: A 사용자 승인 완료(“응”).
- 최종 설계·비목표: 사용자 승인 완료(“응”).
- 수직 작업·구현 착수: 사용자 승인 완료. 테넌트 리뷰는 사용자 요청으로 생략한다. 경계 테스트는 유지한다.
