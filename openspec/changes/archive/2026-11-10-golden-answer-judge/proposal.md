## Why

기존 키워드 채점은 올바른 거절과 옛 규정을 부정하려고 인용한 답변을 실패로 처리한다. 인용 표식이 유효하다는 사실도 인용 근거가 답변을 뒷받침한다는 뜻은 아니므로, 골든셋과 의미 기반 심사를 사람 판정에 대조하는 평가 체계가 필요하다.

추적: https://github.com/kanziman/NexusWiki/issues/266

## What Changes

- 기존 합성 자료에서 질문 30개와 근거 구간, 기대 사실, 허용 표현, 거절 여부를 갖춘 골든셋 후보를 구성한다. 모호한 질문은 새 버전에서 명확히 하고 과거 실행의 판정은 덮어쓰지 않는다.
- 사람이 검토하지 않은 후보는 검토 완료 골든셋으로 표시하지 않는다. 사람의 판정과 근거가 기록된 표본만 심사기 일치도 집계에 사용한다.
- 인용 유효성은 코드로, 사실 일치·인용 정확도·주요 주장 인용 충실도·거절 적절성은 근거를 전달한 LLM 심사로 구분한다.
- LLM은 통과·실패·검토 필요와 짧은 판정 근거 및 답변·근거 구간을 반환한다. 호출 실패·형식 오류·근거 누락은 통과나 일반 오답으로 집계하지 않는다.
- 기존 작업대에 코드 판정 / LLM 판정 / 사람 확인을 나란히 표시하고, 불일치와 미검토 표본을 구분한다.
- 데이터셋·답변·심사 모델·프롬프트·판정 기준 버전과 입력 지문을 보존한다. 수정된 입력에 과거 사람 판정을 자동 재사용하지 않는다.
- 초기 범위는 로컬 실행과 합성 데이터로 제한한다. 유료 심사는 명시적으로 요청할 때만 실행하며 예산을 지정한다. 실제 유료 실행 예산과 모델 선택은 구현 계약과 별도로 확정한다.

## Capabilities

### New Capabilities

- `golden-answer-evaluation`: 골든셋 후보와 검토 상태, 사실·인용 심사, 사람 대조 및 불일치 검토와 버전 보존.

### Modified Capabilities

없음. 기존 오프라인 회귀 관문의 판정·CI 차단 기준과 기존 실험의 사전 등록 판정은 변경하지 않는다.

## Impact

- 평가 스크립트·합성 fixture·실행기·평가 결과 내보내기와 대시보드에 새 평가 경로를 추가한다.
- 사람 검토가 없는 상태를 완료된 골든셋이나 검증된 심사기로 주장하지 않는다. 운영 데이터 수집, 공개 유료 실행, 자동 배포 차단, 자동 원인 진단은 범위 밖이다.
- 저장 방식과 공급자 호출 경계는 다음 구조 게이트에서 비교·확정한다. 운영 DB 마이그레이션은 기본 제안에 포함하지 않는다.

## 승인 상태

- 요구사항·용어 게이트: 사용자 승인 완료(“응”).
- 구조·최종 설계·수직 작업 게이트: 미진행.
