## Context

배경과 승인된 요구사항은 `proposal.md` 및 delta spec을 따른다. 현재 Ask 예산 확인은 조회 후 공급자 호출로 이어져 병렬 승인 경쟁이 있고, 사용량 기록은 스트림 종료 시점에 이뤄진다. `usage_events.cost_micros`는 음수를 허용하지 않으며 기존 행을 수정·삭제할 수 없다. 공급자 경계는 SSE만 전달하므로 generation 응답 헤더를 워커 회계로 전달하는 통로도 필요하다.

## Goals / Non-Goals

- 목표: Ask 공급자 호출 전에 영속적인 예산 확보, 중단 호출의 재시작 가능한 대조, 중복 없는 추기형 정산, 출처가 구분되는 비용 표시.
- 비목표: 전 공급자 호출의 엄격한 선예약, 공급자 실제 청구 상한 보장, 과거 generation ID 없는 호출 복원, 사용자별 과금, #170 턴 복구, 프롬프트 저장, 본문 조회 API 사용, 자동 운영 배포와 실제 유료 검증.

## Decisions

### D1. 호출 상태와 사용량 감사 기록을 분리한다

Gate 2에서 호출별 Postgres 예약·정산 테이블 방식을 승인했다. 통합 이벤트 원장은 기존 집계 전환 범위가 크고, 별도 예약 서비스는 운영 비용과 분산 트랜잭션이 늘어 제외했다.

- `ask_cost_calls`: 워커 발급 `call_id`, `workspace_id`, `trace_id`, 서버가 정한 호출 시작 시각·UTC 귀속 월, 모델·정책 버전, 확보액, generation ID, 상태, 대조 재시도·임대 정보를 보관한다. 본문은 저장하지 않는다.
- `ask_cost_settlements`: 호출별 확정 비용과 근거 종류(최종 사용량 또는 generation 조회), 정산 시각을 추가 전용으로 남긴다. `call_id` 고유 제약으로 확정 정산은 한 번만 허용한다. 임시 조회액을 확정 정산으로 먼저 저장하지 않는다.
- 신규 Ask 사용량 행에는 `call_id`를 연결한다. 기존 완료·중단 사용량 행은 관측 당시 그대로 보존하고, 정산은 별도 이력이다. 부분 보고액보다 작은 확정액도 표현할 수 있어야 하므로 음수 usage 행으로 보정하지 않는다.
- 회계 상태는 `reserved` → `in_flight` → `unresolved` 또는 `settled`다. 공급자 전송을 하지 않았음이 확실한 경우만 `released`로 전환하고 해제 사유 이력을 남긴다.

### D2. 모든 예산 소비자가 같은 유효 금액을 읽는다

공통 DB 집계는 월별로 다음을 계산한다.

`예산 판정액 = 기존·비 Ask 사용량 + 신규 Ask 호출별 유효 금액`

- 정산 완료 호출: 정산된 확정액만 반영한다. 연결된 관측 usage 행은 다시 합산하지 않는다.
- 진행 중·미해결 호출: `max(임시 확보액, 이미 보고된 비용)`을 반영한다. 관측액과 확보액을 단순히 더하지 않는다.
- 공급자 미전송이 확인돼 해제된 호출: 0을 반영한다.

기존 이력의 `call_id` 없는 행은 기존대로 합산하며 추측으로 신규 호출과 묶지 않는다. Ask 선예약 RPC는 워크스페이스 행을 잠그고 집계·잔여 비교·예약 INSERT를 한 트랜잭션으로 수행한다. 같은 call_id 재전달은 같은 예약을 반환하며 새 공급자 호출을 허용하는 재시도 키로 쓰지 않는다. 공급자 호출 자체는 자동 재전송하지 않는다.

수집 인큐와 기존 Ask preflight도 공통 집계를 사용해 임시 점유액을 무시하지 않게 한다. 수집·임베딩·컴파일의 전 비용을 미리 예약하지는 않으므로 전체 워크스페이스의 실제 청구액에 대한 엄격한 상한 보장은 아니다. 예산 행이 없거나 DB 확보가 실패하면 신규 Ask 공급자 호출을 시작하지 않는다.

### D3. 확보액은 운영자가 검토한 모델별 고정 보수액으로 시작한다

초기 정책은 모델별 `reserve_micros`, 전체 messages의 UTF-8 바이트 상한, 공급자에 전달하는 출력 `max_tokens`, 정책 버전을 묶어 명시적으로 설정한다. `reserve_micros`는 입력 상한과 최대 출력에 대한 검토된 가격 추정에 여유분을 더한 값이며 정수 micro-dollar다. 숫자 기본값을 임의로 넣거나 모델을 바꿔도 과거 정책을 재사용하지 않는다. 정책 누락·모델 불일치·입력 초과는 공급자 호출 전에 거부한다. 모델별 정책 설정과 한도 변경은 운영 문서에 근거를 남긴다.

확보액은 공급자가 보장한 최대 청구액이 아니다. 토크나이저·가격 변경 등으로 실제 비용이 초과할 수 있으며, 확인된 실제 비용은 확보액보다 커도 전액 반영하고 초과 상태를 표시한다. 조회 불가 호출의 실제 금액에는 검증된 절대 상한이 없음을 명시한다. 이번 보장은 반복 중단 호출이 무료로 승인되는 경로를 임시 점유로 차단하는 것이며, 외부 청구액의 수학적 상한을 주장하지 않는다. 가격 실조회 의존으로 매 Ask의 가용성을 떨어뜨리는 방식은 채택하지 않는다.

### D4. 전송 의도와 generation ID를 최대한 일찍 기록한다

내부 인증·입력·정책 검증과 기존 속도 제한을 통과한 뒤, 스트림 응답 시작 전에 예산을 확보한다. 예산 부족은 기존 402 `budget_exceeded`, DB 확보 불가는 가용성 오류로 구분한다. 동시 실행 슬롯 대기 중 취소되어 전송을 시작하지 않았다면 예약을 해제할 수 있다.

공급자 경계를 넘기기 전에 DB에 `in_flight` 전송 의도를 남긴다. 그 뒤 프로세스가 죽으면 실제 전송 여부를 몰라도 미해결로 유지한다. 응답 헤더의 generation ID를 본문 청크보다 먼저 저장하고, 헤더가 없으면 프레임의 ID를 보조 수단으로 사용한다. ID 불일치는 자동 정산하지 않고 경고·미해결로 남긴다. ID 저장 실패 후에도 예약은 남으므로 비용 0으로 해제하지 않는다.

정상 최종 사용량도 같은 정산 RPC를 사용한다. 서버가 확인한 유효한 비용과 완료 근거가 있는 경우만 정산한다. 비용 필드의 부재·null·형식 오류를 0으로 변환하지 않는다. 공급자에게서 정상적인 명시적 0을 보고받은 경우는 0 정산이 가능하다.

### D5. 기존 워커에서 제한된 사후 대조를 실행한다

전용 워커 루프가 DB에서 만료된 in-flight와 대조 가능한 unresolved를 임대해 처리한다. 공급자 조회는 워커만 실행하고 generation 비용 메타데이터 API의 허용 필드만 읽는다. 프롬프트·응답 본문 조회 API는 사용하지 않는다.

대조는 호출 동시성·요청 시간·한 번에 처리할 건수를 제한하고, 오류에는 지수 지연과 상한을 적용한다. 일정 횟수 실패하면 자동 시도를 멈춘 `manual_review` 표시를 남기되 미해결 점유는 유지한다. 이 상태는 회계적으로 unresolved다. 정상 조회라도 종료 여부·호출 ID·모델·비용이 유효하지 않으면 정산하지 않는다. 임대 만료 뒤 다른 워커가 재시도해도 정산 고유 제약으로 중복 반영되지 않는다.

정산 RPC는 호출과 해당 워크스페이스를 확인하고 확정 이력 추가·상태 전환을 한 트랜잭션으로 수행한다. 임시 점유만 먼저 해제하는 구간은 없다. 달이 바뀌어도 기존 호출은 생성 당시 UTC 월에 귀속되며 새달의 호출로 다시 계산하지 않는다. 불명확한 과거달 점유를 새달에 이월하지는 않는다.

### D6. 권한과 표시 경계를 유지한다

예약·정산 쓰기와 대조 임대는 service_role 전용 RPC로 제한하고 워커는 workspace_id를 명시한다. 호출 상태와 generation ID는 사용자 직접 SELECT를 허용하지 않는다. 클라이언트가 generation ID나 확보액을 지정하는 API는 만들지 않는다.

Control Room의 요청자 JWT 경로는 기존 작성자·역할 게이트를 통과한 뒤 허용된 금액·상태만 받는다. 필요한 집계 RPC의 definer 경로에는 현재 멤버십·작성자 또는 editor 권한을 함수 안에서도 검사하고 고정 search_path와 최소 EXECUTE 권한을 둔다. 비용 RPC가 새로운 타인 Ask 상세 조회 경로가 되지 않게 한다. 워크스페이스 집계에는 개인 식별자를 추가하지 않는다.

표시는 공급자 보고액, 미확정 점유액, 예산 판정액을 구분한다. 정산은 공급자 호출 횟수를 늘리는 사건이 아니므로 호출 수·토큰을 중복 집계하지 않는다. 공급자 원시 응답·generation ID·비밀 키·본문을 화면이나 로그에 싣지 않는다.

리뷰 r1 조치: trace 없는 비용 조회는 `p_ask_only`와 무관하게 RPC 내부에서 UTC 일 단위로 경계를 내린다. 작성자 전용 `ask_cost_trace_calls`가 원 관측액과 정산 반영액을 함께 반환해 호출별 비용 합과 trace 합계를 일치시킨다. 관측 usage가 없는 중단 호출도 한 행으로 표시하되 토큰은 기록 없음으로 표시한다. 기존 Control Room의 사용량 행 합계 문구는 유효 비용 합계로 delta에 명시적으로 수정했다.

## Risks / Trade-offs

- ID 확보 전 종료되거나 전송 직전 죽으면 자동 대조가 불가능할 수 있다 → 예약 유지와 운영자 확인 상태로 드러낸다. 임의 기간 경과로 해제하지 않는다. 수동 금액 조정 UI는 범위 밖이다.
- 보수적 확보액이 남은 예산보다 크면 실제 저렴한 질문도 거부된다 → 확정 청구와 구분해 안내하고 모델 정책을 운영자가 조정한다.
- 실제 비용이 확보액을 넘을 수 있다 → 초과액을 숨기거나 잘라내지 않고 확정액에 반영한다. 전 공급자의 실제 청구 상한 보장은 범위 밖이다.
- 원시 usage 합과 정산 후 유효 금액이 달라진다 → 예산·설정 화면·Control Room·집계의 비용 소비자를 전부 찾아 공통 집계 의미로 맞추고 원시 관측 이력과 구분한다.
- 기존 워커가 새 회계를 우회할 수 있다 → 전환 중 신규 Ask를 일시 중지하고 모든 워커를 전환한 뒤 재개한다. 운영 중지를 에이전트가 임의 실행하지 않는다.

## Migration Plan

원격 원장과 로컬 최신 번호를 확인한 뒤 새 마이그레이션 번호를 배정한다. 기존 적용 파일은 수정하지 않는다. 새 테이블·RPC·공통 집계와 기존 인큐 조회 변경은 이전 코드와의 호환성을 검사하고 머지 전 승인된 운영자가 DB에 적용·확인한다.

운영 전환은 신규 Ask 유입 중지 → 기존 스트림 종료 대기 → DB 적용 확인 → 워커·API·대시보드 전환 → 예약·정산·표시 확인 → Ask 재개의 별도 승인 절차로 진행한다. DB 선적용은 구 워커의 비용 0 기록을 해결하지 않으므로 배포 중 빈틈을 명시한다. 로컬 검증과 PR 작성이 운영 전환 실행을 승인하는 것은 아니다.

활성 예약이 생긴 뒤 구 코드로 단순 롤백하면 예약을 무시할 수 있다. 이 경우 신규 Ask를 중지한 상태에서 예약을 인식하는 버전으로 복구하거나 운영자에게 이관한다. 테이블 삭제·감사 기록 수정으로 롤백하지 않는다.

## Verification

- DB 병렬 예약, 동일 키 재시도, 중복·동시 정산, 비용 하향·상향 정산과 월 경계 테스트.
- 공급자 전송 전·후 및 ID 저장 전·후 중단, DB 실패, 워커 재시작·임대 만료·조회 오류 테스트.
- 정상 Ask와 명시적 0 비용, 비용 필드 누락, 보수액 초과의 회계 일치 테스트.
- 작성자·다른 멤버·비멤버·멤버십 상실자의 비용 조회 및 직접 예약·정산 우회 거부 테스트.
- Control Room의 점유·확정·정산 표시, 중복 없는 호출 수와 토큰, 본문·비밀 누출 검사.
- 실제 유료 호출 없이 공급자 헤더와 조회 fixture로 검증하며, 실제 취소 호출의 조회 성공 여부는 운영자가 별도로 확인한다.
