## r1 조치 확인

### 1. 직접 비용 집계 RPC의 기간 보호

`ask_cost_snapshot`이 trace 없는 요청의 시작 시각을 DB 함수 내부에서 `date_trunc('day', p_since, 'UTC')`로 정규화한다. 금액·미해결 건수·운영자 확인 건수·초과 건수의 모든 필터가 정규화한 `v_since`를 사용한다. `p_ask_only=true`뿐 아니라 false 경로도 같은 처리를 하므로 플래그 변경으로 우회되지 않는다. 작성자 전용 trace 상세만 기존의 명시적인 기간을 유지한다.

실제 요청자 JWT로 직접 RPC를 호출하는 회귀 테스트에서 같은 날의 서로 다른 시작값이 두 플래그 모두 같은 점유액·건수를 반환함을 확인했다.

### 2. 호출별 유효 비용과 상세 합계의 정합성

작성자 전용 `ask_cost_trace_calls` RPC를 추가하고 함수 내부에서 기존 snapshot의 현재 멤버십·작성자 게이트를 재사용한다. generation ID는 반환하지 않는다. 정산된 호출은 확정액, 미정산 호출은 원 관측액을 공급자 보고 비용으로 반환하며 원 관측액·미확정 점유액·상태는 별도 필드다.

API는 신규 Ask에 연결된 원 관측 행을 호출별 투영으로 대체해 정산을 새 호출로 중복 집계하지 않는다. 레거시 호출과 질의 임베딩 관측은 보존한다. 화면은 「원 관측 비용」「공급자 보고 비용 (정산 반영)」「미확정 점유」를 구분하고, 관측되지 않은 토큰을 기록 없음으로 표시한다.

기존 `Control Room 추적 탭` requirement 전체를 MODIFIED delta로 정리해, 상세 합계가 원시 usage 합이 아니라 호출별 유효 비용 합과 일치한다는 승인된 설계 의미를 계약에 반영했다. 기존 진행 중 수집·빈 상태 시나리오도 보존했다.

회귀 테스트에서 원 관측 비용 90 → 확정 비용 20의 하향 정산 후 호출 수 1건, 원 관측액 보존, 호출별 유효 비용 합과 상세 합계의 일치를 확인했다. 기존 owner·viewer의 타인 Ask 호출별 RPC 접근은 403이고, 작성자의 비용·상태 조회는 허용됨을 확인했다.
