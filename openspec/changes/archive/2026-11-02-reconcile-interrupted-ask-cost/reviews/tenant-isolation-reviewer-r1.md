# 테넌트 격리 리뷰 1라운드

판정: **needs_fix**

대상: `reconcile-interrupted-ask-cost`의 현재 작업 트리. 운영 적용과 실제 유료 공급자 호출은 검증 범위 밖이다.

## 수정 필요

### P2 — 공개 비용 RPC가 초 단위 집계 경계를 허용한다

- 위치: `supabase/migrations/0027_ask_cost_accounting.sql`의 `ask_cost_snapshot`, 특히 203~216행의 `p_since` 비교.
- API의 Ask 집계 경로는 시각을 UTC 일 단위로 내리지만, authenticated에 공개된 RPC 자체는 `p_since`를 그대로 사용한다. editor가 PostgREST로 직접 호출하면 기존 「개인을 드러내지 않는 Ask 집계」의 집계 경계 내림을 우회할 수 있다.
- 로컬 재현: 임시 owner와 워크스페이스에 70 micro-dollar 예약 한 건을 만든 뒤 요청자 신원과 `set local role authenticated`로 같은 RPC를 호출했다. `p_ask_only=true`, `p_since=now()-1 second`는 `pending_micros=70`, `unresolved_count=1`을, `p_since=now()+1 second`는 모두 0을 반환했다. 두 경계는 같은 UTC 날이다. 전체 트랜잭션은 롤백했다.
- 영향: 다른 멤버의 미확정 호출 발생 시각과 상태·금액을 집계 차분으로 분리할 수 있다. 워크스페이스를 넘는 데이터 노출은 발견하지 않았지만 기존 집계의 개인정보 보호 계약이 약화된다.
- 수정 방향: trace 없는 집계의 시작 경계를 RPC 내부에서 UTC 일 단위로 정규화한다. `p_ask_only=false`의 일반 예산 조회로 같은 경계를 우회하지 않도록 비-trace 비용 집계 전체에 적용하고, 공개 RPC 직접 호출 회귀 테스트를 추가한다. 특정 trace 조회는 기존 작성자 게이트를 유지한다.

## 확인한 경계

- 예약·전이·임대 함수는 public·anon·authenticated 실행 권한을 회수하고 service_role에만 부여한다. 호출·정산 테이블과 내부 투영은 사용자 직접 SELECT를 허용하지 않는다.
- 쓰기 RPC는 workspace와 call을 함께 확인하며 관측 행의 복합 FK가 다른 워크스페이스 호출 연결을 막는다. 워커 변경 요청에도 workspace_id가 명시된다.
- snapshot은 현재 멤버십을 검사하고 trace 상세는 스레드 작성자만 통과시킨다. owner나 editor라는 이유만으로 타인 Ask 상세를 허용하지 않는다. viewer의 비-trace 조회에서는 Ask 건수·manual_review 건수를 숨긴다.
- 워크스페이스 행 잠금으로 동시 Ask 예약을 직렬화하고, 정산은 호출 행 잠금과 call_id 고유 정산 이력으로 중복을 막는다. 확정 정산과 예약 해제 사이에 금액이 비는 트랜잭션 구간이 없다.
- 원시 usage 행은 수정·삭제하지 않고 호출별 투영으로 예약·관측·정산의 중복 합산을 피한다. 정산액은 호출 생성 시각으로 원래 기간에 귀속된다.
- 전송 의도를 먼저 저장하고 ID 부재·조회 오류·불명확한 전송은 예약을 유지한다. 만료 임대의 응답은 토큰과 만료 시각으로 거부하며, 실패 재시도나 manual_review는 비용 0 해제로 연결되지 않는다.
- 공급자 비용 대조는 메타데이터 엔드포인트만 사용하고 정산에 필요한 ID·모델·종료 근거·금액을 검증한다. 새 화면·로그에 공급자 본문이나 키를 추가하는 경로는 발견하지 않았다.
