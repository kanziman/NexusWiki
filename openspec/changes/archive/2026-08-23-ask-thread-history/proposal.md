## Why

현재 Ask 대화는 브라우저 메모리에만 있어 새로고침이나 화면 이탈 시 질문·답변과 인용 탐색 맥락이 모두 사라진다. 사용자가 자신의 대화를 다시 열었을 때도 NexusWiki의 핵심 가치인 발급된 위키·원문 이중 인용을 그대로 추적할 수 있도록 서버 영속 스레드 이력이 필요하다.

## What Changes

- 워크스페이스 멤버가 자신이 작성한 Ask 대화 스레드를 생성하고 목록 조회·열기·이름 변경·삭제할 수 있게 한다.
- 완료된 질문과 답변을 스레드의 턴으로 영속화하고, 새로고침이나 다른 기기에서 저장된 턴을 복원한다.
- 복원된 답변은 저장된 최종 텍스트와 발급 인용 해소 정보를 함께 사용하여 위키 마커와 원문 마커를 클릭 가능한 상태로 재수화한다. 비활성 placeholder를 복원 결과로 사용하지 않는다.
- 사용자 요청 경로의 모든 스레드 접근은 요청자 JWT의 `user_client`를 사용하고, 워크스페이스 멤버십 안에서 작성자 소유 행만 허용하는 RLS를 적용한다. `anon`은 거부하며, `USING` 정책에 막힌 쓰기의 0행 결과는 HTTP 403으로 응답한다.
- SSE `done`으로 정상 완료된 턴의 저장을 at-least-once로 처리하고 `client_turn_id`를 멱등 키로 사용하여 같은 완료 턴이 중복 저장되지 않게 한다.
- 기존 단건 grounded Ask 의미와 SSE 이벤트 순서는 유지한다. 이전 턴을 LLM 문맥으로 재주입하는 멀티턴 답변, 워크스페이스 공유·공개 스레드, 미완료 `dropped` 상태의 영속화는 이번 변경의 범위에 포함하지 않는다.

## Capabilities

### New Capabilities

- `ask-thread-history`: 사용자 소유 Ask 스레드의 생명주기, 완료 턴의 멱등 영속화, 이중 인용 복원, 요청자 인증과 RLS 격리 계약을 정의한다.

### Modified Capabilities

- 없음.

## Impact

- Ask API의 요청 계약과 스레드·턴 조회 및 변경 엔드포인트가 확장된다.
- Ask 서비스의 SSE 완료 처리와 사용자 JWT 데이터 접근 경로가 스레드 영속화와 연결된다.
- Supabase에 Ask 스레드·턴 저장 구조, 멱등 제약, 작성자 소유 RLS 정책이 추가된다.
- 대시보드 Ask 화면에 스레드 목록·전환·이름 변경·삭제 및 저장된 인용 복원 상태가 추가된다.
- 관련 API·RLS 통합 테스트와 대시보드 상태·인용 복원 테스트가 영향을 받는다.
