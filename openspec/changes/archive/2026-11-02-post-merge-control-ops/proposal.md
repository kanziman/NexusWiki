## Why

#173의 squash 병합으로 공개 증거가 가리키는 브랜치 커밋과 main 이력이 달라졌고, 클라우드 적용 기록도 복구 결과를 반영하지 못했다. main 머지가 Railway 운영 배포를 시작하므로, DB 적용이 늦어 같은 장애가 재발하지 않도록 머지 전 운영 게이트가 필요하다.

## What Changes

- #171의 공개 증거 `after.commit`을 main 병합 커밋 `184c5b4`로 교체한다. 이번 세션의 재측정에서 4개 항목의 `after.values`가 기존 값과 같음을 확인했다.
- 마이그레이션 기록에 사용자가 전달한 클라우드 `0026` 적용, 대기 0건, API health의 병합 해시 일치, 위조 토큰 401 결과를 출처와 함께 기록한다. 적용 전 최신 번호의 잘못된 가정 `0022`를 실제 보고된 `0021`로 정정하고, 실제 push 대상에 `0022`가 포함됐는지는 명령 기록 없이 단정하지 않는다.
- 이전 운영 코드와 호환되는 마이그레이션은 main 머지 전에 DB에 적용하고 원장·대기 목록을 확인하도록 PR 계약과 운영 체크리스트에 명시한다. 미적용 또는 확인 불가 상태에서는 머지하지 않는다.
- 이전 코드와 호환되지 않는 변경은 호환 단계로 분리하거나 자동 배포를 통제하는 별도 승인 계획을 마련하도록 한다. 모든 DDL을 무조건 먼저 적용하는 규칙으로 만들지 않는다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `pull-request-workflow`: 자동 운영 배포를 유발하는 main 머지 전에 마이그레이션 호환성, 선적용, 적용 결과 확인을 요구한다.

## Impact

- 변경 대상: 공개 합성 증거 JSON, 마이그레이션 적용 기록, Railway 운영 체크리스트, PR workflow 스펙과 해당 delta.
- 애플리케이션 코드, DB 스키마, 의존성은 변경하지 않는다.
- 실제 로그인·원문 등록·Ask·Control Room·워커 상태는 미검증으로 명시한다. 운영 데이터 쓰기, 비밀 키 변경, 실패 원문 재시도는 이 후속 PR의 범위에 포함하지 않는다.
