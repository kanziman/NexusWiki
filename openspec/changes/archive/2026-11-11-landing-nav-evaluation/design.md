## Context

상단 메뉴는 `PublicLandingHeader.tsx`의 `sectionLinks` 배열을 데스크톱 `nav`와 모바일 `nav`가 함께 그린다. 지금 항목은 전부 같은 페이지 안의 `#앵커`라서 `<a>`로 충분하다.

## Decisions

- **D1. 평가 기록은 `sectionLinks`에 섞지 않고 별도 `Link`로 둔다.** 앵커는 `<a>`, 페이지 이동은 `next/link`라 요소가 다르다. 배열에 `kind` 필드를 넣는 것보다 두 메뉴에 한 줄씩 추가하는 편이 읽기 쉽다. 스타일은 기존 섹션 링크와 같은 클래스를 써서 시각적으로 구분되지 않게 한다.
- **D2. `prefetch={false}`.** 평가 소개 섹션 링크와 같은 이유다. 공개 랜딩 방문만으로 평가 페이지 번들과 데이터를 가져오지 않는다.
- **D3. 위치는 `FAQ` 오른쪽.** 섹션 앵커 순서를 깨지 않고, 페이지를 떠나는 링크가 마지막에 온다.

## Risks / Trade-offs

- 데스크톱 메뉴가 4개에서 5개로 늘어난다. 기존 `gap-7`로는 `md`(768px) 경계에서 메뉴 글자가 두 줄로 꺾였다. 그래서 간격을 `gap-4 lg:gap-7`로 바꾸고 섹션 링크와 평가 기록 링크에 `whitespace-nowrap`을 붙였다. 768px·1024px 폭 iframe에서 줄바꿈과 겹침이 없고 문서 가로 스크롤 폭이 뷰포트 안에 있음을 측정했다.
