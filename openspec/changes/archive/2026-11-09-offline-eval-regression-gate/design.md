## Context

동기는 proposal.md를 따른다. `scripts/ask_replay.py`의 `verdict`는 행만 읽는 순수 채점 함수이며 이미 CLI와 성적표가 공유한다. 재생 원본은 Git 밖에 있고 실제 운영 자료가 아닌 물류 합성 fixture로 생성됐다.

## Goals / Non-Goals

**Goals:** 기존 실제 합성 회차에서 고정한 문항별 통과·실패를 PR에서 저비용으로 검증한다.

**Non-Goals:** 새 답변 생성, 모델·프롬프트 품질 평가, 자동 기준선 갱신, 운영 데이터 공개.

## Decisions

- 독립 CLI `scripts/check_eval_regression.py`가 현재 `ask_replay.verdict`를 불러온다. 채점 로직을 복제하면 실제 규칙 변경을 놓치므로 복제하지 않는다.
- JSON fixture에 원본 sha256·출처·계획 문항과 채점 필드·기대 verdict를 저장한다. 원본 전체 커밋은 자격증명·근거·워크스페이스 필드 때문에 기각한다. 소수 인공 사례만 쓰는 대안은 실제 회차를 검증하지 못하므로 기존 단위 테스트에 맡긴다.
- `id`, `doc`, `status`, `answer`, `keyword_hit`, 인용 개수·위조 개수·옛 이중 인용 비율 등 채점에 필요한 필드만 허용한다. 답변은 합성임을 명시하고 문항별 정답과 거절 기대값을 고정한다.
- CI의 기존 Python 설치 경로에 명시적 단계로 붙인다. 모델 호출 권한과 GitHub secret을 요구하지 않는다.
- 기대값은 현재 판정을 무조건 덮어쓰는 갱신 명령으로 만들지 않는다. 변경 이유와 문항 차이를 코드 리뷰 대상으로 남긴다.

## Risks / Trade-offs

- 같은 저장된 출력만 검사하므로 생성 모델의 품질 변화를 잡지 못한다. 평가 지도에 한계를 표시한다.
- 채점기가 잘못 완화되거나 강화돼도 모두 차이로 실패한다. 의도한 변경만 fixture와 근거를 함께 갱신한다.
- 공개 fixture는 허용 필드를 검사하고 원본 해시로 추적한다. 실제 운영 자료는 입력으로 채택하지 않는다.

## Migration Plan

DB·운영 배포 변경 없음. CLI와 fixture를 추가하고 PR CI에 연결한다. 사용자가 권장안에 따른 계획·구현 게이트 진행을 승인했다.
