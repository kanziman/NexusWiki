## Why

로그인한 사용자가 접근 가능한 워크스페이스가 있어도 루트 경로에서 이를 발견하거나 선택할 수 없어, 다중 프로젝트 사용 흐름과 첫 진입이 막혀 있다. 워크스페이스가 제품의 테넌트 경계이므로, 접근 가능한 범위 안에서만 일관된 진입 경로를 제공해야 한다.

## What Changes

- 요청자의 RLS 범위에서 접근 가능한 워크스페이스를 기준으로 로그인 후 진입 경로를 결정한다.
- 워크스페이스가 하나면 해당 워크스페이스 홈으로 바로 이동하고, 둘 이상이면 명시적인 선택 화면을 제공한다.
- 선택 화면과 기존 헤더 전환기는 접근 가능한 워크스페이스만 표시하고, 선택 후 모든 화면을 URL의 워크스페이스 범위에 유지한다.
- 접근 가능한 워크스페이스가 없을 때는 기존 초대 안내를 유지한다.
- 변조되었거나 접근할 수 없는 워크스페이스 URL은 존재 여부나 데이터를 노출하지 않는다.

## Capabilities

### New Capabilities

- `workspace-entry-flow`: 인증된 사용자의 단일·다중·무소속 워크스페이스 진입과 선택 계약

### Modified Capabilities

- 없음.

## Impact

- 영향 영역: dashboard 루트 라우트, 로그인 후 리디렉션, 워크스페이스 선택 UI와 헤더 전환기, RLS 범위의 workspace 조회
- API·DB 스키마: 새 공개 API나 데이터 모델은 추가하지 않으며, 기존 요청자 JWT 기반 Supabase 조회를 사용한다.
- 보안: 사용자 요청 경로에서 `service_role`을 사용하지 않고, 현재의 workspace URL 접근 제어를 유지한다.
