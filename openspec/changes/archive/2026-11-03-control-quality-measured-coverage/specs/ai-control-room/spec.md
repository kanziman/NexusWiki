## MODIFIED Requirements

### Requirement: Control Room 품질 탭
시스템은 Control Room 품질 탭에서 Ask 인용 위반, 수리, Fallback 집계와 구조화 출력의 시도 위반, 펜스 제거, 소진, 페이지 근거 집계를 SHALL 제공한다. 요청은 요청자 JWT로 수행하며 본문과 사용자 식별자를 MUST NOT 반환한다. `editor` 이상은 워크스페이스 전체를, `viewer`는 본인 Ask 집계만 본다. 시스템은 답변 턴과 구조화 호출의 측정 건수를 전체 건수와 함께 SHALL 제공한다. 측정 건수는 품질 판정을 실제로 수행했고 그 기록의 형식이 유효한 데이터의 건수이며, 위반, 수리, Fallback, 펜스 제거, 오류, 소진 지표는 측정된 데이터만 MUST 집계한다. 측정되지 않은 데이터를 위반 없음으로 MUST NOT 표시한다. 각 지표 묶음은 집계 기준을 화면 텍스트로 SHALL 표시한다.

#### Scenario: editor가 품질 탭을 연다
- **WHEN** `editor` 또는 `owner`가 품질 탭을 연다
- **THEN** Ask와 수집 경로의 품질 집계가 표시되고 답변 본문이나 사용자 식별자는 없다

#### Scenario: viewer가 품질 탭을 연다
- **WHEN** `viewer`가 품질 탭을 연다
- **THEN** 본인 Ask 집계와 그 측정 건수만 표시되고 수집 경로 집계는 반환되지 않는다

#### Scenario: 비멤버의 요청
- **WHEN** 비멤버가 품질 API를 호출한다
- **THEN** HTTP 403으로 거부되고 수치가 반환되지 않는다

#### Scenario: 집계할 데이터가 없다
- **WHEN** 기간 안에 턴과 호출이 없다
- **THEN** 0을 정상 수치처럼 꾸미지 않고 빈 상태를 표시한다

#### Scenario: 측정 전 데이터가 일부 섞여 있다
- **WHEN** 기간 안의 답변 턴 6건 중 4건에만 품질 판정 기록이 있다
- **THEN** 화면은 측정 4건과 전체 6건을 함께 표시하고, 위반과 수리 지표는 그 4건만 집계한다

#### Scenario: 측정된 데이터가 하나도 없다
- **WHEN** 기간 안에 답변 턴 또는 구조화 호출이 있지만 해당 경로의 측정 건수가 0이다
- **THEN** 그 경로의 위반, 수리, 오류 지표를 0건으로 표시하지 않고 측정 기록 없음을 표시한다

#### Scenario: 품질 기록의 형식이 잘못됐다
- **WHEN** 답변 턴의 품질 기록이 없거나, 객체가 아니거나, 위반 목록과 수리 여부의 형식이 유효하지 않다
- **THEN** 그 턴은 전체 건수에만 포함되고 측정 건수에서 제외되며, 다른 멤버의 집계 조회는 실패하지 않는다

#### Scenario: 인용 계약 검사가 꺼진 턴
- **WHEN** 답변 턴이 품질 모드 `off`에서 생성되어 계약 검사를 수행하지 않았다
- **THEN** 그 턴은 전체 건수에만 포함되고 측정 건수와 위반 지표에서 제외된다

#### Scenario: 측정 건수를 모르는 응답
- **WHEN** 화면이 측정 건수 필드가 없는 이전 API 응답을 받는다
- **THEN** 측정 건수를 0건으로 다루어 위반 지표 대신 측정 기록 없음을 표시한다

#### Scenario: 멤버가 지표의 기준을 확인한다
- **WHEN** 데이터가 있는 품질 탭이 표시된다
- **THEN** 답변 턴과 구조화 호출 묶음에는 최근 N일 기준이, 근거 연결 묶음에는 기간과 무관한 전체 페이지 기준이 화면 텍스트로 표시된다

### Requirement: Control Room 리스크 탭
시스템은 Control Room 리스크 탭에서 적용 중인 정책 버전, 쓰기 모드, 위험 등급별 개정 건수, 승인 후 반영 중인 건수, 승인 대기 목록을 SHALL 제공한다. `editor` 이상은 대기 제안의 이전·제안 본문을 보고 승인하거나 거부할 수 있다. `viewer`는 집계만 보며 제안 본문을 MUST NOT 받는다. 비멤버는 HTTP 403이다. 최근 N일 기준 지표와 현재 상태 지표는 기준을 화면 텍스트로 구분해 SHALL 표시한다.

#### Scenario: editor가 대기 제안을 처리한다
- **WHEN** `editor`가 리스크 탭에서 대기 제안을 승인한다
- **THEN** 제안이 목록에서 사라지고 집계가 갱신된다

#### Scenario: viewer가 리스크 탭을 연다
- **WHEN** `viewer`가 리스크 탭을 연다
- **THEN** 집계만 표시되고 승인 버튼과 본문이 없다

#### Scenario: 비멤버의 요청
- **WHEN** 비멤버가 리스크 API를 호출한다
- **THEN** HTTP 403으로 거부된다

#### Scenario: 멤버가 지표의 기준을 확인한다
- **WHEN** 멤버가 리스크 탭을 연다
- **THEN** 위험 등급별 개정, 승인 반영, 거부는 최근 N일 기준으로, 승인 대기와 승인 후 반영 중은 현재 상태 기준으로 화면 텍스트에 구분되어 표시된다
