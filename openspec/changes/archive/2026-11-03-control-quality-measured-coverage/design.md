## Context

품질 집계 RPC `control_quality_snapshot`은 `control_report.quality`가 없는 턴을 위반 없음으로 센다. 답변 턴은 `quality`의 모드와 형식으로 측정 여부를 판별할 수 있지만(D2), 구조화 호출에는 명시적인 측정 표식이 없다.

구조화 호출의 사용량 메타데이터는 위반이 있을 때만 `violation` 등을 남긴다. 따라서 정상 호출과 측정 전 호출은 이 키들로 구별되지 않는다. `policy_version`은 `llm_gateway.py`의 시도 기록에서 항상 함께 기록되며, 출력 계약 검증보다 나중에 도입됐다.

운영의 구조화 호출은 2건이다. 2026-11-02 호출에는 `policy_version`이 없고, 2026-11-03 호출에는 있다. 그 사이 기간에는 컴파일이 없었다.

## Goals / Non-Goals

**Goals:**

- 측정되지 않은 데이터가 위반 0건으로 보이지 않게 한다.
- 지표마다 집계 기준을 화면 텍스트로 알 수 있게 한다.
- 운영 참조 문서를 실제 상태와 맞춘다.

**Non-Goals:**

- 추적 탭과 예산 탭의 기간 표시 변경
- 저장된 사용량과 Ask 턴 데이터의 수정이나 재측정
- `AI_CONTROL_RISK_MODE`의 `enforce` 전환과 전환 시점 판단
- 잘린 위키 본문의 원인 조사와 복구, 중복 페이지 정리
- 나머지 3개 워크스페이스의 근거 백필
- 카드 줄바꿈 등 측정 구분과 무관한 외관 개선

## Decisions

### D1. 구조화 호출의 측정 표식은 `policy_version`의 존재로 판별한다

| 기준 | A. `policy_version` 존재 (선택) | B. 새 `contract_checked` 표식 | C. 머지 시각 기준 |
| --- | --- | --- | --- |
| 데이터 구조 | 변경 없음 | 사용량 메타데이터에 키 추가 | RPC에 시각 상수 추가 |
| API 영향 | 응답 필드 추가 | 응답 필드 추가 | 응답 필드 추가 |
| 상태 관리 | 기존 기록 재사용 | 새 표식 기록 필요 | 환경별 시각 관리 필요 |
| 핵심 동작 | 운영 호출 2건을 정확히 구분 | 2026-11-03 호출이 미측정이 됨 | 배포 시각과 어긋날 수 있음 |
| 구성 요소 | RPC, API, 화면 | worker, RPC, API, 화면 | RPC, API, 화면 |
| 기존 패턴 일치 | 메타데이터 키로 집계하는 방식과 같음 | 같음 | 없음 |
| 테스트 용이성 | 메타데이터 시드로 검증 | 메타데이터 시드와 worker 검증 | 시간 경계 시드 필요 |

A를 선택한다. worker 변경이 없고 운영 데이터를 바로 정확히 구분한다. 출력 계약 도입 후 정책 버전 도입 전 호출은 미측정으로 분류되지만, 운영에는 그런 호출이 없고 측정을 부풀리지 않는 방향이다.

⚠️ 이후 `policy_version`을 시도 기록에서 빼면 호출이 모두 미측정으로 보인다. RPC와 게이트웨이 양쪽에 이 의존을 주석으로 남긴다.

### D2. 답변 턴은 품질 판정을 수행한 유효한 기록만 측정으로 본다

`quality`가 객체이고, `mode`가 `shadow` 또는 `enforce`이며, `violations`가 배열이고, `repair_attempted`와 `repaired`가 불리언일 때만 측정으로 본다. `off`는 계약 검사를 건너뛰면서도 빈 위반 목록을 저장하므로 객체 여부만으로는 판별할 수 없다.

`control_report`는 작성자가 쓸 수 있는 값이다. 형식이 잘못된 턴은 측정에서 제외하되 집계 조회는 실패시키지 않는다. 위반, 수리, Fallback도 측정된 턴에서만 센다.

### D3. 새 마이그레이션 `0036`에서 RPC를 다시 만든다

반환 컬럼을 추가하려면 함수를 삭제하고 다시 만들어야 한다. 단일 트랜잭션에서 수행하고 실행 권한도 다시 설정한다. API 응답에는 `ask.measured_turns`와 `structured.measured_calls`를 추가하고 기존 필드는 유지한다.

### D4. 측정 건수 0은 화면에서 지표 대신 안내로 표시한다

해당 경로의 측정 건수가 0이면 위반, 수리, 오류 카드를 숨기고 측정 기록 없음을 표시한다. 측정 건수 표시는 전체 건수를 함께 보여 준다. 데이터가 전혀 없을 때의 기존 빈 상태는 유지한다. 대시보드와 API는 따로 배포되므로, 응답에 측정 건수가 없으면 0건으로 다룬다.

### D5. 기간 기준은 묶음별 캡션으로 표시한다

기존 스크린 리더 라벨은 유지하고, 묶음마다 보이는 캡션을 추가한다. 리스크 탭은 현재 상태 지표와 최근 N일 지표를 별도 묶음으로 나눈다. 카드마다 기간을 반복하지 않아 화면이 복잡해지지 않는다.

## Risks / Trade-offs

- **배포 순서** → `0036` 적용 전에 새 API가 뜨면 측정 건수가 0이 되어 측정 기록 없음으로 잘못 표시된다. 기존 API는 추가 컬럼을 무시하므로, 운영 순서는 `0036`, API, 대시보드로 한다.
- **위조 가능한 품질 기록** → 작성자가 올바른 형식의 값을 직접 넣으면 측정으로 세어지고, 측정 0건 워크스페이스의 안내가 지표 카드로 바뀔 수 있다. 형식 검사로는 막을 수 없는 수용한 위험이며, 위반 집계를 작성자 값에 의존하는 기존 구조에서 비롯된다. 다른 멤버의 조회 실패와 형식 오류의 오집계는 막는다.
- **호출 수의 의미** → 구조화 호출은 기존처럼 시도 단위로 센다. 측정 건수도 같은 단위를 쓴다.
