## Why

Ask 평가 결과(평가 지도 · 반복 측정 · 거절 성능 · 적용 원장)가 `docs/ops/` 마크다운 표와 저장소 밖 성적표 HTML에 흩어져 있어, 포트폴리오 방문자가 무엇을 쟀고 무엇을 아직 안 쟀는지 한 화면에서 확인할 수 없다. #247에서 반복 측정이 끝나 공개할 수 있는 기록이 갖춰졌으므로, 숫자가 분모 · 회차 · 실행 경로 · 한계와 떨어지지 않는 공개 화면으로 묶는다.

## What Changes

- 로그인 없이 여는 공개 쇼케이스 `/showcase/evaluation`을 추가한다. 한 페이지에 다섯 구역을 둔다.
  - **평가 지도**: 측정면별 상태(잰 것 · 일부만 · 비어 있음)와 숫자 · 분모 · 측정일 · 출처. 비어 있는 측정면도 이유와 함께 보인다.
  - **반복 측정 격자**: 문항 × 회차의 통과 · 실패 · 미실행, 문항 안정성, 회차별 실행 경로(HTTP · 하네스), 알려진 실패의 보고 단계와 자동 단계.
  - **거절 성능**: 답할 수 있는 문항 통과 · 정확한 거절 · 잘못된 거절을 회차별로 분모와 함께.
  - **적용 원장**: 날짜순으로 적용한 평가 기법과 측정이 바꾼 것.
  - **재현 조건과 한계**: 고정 입력 지문 · 모델 · 정책 · 비용과 합성 샘플 · 회차 수 · 거절 표본 한계.
- 화면은 저장소에 커밋한 버전 있는 공개 평가 기록(허용 필드 JSON)만 빌드 시점에 읽는다. 운영 DB · API · 모델을 호출하지 않는다.
- 공개 기록을 그대로 내려받는 JSON 링크를 둔다.
- 기존 `controlled-ai` · `evidence-research` 쇼케이스와 이 페이지를 서로 연결한다.
- 새 측정이나 유료 호출은 없다. 이미 보존한 기록만 옮긴다.

## Capabilities

### New Capabilities

- `evaluation-showcase`: 합성 Ask 평가의 측정면별 상태 · 반복 측정 · 거절 성능 · 적용 원장 · 재현 조건을 공개 화면으로 보여 주고, 허용 필드 정적 기록만 읽는 공개 경계를 지킨다.

### Modified Capabilities

(없음. 기존 쇼케이스 페이지에 링크를 더하는 것은 새 capability의 요구사항으로 다루며 기존 요구사항을 바꾸지 않는다.)

## Impact

- `apps/dashboard`: 새 정적 라우트 `/showcase/evaluation`, 공개 JSON 다운로드 라우트, 화면 컴포넌트와 테스트, 버전 있는 공개 평가 기록 파일. 기존 두 쇼케이스 컴포넌트에 링크 추가.
- `scripts/` 또는 수동 큐레이션: 보존된 반복 측정 · 검색 기록에서 허용 필드만 골라 공개 기록을 만드는 경로(방식은 design에서 결정).
- `docs/ops/evaluation-map.md`: 공개 화면과 숫자가 어긋나지 않도록 하는 관계(design에서 결정).
- API · 워커 · DB · RLS · 마이그레이션 변경 없음. `/showcase/*`는 인증 미들웨어 matcher 밖이라 미들웨어도 바뀌지 않는다.
