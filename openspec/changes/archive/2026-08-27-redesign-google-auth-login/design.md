## Context

현재 로그인 화면은 `LoginForm`이 제공하는 Google OAuth 동작을 단순한 중앙 정렬
레이아웃에 배치한다. 인증 시작과 오류 상태는 이미 클라이언트 컴포넌트에 있고,
콜백의 코드 교환은 별도 경로가 소유한다. 제품 동기는
[`proposal.md`](proposal.md)를, 표시 계약은
[`specs/google-authentication/spec.md`](specs/google-authentication/spec.md)를 따른다.

## Goals / Non-Goals

**Goals:**

- v3 템플릿의 지식 비주얼과 인증 패널의 위계를 `/login`에 재현한다.
- 기존 Google OAuth 호출, 내부 콜백 목적지, 오류 문구를 유지한 채 요청 중 상태를
  명확히 보인다.
- 좁은 화면에서는 인증 영역을 먼저 보이는 한 열 레이아웃으로 전환한다.
- 로그인 전용 이미지와 스타일의 영향 범위를 `/login`으로 한정한다.

**Non-Goals:**

- 인증 제공자, Supabase 콜백, 세션 처리, 미들웨어를 변경하지 않는다.
- `/signup`의 레이아웃 또는 Google OAuth 동작을 변경하지 않는다.
- 아직 제공하지 않는 약관·개인정보 처리방침 목적지로 연결을 추가하지 않는다.

## Decisions

### 로그인 전용 프레젠테이션을 페이지·보조 구성요소·범위 스타일로 분리한다

`/login` 서버 페이지는 URL 오류를 읽고, 지식 비주얼과 인증 패널을 조립한다.
애니메이션이 필요한 미리보기는 작은 클라이언트 보조 구성요소가 소유하고,
`LoginForm`은 로그인 전용 표현 변형을 받아 OAuth 상태 전이만 담당한다. 모든
스타일은 `.login-page` 접두사 아래에 둔다.

이 구조는 가입 페이지가 재사용하는 기본 `LoginForm`의 표시와 인증 계약을
보존한다. 별도 OAuth 폼을 만들면 성공·실패·리디렉션 구현이 갈라질 수 있고,
전역 비접두사 스타일은 다른 인증 화면을 오염시킬 수 있어 채택하지 않는다.

### 문서 에셋을 dashboard 정적 경로로 제공한다

승인된 `nexuswiki-login-knowledge-landscape-bright.png`를
`apps/dashboard/public/`에 복사하고 Next.js의 정적 URL로 참조한다. 문서 디렉터리를
런타임 의존성으로 삼지 않아 배포 산출물에 이미지가 빠지는 일을 막는다.

CSS로 유사한 배경을 새로 만들거나 외부 이미지를 참조하는 대안은 승인된 시각
방향을 잃거나 네트워크 실패 지점을 추가하므로 채택하지 않는다.

### 보조 미리보기의 움직임은 비차단·감소 모션 대응으로 둔다

지식 미리보기는 첫 시나리오를 즉시 렌더링하고, 모션 허용 환경에서만 후속
시나리오를 순환한다. `prefers-reduced-motion`에서는 정적 내용을 유지한다. 이는
로그인 CTA를 방해하지 않으면서 템플릿의 제품 맥락을 전달한다.

## Risks / Trade-offs

- [정적 이미지 파일 증가] → 승인된 단일 이미지만 dashboard 공개 경로에 두고
  `next/image`의 크기·우선순위 힌트를 사용한다.
- [좌측 비주얼의 움직임이 로그인 집중을 방해] → 기본 콘텐츠를 즉시 노출하고,
  미리보기는 보조 영역으로 한정하며 감소 모션 환경에서는 정적으로 보인다.
- [화면 폭에 따른 두 패널의 압축] → 900px에서 한 열로 전환하고 640px 이하에서
  인증 패널의 여백과 제목 크기를 별도로 조정한다.

## Migration Plan

1. 정적 에셋과 로그인 전용 프레젠테이션을 배포한다.
2. 기존 OAuth 단위 테스트와 로그인 페이지 렌더링 테스트로 리디렉션·오류 계약을
   확인한다.
3. 문제 발생 시 로그인 페이지의 프레젠테이션과 추가 에셋만 되돌린다. OAuth
   콜백과 데이터는 변경하지 않으므로 데이터 마이그레이션은 필요 없다.
