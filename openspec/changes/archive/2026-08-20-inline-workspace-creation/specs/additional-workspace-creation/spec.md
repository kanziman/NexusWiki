## MODIFIED Requirements

### Requirement: 상한 이내 추가 워크스페이스 생성

시스템은 인증 사용자가 상한(3개) 미만의 소속 워크스페이스를 가질 때 이름 하나로 개인 워크스페이스를 생성해야 한다(MUST). 생성 판정은 RLS로 좁혀진 소속 개수를 요청 시점에 서버에서 다시 세어 이루어져야 하며(MUST), 클라이언트 표시 상태만으로 최종 판정해서는 안 된다(MUST NOT). 이 판정과 생성 로직은 전용 라우트와 워크스페이스 스위처의 인라인 폼 양쪽에서 동일해야 한다(MUST) — 두 진입점이 서로 다른 결과를 내면 안 된다.

#### Scenario: 상한 미만에서 생성 성공
- **WHEN** 소속이 3개 미만인 사용자가 1~100자 이름을 제출하면
- **THEN** 시스템은 owner 멤버십을 가진 personal 워크스페이스를 만들고 해당 워크스페이스로 이동한다

#### Scenario: 상한 도달 시 생성 거부
- **WHEN** 소속이 이미 3개인 사용자가 전용 라우트에서 이름을 제출하면
- **THEN** 시스템은 워크스페이스를 생성하지 않고 상한 안내를 반환한다

#### Scenario: 인라인 폼에서 상한 미만 생성 성공
- **WHEN** 소속이 3개 미만인 사용자가 워크스페이스 스위처의 인라인 폼에 1~100자 이름을 제출하면
- **THEN** 시스템은 owner 멤버십을 가진 personal 워크스페이스를 만들고 해당 워크스페이스로 이동한다

#### Scenario: 인라인 폼 제출 시점에 상한에 도달해 있으면 서버가 거부한다
- **WHEN** 인라인 폼을 연 뒤(진입점이 아직 보이던 시점) 다른 탭에서 소속이 3개가 된 사용자가 그 폼으로 이름을 제출하면
- **THEN** 시스템은 워크스페이스를 생성하지 않고 상한 안내를 인라인으로 보여준다

### Requirement: 상한 도달 시 죽은 링크를 만들지 않는다

워크스페이스 스위처의 생성 진입점은 상한에 도달한 사용자에게 눌러야만 실패를 알게 되는 진입점을 보여주어서는 안 된다(MUST NOT).

#### Scenario: 상한 도달 시 진입점 숨김
- **WHEN** 소속이 이미 3개인 사용자가 워크스페이스 스위처를 열면
- **THEN** 시스템은 "새 워크스페이스 생성" 진입점을 렌더링하지 않는다

#### Scenario: 상한 미만에서 진입점 노출
- **WHEN** 소속이 3개 미만인 사용자가 워크스페이스 스위처를 열면
- **THEN** 시스템은 클릭 시 같은 자리에서 인라인 입력 폼으로 바뀌는 "새 워크스페이스 생성" 진입점을 렌더링한다

## ADDED Requirements

### Requirement: 워크스페이스 스위처의 인라인 생성 폼

시스템은 워크스페이스 스위처에서 "새 워크스페이스 생성"을 활성화하면 별도 페이지로 이동하지 않고 드롭다운을 유지한 채 그 자리를 이름 입력 폼으로 전환해야 한다(MUST). 이 폼은 `/w/new` 전용 라우트와 별개의 두 번째 진입점이며, 전용 라우트를 대체하지 않는다.

#### Scenario: 인라인 폼 진입
- **WHEN** 소속이 3개 미만인 사용자가 워크스페이스 스위처에서 "새 워크스페이스 생성"을 활성화하면
- **THEN** 시스템은 드롭다운을 닫지 않고 그 자리를 이름 입력 필드와 제출·취소 동작으로 바꾼다

#### Scenario: 인라인 폼 취소
- **WHEN** 사용자가 인라인 폼이 열린 상태에서 취소하면
- **THEN** 시스템은 입력값을 버리고 "새 워크스페이스 생성" 진입점으로 되돌린다. 워크스페이스는 생성되지 않는다

#### Scenario: 인라인 폼 제출 중 검증 오류
- **WHEN** 사용자가 인라인 폼에 빈 문자열이나 100자를 초과하는 이름을 제출하면
- **THEN** 시스템은 워크스페이스를 생성하지 않고 폼 안에 오류를 표시하며, 입력값과 폼은 유지된다
