## Why

첫 하이브리드 검색이 비교 대상이나 문서의 다른 표현을 놓치면, 후보 재정렬만으로는 빠진 근거를 복구할 수 없다. 첫 결과를 본 모델이 부족한 근거를 겨냥해 재검색하는 작은 실험을 만들고, 품질 개선과 추가 비용·지연을 동일 조건에서 측정한다.

추적: https://github.com/kanziman/NexusWiki/issues/227

## What Changes

- 기존 검색 후 모델이 충분성을 판단하고 실제 `search_evidence(query)` 도구 호출을 선택한다. 첫 검색 내용을 보지 않는 고정 쿼리 확장은 범위에 포함하지 않는다.
- 추가 검색은 1라운드·최대 2회이며, 서버가 요청자의 JWT와 workspace_id를 고정한다. 모델에는 검색어만 허용한다.
- 기존·추가 근거를 중복 제거해 병합하고, 서버 인용 별칭과 기존 컨텍스트 토큰 예산을 적용한다. 도구 실행은 답변 스트리밍 전에 끝낸다.
- 기능 OFF/ON 비교가 가능해야 한다. 도구 실패·시간 제한·잘못된 호출 시의 종료 정책은 다음 설계 게이트에서 확정한다.
- 같은 수집 결과·모델·검색 정책으로 적용 전후 eval을 수행한다. RRF 변경을 함께 섞지 않는다.
- 기존 30문항 회귀와 비교형·표현 불일치 전용 문항을 평가한다. 첫 검색 실패 중 복구 비율, 비교 대상 전체 근거 확보, 최종 답변 정확성·이중 인용·거절, 입력/출력 토큰·실비용·지연 p50/p95를 기록한다. 판단 호출 비용도 포함한다.
- eval 문항과 판정 기준은 ON 결과를 보기 전에 고정한다. 동일 문서를 재수집하지 않으며, 반복 횟수와 채택 기준은 설계 게이트에서 정한다.
- 적용 전후 eval 결과를 포트폴리오용 전용 페이지에서 확인할 수 있게 한다. 동일 문서·모델·RRF 정책을 확인할 실행 메타데이터, OFF/ON 품질·비용·지연 비교, 문항별 결과와 합성 평가의 한계를 제공한다. 공개 데이터는 합성 fixture와 공개 가능한 실행 기록으로 제한한다.
- 주변 청크 읽기·위키 전체 읽기·위키 이웃 탐색은 이번 범위에서 제외한다.

## Capabilities

### New Capabilities

- `ask-evidence-research`: 첫 검색 근거를 바탕으로 제한된 도구 재검색을 수행하는 Ask 흐름과 관측 계약.
- `retrieval-evaluation-showcase`: 재현 조건과 적용 전후 결과를 공개하는 포트폴리오 평가 페이지.

### Modified Capabilities

- `ask-replay-scorecard`: 재검색 OFF/ON의 복구 효과·회귀·전체 호출 비용·지연을 동일 조건에서 비교하는 평가 계약.

## Impact

- API Ask 서비스와 요청자 권한의 검색 서비스, 워커 내부 LLM 호출 및 비용 회계 경계.
- 기존 인용·컨텍스트 예산·SSE 순서·테넌트 격리 계약을 유지해야 한다.
- 재생 스크립트·고정 fixture·평가 기록. RRF 작업과 분리된 main 기준 worktree에서 진행한다.
- 현재 상태는 요구사항 승인 대기이며, 구현이나 평가 결과는 아직 없다.
