Umbrella: https://github.com/kanziman/NexusWiki/issues/210

2026-11-03 요구사항·아키텍처 A·최종 설계·Gate 4 승인 완료. 사용자가 로컬 구현 apply를 명시적으로 요청했다. 운영 마이그레이션·실제 백필·push/PR·머지는 별도 경계로 유지한다.

## 1. 운영자가 청크 후보를 안전하게 대조한다

의존성: 없음. 예상: 0.5~1일. 하위 이슈: https://github.com/kanziman/NexusWiki/issues/211

- [x] 1.1 0035의 service-role 전용 후보·토큰 조회 경계와 워커 CLI `export`를 연결해, 전체 페이지를 순회하고 결정적으로 정렬한 후보 JSON·정적 HTML·빈 승인 파일을 생성한다. workspace/출처·원문 좌표 검증, 파일 경로·덮어쓰기 보호·본문 로그 비노출과 실제 로컬 DB 검증을 포함한다.

**인수 조건**

- Given 기존 출처가 있는 검증 완료 페이지, When `export`를 실행하면, Then 같은 workspace·기존 출처의 모든 유효 청크와 0점 후보를 보고서에서 비교할 수 있고 승인 목록은 비어 있다.
- Given 후보 없는 페이지 또는 비어 있는 workspace, When 내보내면, Then 누락하지 않고 후보 없음·0건 결과를 표시한다.
- Given 조회 제한보다 많은 페이지, When 커서 순회하면, Then 전수를 수집하거나 명시적 오류로 끝내며 잘린 결과를 성공으로 보고하지 않는다.
- Given 악성 HTML이 섞인 저장 본문, When 보고서를 열면, Then 텍스트로만 보이고 스크립트 실행·외부 요청은 없다.
- Given 운영자가 읽기 전용 보고서를 생성함, When 전후 DB를 비교하면, Then 페이지·근거·원문·청크·색인·개정·제안·잡·사용량이 모두 동일하며 모델 호출은 없다.
- Given 일반 사용자 또는 익명 역할, When 후보 RPC를 실행하면, Then 거부되고 운영 본문을 받지 못한다.

**검증**: 보고서 순수 테스트, 50페이지를 넘는 로컬 합성 fixture의 전수 순회, RPC 권한과 교차 테넌트·출처 필터·좌표 검사, export 전후 행/필드 스냅샷 비교. 원격 본문은 테스트 fixture나 저장소 산출물에 넣지 않는다.

## 2. 운영자가 검토한 연결만 원자적으로 추가한다

의존성: 1. 예상: 1일. 하위 이슈: https://github.com/kanziman/NexusWiki/issues/212

- [x] 2.1 동일 도구의 `validate`·`apply`와 0035의 추가 전용 적용 RPC를 연결해, 승인된 최대 500쌍을 잠금·현재 토큰 검증 후 원자적으로 추가한다. 누락·변조·출처/tenant 오류·stale·빈 승인·반복 적용과 원문 삭제/페이지·청크 수정 경합의 실DB 검증을 포함한다.

**인수 조건**

- Given 빈 승인 목록, When validate/apply하면, Then 유효한 무작업으로 끝나고 DB 적용 RPC를 호출하지 않는다.
- Given 파일 해시 불일치·후보 밖 쌍·중복·workspace 불일치·500쌍 초과, When validate/apply하면, Then DB 쓰기 전에 거부하며 승인 목록을 자동 보완하거나 배치를 자동 분할하지 않는다.
- Given 검토한 연결, When 명시적 확인 workspace로 적용하면, Then 신규 연결만 추가되고 기존/다른 원문 근거와 페이지·검증·검색 색인은 보존된다.
- Given 같은 검토 파일을 반복 적용, When 원본 토큰이 같으면, Then 신규 0건으로 끝나고 행 수가 늘지 않는다.
- Given 배치의 한 ID가 없거나 페이지·원문·청크 내용/출처가 바뀜, When 적용하면, Then 배치 전체가 실패하고 다른 유효 쌍도 저장되지 않는다.
- Given 페이지 수정·청크 재처리·원문 삭제와 경합, When 적용하면, Then 유효한 검토 상태의 추가 또는 배치 전체 실패만 일어난다.
- Given 일반 사용자·익명 역할 또는 다른 workspace의 ID, When RPC를 호출하면, Then 거부되고 근거는 변하지 않는다.
- Given DB 커밋 후 결과 파일 저장 실패, When CLI가 종료하면, Then 이미 적용된 사실을 알리고 실패를 롤백으로 오보고하지 않는다.

**검증**: 파일 입력 테스트, 로컬 DB의 기존/신규 근거·범위·stale·500/501 경계·전체 롤백, 별도 연결을 사용한 잠금 경합, 신규 삽입 목록과 결과 건수, 영향을 받지 않아야 할 모든 필드·테이블 스냅샷. 공유 큐 테스트는 다른 프로세스와 겹치지 않게 실행한다.

## 3. 운영자가 검토·적용 결과를 확인하고 후속 조치를 판단한다

의존성: 1, 2. 예상: 0.5일. 하위 이슈: https://github.com/kanziman/NexusWiki/issues/213

- [x] 3.1 합성 workspace로 export → 수동 승인 파일 → validate → apply → 재실행 → 품질 집계까지 운영 절차를 로컬에서 재현하고, 본문 불변·미확정 페이지·신규 삽입 목록·실패 후 재검토를 확인할 수 있는 한국어 운영 문서와 커밋 가능한 비민감 검증 기록을 작성한다.

**인수 조건**

- Given 후보가 있지만 근거를 확정할 수 없는 페이지, When 운영자가 승인하지 않으면, Then 미확정으로 남고 연결률을 채우기 위한 추정 연결이 추가되지 않는다.
- Given 일부 페이지만 승인한 합성 workspace, When 전체 절차를 수행하면, Then 품질 집계는 실제 연결된 페이지만 증가하고 검증 완료 본문·기존 출처·색인은 불변이다.
- Given 오래된 승인 파일, When 재검토 절차를 따르면, Then 새 보고서를 만들고 사람 선택을 다시 거쳐야 하며 자동 재컴파일이나 강제 적용은 없다.
- Given 성공 후 잘못 승인한 연결 발견, When 운영 문서를 따르면, Then 실제 신규 삽입 목록을 바탕으로 별도 제거 계획을 검토하며 기존 근거 전체 삭제를 실행하지 않는다.
- Given 운영 적용 전 단계, When 문서를 확인하면, Then 운영자의 0035 선적용·linked 확인·별도 apply 경계와 에이전트의 운영 쓰기 금지가 명확하다.

**검증**: 합성 데이터로 end-to-end 절차 재현, `control_quality_snapshot` 결과와 직접 집계 대조, 결과 파일에서 본문·비밀이 검증 요약으로 새지 않는지 확인. 에이전트는 운영 마이그레이션·실제 백필 apply를 실행하지 않는다.

## 완료 게이트와 범위

각 task는 인수 조건 전체 검증 직후에만 완료 처리한다. 구현 후 관련 테스트·전체 pytest·Ruff·SEC-03·strict validation을 새로 실행한다. frontend 코드는 범위 밖이므로 현재 계획의 관련 검증은 Python·SQL·CLI·문서다. 새 frontend 변경이 생기면 먼저 설계와 범위를 재검토한다.

`spec-conformance-reviewer`와 `tenant-isolation-reviewer`를 병렬 실행하고 최대 3라운드를 지킨다. 양쪽 pass 후 delta 동기화·본 스펙 strict 검증·archive·한국어 커밋까지 진행한다. push·PR은 초안 승인 뒤 수행하며 운영 DB 쓰기와 머지는 운영자가 한다. 하위 이슈는 PR 발행 뒤, umbrella는 머지 뒤에만 닫는다.

운영 30페이지/167후보는 계획의 규모 근거이며 테스트 fixture로 복제하지 않는다. 구현 완료·로컬 시연 완료와 운영 백필 완료는 별개로 보고한다.
